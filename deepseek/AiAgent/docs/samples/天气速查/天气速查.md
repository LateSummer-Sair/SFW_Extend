# 天气速查（示例）

这是个**演示技能**，用来说明「一个技能一个文件夹」怎么写：本文件夹里有

```
天气速查/
  ├─ 天气速查.md      ← 本文件：元数据 + 说明
  ├─ AirunSkill.java  ← 入口类（含 airun 方法）
  └─ WeatherFmt.java  ← 辅助类（同一个文件夹里的 .java 会一起编译）
```

安装：把整个 `天气速查/` 文件夹拷进 `data/skills/` 即可（热加载，不用重启）。

## 这个示例演示了什么

| 能力 | 写法 |
|---|---|
| 声明式入参 | `airun.params` 里的 `type` / `required` / `description` |
| 缺省补齐 | `default: 北京` / `default: 3` —— 模型没填时框架补上 |
| 限定取值 | `enum: [简要, 详细]` —— 写进 JSON Schema |
| 示例提示 | `example: 上海` —— 拼进参数描述，模型填对率更高 |
| 数组参数 | `type: array` + `items: string` + `items_description` |
| 返回说明 | `returns:` —— 进工具描述，告诉模型结果怎么用 |
| 上下文注入 | `context: true` + `airun(Map args, Map ctx)` |
| 实例策略 | 不写 `state` 即默认 `per_call`（每次调用新实例，成员变量不会并发串台） |
| 辅助类 | 同目录 `WeatherFmt.java`，`AirunSkill` 直接 `new WeatherFmt()` 用 |
| 入口指定 | 本技能只有一个类带 `airun`，所以不用写 `entry:` |

## 代码

入口类见 `AirunSkill.java`，辅助类见 `WeatherFmt.java`。

要点：

- 全部 `.java` 一起编译，辅助类可以正常 new；
- `AirunSkill` 必须是 `public` 且有无参构造器；
- 入口方法名固定 `airun`；
- 返回 `Map` 会自动序列化为 JSON 交给模型；
- 上下文是只读投影（拿不到 `napcatApi` 这类可写句柄，见 `docs/skills-migration.md`）。
