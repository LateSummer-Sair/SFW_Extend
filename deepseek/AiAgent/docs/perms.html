01 / 模型

权限模型：谁 × 什么 × 哪一位

一次判定永远由三件事决定：主体（谁在要）、资源（要什么）、位（要读、要写、还是要执行/对外）。

主体三类（外加两种写法）

主体是谁默认位出处
MASTER主人。本地控制台 ≡ QQ 里的主人（控制台调用者就是主人）恒全权，任何条目都影响不到他auth\Caller.java:13-19、:17、auth\Acl.java:883
SYSTEM她自己的自主行为（定时唤醒、维护、她自己发出去的话）A:R / B:RW / C:RWX / E:Xauth\Caller.java:23-25、:18、auth\Acl.java:182-190
ALLUSER除主人与她之外的所有人（是 User<QQ> 与 Group<群号> 的底稿）按类默认分配（见下一节）auth\Caller.java:19、:96-98、auth\Acl.java:55-56
User<QQ号>某一个具体的人（裸 QQ 号是它的便捷写法）命中例外就按例外给位auth\Acl.java:42、:399-410
Group<群号>某一个群里的所有人命中例外就按例外给位auth\Acl.java:42、:264-273

层级与顺序

主体层级：User<QQ>(3) > Group<群号>(2) > ALLUSER(1)；SYSTEM 自成一路（只对 Kind.SYSTEM 生效，层级 3）。同一层级里，后面的条目覆盖前面的。

出处 auth\Auth.java:27、auth\Acl.java:139-141、:264-273、:654。判定顺序是「显式 SYSTEM 标志 > master > 其它」（auth\Caller.java:26-27、:129-130）。

MASTER 不接受例外

账本里写 MASTER 会被拒收（主体只允许 User<QQ号> / Group<群号> / SYSTEM / ALLUSER）；主人恒全权，不需要也不允许给他写例外。

出处 auth\Acl.java:43、:411、:429-434。

她有三条"自主行为"路径会落到 SYSTEM：没有触发者的那些调用（定时唤醒、维护、她自己发出去的话）。出处 auth\Caller.java:26-27、:80-83。

02 / 资源

资源五类，位只有三个

资源按"要动的是什么东西"分类，类别字母就是账本里条目的第一个字符。

类是什么范围怎么写ALLUSER 默认出处
A本机：SFW 数据根之外的任意本机路径，以及本机进程路径（"" = 整个 A 类）无（一位都不给）auth\Res.java:10、:63-67、auth\Acl.java:145-150
BSFW 之内：SFW 运行时目录里的文件（含插件数据根里的那些）路径（"" = 整个 B 类）无auth\Acl.java:154-158、auth\Res.java:10
C数据：库的全部内容（db:<库> 一类）、运行期内存状态（mem:xxx）、数据根的 files 目录库名 / mem:xxx / files 下的路径（"" = 整个 C 类）Rauth\Acl.java:164-166、:44-46
E对外：QQ 平台动作（NapCat 的输入输出）+ 向 SFW 发命令动作名（"" = 整个 E 类）无auth\Acl.java:171-172、auth\Res.java:209
T工具：一把工具的"入口"（工具执行过程本身不判位，判定只发生在入口）工具名（可省 tool: 前缀，"" = 整个 T 类）无auth\Acl.java:179-180、:457-458、tool\Registry.java:191-199

三个位

位只有三个：R 读 / 看；W 写 / 改 / 注册；X 执行或对外（把东西交出去）。三个位可以任意组合写成 RWX 这样的串。

出处 auth\Bits.java（位运算与 format()）、auth\Acl.java:40-47（条目里"位"这一格）。认不出的位串 = 空（fail-closed，auth\Acl.java:392-397、auth\Bits.java:15-16）。

T 类只看 X

工具能不能用只有一条判据：有效位里有没有 X；看不到的工具名不会出现在模型面前（可见性也由同一位决定）。

出处 tool\Registry.java:191-199、:210-217（入口闸门）、:426-446（ai/tools 的行格式与有效位）。

特例：数据根的 files 目录：它是 C 类里的一个"特例文件实体" —— 位一律服从 C 的默认分配（ALLUSER = R、SYSTEM = RWX），但它会按路径式范围命中，所以 C["User<QQ>","<数据根>/files","RWX"] 这种写法能命中它下面的文件。出处 auth\Res.java:118-130、:236-243、auth\Acl.java:87、:292-296。

03 / 账本

账本：perms.json

一本账，一个文件，在数据根下。账本里没有的东西 = 没给；账本里写了空位 = 明确拒绝。

文件与格式

文件名固定 perms.json，内容形如 {"version":3,"entries":[…]}；一条条目的形态是 类["主体","范围","位"]。

出处 auth\Acl.java:121（文件名）、auth\Auth.java:24（唯一一本账 + version:3）、auth\Acl.java:40-47（条目语法）。

它在哪、谁写它

在数据根下：SairFrameWork\data\AiAgent-V4\perms.json（数据根由配置对象拼出）。写入方是插件自己（授权/撤销时落盘）；随仓库的部署脚本明确跳过它 —— 不覆盖线上账本；若源侧是旧版格式只提示、不迁移。

出处 auth\Auth.java:83、Conf.java:1093-1103；部署脚本里的账本段与其跳过/校验行为：仓库根部署脚本 :47-53（账本段与文件名）、:171（版本不是 3 ⇒ LEDGER_MIGRATION_FAILED）、:183（条目形态非法 ⇒ LEDGER_ENTRY_SHAPE_BAD）、:185（读不了 ⇒ LEDGER_UNREADABLE）。

条目形态（照这个写就不会错）

json<数据根>\perms.json（写法示意，不是线上实录）
{
  "version": 3,
  "entries": [
    "T[\"User123456\",\"<工具名>\",\"X\"]",     // 只给这个人这一把工具的入口
    "E[\"User123456\",\"send_group_msg\",\"X\"]", // 允许他发群消息（E 类：对外动作）
    "A[\"Group121873503\",\"D:/share\",\"RW\"]",  // 这个群里的人可读可写 D:/share
    "B[\"ALLUSER\",\"\",\"\"]"                   // 全体用户在 B 类：空位 = 明确拒绝
  ]
}

语法与取值范围出处 auth\Acl.java:40-47；E["…","send_group_msg","X"] 这行是源码自带的示范写法（auth\Acl.java:172）；"空串 = 整个该类"见 :44-47、:92-99；空位串一律当"拒绝"（auth\Acl.java:55-56 的默认位表就是这种"空"的语义）。

改账本前先备份：把 perms.json 复制一份带时间戳再动。非法条目不会被"猜"着用 —— 形态认不出就跳过并给一行告警（auth\Acl.java:624），而过期的 default 字段也会被忽略并告警一次（:590-593）。

04 / 查

怎么查：ai/acl 看权限，ai/perm 看好感度

这两个命令名字像、含义完全不同。一句话：ai/acl 管"能不能做"（只读），ai/perm 管好感度数值。

命令干什么做完会看到什么能不能改
ai/acl 看权限账本：默认分配 + 逐条例外（带主体层级） 两段：一行"默认分配（一条例外都没命中时，按资源类型）" + 一行"她自己的默认分配（SYSTEM）"，然后是账本里的条目逐条列出（空串范围会标注"（空串 = 整个 X 类）"），超出上限会写"还有 N 条" 只读
ai/perm 看/设/重置好感度 好感度数值与榜单口径 能改好感度（不是权限）

出处：命令注册 term\Cmd.java:166（acl）、:162（perm）；命令表原文分工 Cmd.java:1383-1384、:1393-1394；acl 的输出由账本自己生成（auth\Acl.java:647-663）。好感度不参与任何权限判定（auth\Auth.java:32-33、:57）。

她在每一轮都能看到你的权限事实：事实块里有三个键 —— caller.kind（你属于哪类主体）、caller.bits（你对五类资源的有效位 = 结论）、caller.rules（能命中你的例外条目 = 依据）。她据此判断"这件事能不能答应你"。

出处 ctx\CtxBuild.java:298（kind）、:299、:401（bits）、:303、:416-446（rules，含条数上限 :412）；取值一律问账本，基板不另算一套（auth\Acl.java:1113、ctx\CtxBuild.java:120-126）。

05 / 改

怎么授权与撤销

控制台不直接改账本：授权/撤销/查询/验算走她那边的 perm 工具（基板内置工具，随基板走）。

三条路，各管一段

  • 授权 / 撤销 / 查询 / 验算：用她的 perm 工具（对主人开放）；
  • 看结果：ai/acl（只读，账本怎么判就怎么显示，不另算一套）；
  • 看数值：ai/perm（好感度，与权限无关）。

出处 term\Cmd.java:1393-1394（分工原文）、:1384（ai/acl 只读）、term\Builtins.java:1432-1491（视图一律调账本的 bitsOf / source）、:1549-1562（拒绝原文与账本同形）。

落盘与生效

授权/撤销会写账本：同一个"主体 + 类 + 规范化范围"就地覆盖，否则追加到末尾；撤销就是删掉那一条。

出处 auth\Acl.java:724-732（覆盖/追加）、:771（撤销）、:810（不再写已废弃的 default 字段）。给 SYSTEM 写例外时会额外提醒一行（:752-753）。

可照抄的例子（每条都写"在 ai/acl 里会看到什么"）

目标写这一条在 ai/acl 里会看到
让所有人都能用某一项工具 T["ALLUSER","<工具名>","X"] 账本段多出一行 T["ALLUSER","<工具名>","X"]（主体 ALLUSER，层级 1）
只给某一个 QQ开某一项工具 T["User<QQ号>","<工具名>","X"] 多出一行 T["User…"]（层级 3）；同一工具如果 ALLUSER 另有条目，层级高的先算
允许某人对外发群消息（E 类动作） E["User<QQ号>","send_group_msg","X"] 多出一行 E[…]；E 类默认对 ALLUSER 是"无"，所以这一行是唯一来源
全员禁止写 B 类（明确拒绝，压过默认） B["ALLUSER","",""] 多出一行范围为空串的 B 条目（ai/acl 会标注"（空串 = 整个 B 类）"），位是空的 ⇒ 拒绝
把某一类资源整类放开读 A["ALLUSER","","R"] 多出整类条目；A 类默认一位都不给，这一行就是"例外突破默认"

语法依据 auth\Acl.java:40-47；"空串 = 整个该类":44-47；"例外突破默认":84-90；E 类示范 :172；层级覆盖 auth\Auth.java:27。具体有哪些工具名，不在本文档范围内 —— 用 ai/tools 可以看到当前可见的工具名（Cmd.java:1374）。

06 / 默认

默认分配与例外：谁说了算

判定只有一条实现：按类默认分配 + 例外突破默认。一条例外都没命中时，位来自"资源类型的默认分配"。

主体A 本机B SFWC 数据E 对外T 工具
MASTER全权（恒定，任何条目都影响不到）
SYSTEM（她自己）RRWRWXXRWX
ALLUSER（所有人）无无R无无

出处：位表 auth\Caller.java:17-19、auth\Acl.java:55-56（DEFAULT_BITS / SYSTEM_BITS）、逐类常量 :145-181、SYSTEM 那一路 :182-190；有效位的唯一实现 :962-977（bitsOf）；主人恒 RWX 见 :883、:969。

两层"连例外也不开"的受保护资源

  • 第一层：账本自身（perms.json 与它的临时文件）、授权动作本身（mem:acl）、账号凭据（登录态）。只有主人拿得到，连 SYSTEM 也恒为空。
  • 第二层：受限配置文件与脚本（按后缀认定的那几类，只对 B 类路径生效）—— 对 ALLUSER 连读都不给，例外也不开。

出处 auth\Acl.java:1000-1005、:1019-1043、后缀清单 :205-210；判定入口 :969-977。

为什么默认是"拒绝"

A 类 = SFW 数据根之外的任意本机路径 + 本机进程，所以对普通用户一位都不给（读也不给）。要放开只能写例外。fail-strict：拿不准的时候按更严的那一类判。

出处 auth\Acl.java:145-150、auth\Res.java:125-126（真身化不可靠时仍判 A）、:161-165（执行本机程序恒 A 类）。

07 / 拒绝

被拒时长什么样

拒绝是一句可读的说明，而且它是"被算作失败"的形态之一 —— 连续失败闸门靠它计数。

text拒绝文案的形态（产出侧：Host.need* + 账本原文）
缺 W 位 —— [权限阻断] 需要 <资源> 的 W 位（默认分配 <…>，当前有效位 <…>）

产出侧：位名前缀 skill\Host.java:289-291（形如 缺 W 位 —— ），账本原文前缀 auth\Acl.java:125（[权限阻断] ），两者拼起来的完整形态见 skill\Host.java:147-158、tool\Registry.java:207、term\Builtins.java:2311（"一字不差同形"）。

三种拒绝形态都能被认出来

形态长什么样说明出处
① 现代判据正文里包含 [权限阻断]ACL 内核的产出，唯一现代判据（可能在 缺 X 位 —— 之后）auth\Acl.java:125、agent\Loop.java:334-341、tool\Registry.java:351
② 兼容识别出现 [auth] 权限阻断旧写法，只用于识别兼容，不再出现在任何产出文案里auth\Auth.java:40-47、tool\Registry.java:340-341
③ 信息性前缀以 缺 R 位 —— / 缺 W 位 —— / 缺 X 位 —— 开头基板 need* 的位名前缀；它自己不是拦下的证据，但识别面保留它agent\Loop.java:339-341、tool\Registry.java:342-354

为什么这件事重要：权限阻断必须算"失败" —— 否则连续失败闸门数不到它（agent\Loop.java:358-365、:386）。识别一律用"包含 [权限阻断]"而不是"以它开头"（tool\Registry.java:343-344）。

自己怎么复核一句拒绝：拿到那句文案后，去 ai/acl 里比对三件事 —— ① 该类对该主体的默认分配；② 能命中你的例外条目（caller.rules）；③ 当前有效位（caller.bits）。三者一致就说明判对了。

09 / 排错

常见误用与排错

权限问题九成来自三件事：写得不是那个类、位给了错的、或者压根没写。

现象先看什么原因与处理
写了例外但不生效 ai/acl 里有没有那一行、位是不是你要的 ① 主体写错（MASTER 会被拒收，要写 User<QQ号>，auth\Acl.java:429-434）；② 类写错（T 是工具、E 是对外动作，:44-47）；③ 位写空 = 拒绝（:55-56）
同一资源有人能用、有人不能 caller.rules（能命中的例外） 层级高的先算：User(3) > Group(2) > ALLUSER(1)，同级后面的覆盖前面的（auth\Auth.java:27）
改了账本要不要重启 再问一次权限，看判定有没有变 账本首次判定时懒装载（auth\Auth.java:68-69），并有显式重载口（auth\Acl.java:571）；取值与判定共用同一份实现、文件变了会被重读（ctx\CtxBuild.java:120-126）。手改文件后的确切生效时机本文档未做运行期验证
条目形态写坏 那行告警 非法条目被跳过并告警一次（auth\Acl.java:624）；部署脚本对形态非法会给 LEDGER_ENTRY_SHAPE_BAD（仓库根部署脚本 :183）
她"答应不了"某件事 那句 [权限阻断] 说明 说明里点明了资源、该类默认分配与当前有效位；按上一节三步复核即可（skill\Host.java:147-158）
不确定谁能动什么 ai/acl 的两个"默认分配"段 先读默认，再读条目：没写的一律按默认，默认基本是拒绝（auth\Acl.java:145-181）
