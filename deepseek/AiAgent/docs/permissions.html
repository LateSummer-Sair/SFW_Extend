权限与通道

三层通道权限模型将「本地」与「QQ」隔离，按通道收缩工具集与技能范围。 权限由 HarnessConfig 权限矩阵统一裁决（MASTER / GROUP_MASTER / MEDIA / AFFECTION:N）， 越权调用立即终止并告知无权限，execq 通道高危代码被确定性拦截。

Model

三层权限模型

从最高权限到受限，逐层收紧。所有通道均为免确认模式，权限由矩阵 + 代码拦截兜底。

① 本地 execs（console）全量工具 buildAllTools + 技能（general/task/persona）· 本地全信任
② QQ execs:（主人关键字）全量工具 + 全技能（含 NapCat）· 权限提升
③ QQ execq（普通消息）受限工具 buildExecqTools + 仅 NapCat 技能 · 越权立即终止
权限从高到低：本地 execs → QQ execs: → QQ execq
Matrix

工具权限矩阵

HarnessConfig 权限矩阵的默认值（data/harness.json 可热加载覆盖）。

权限级别语义工具
MASTER仅主人（任何通道）sendfile、block、unblock、delfriend、forwardmsg、sendgroupmsg、setaffection、recorddonation、resetdonation、setname、setsignature、settrigger

🔑
权限校验仅在 QQ 上下文（ctx.napcatApi != null）强制；console 本地通道视为全信任直接放行。群管类工具（GROUP_MASTER）还要求 ctx.isMaster 且消息为群聊上下文。

Code Safety

高危代码拦截

execq 非主人通道的动态代码执行受「禁用模式」确定性拦截，防止 AI 通过动态注入绕过权限。

🛡️
仅对 eval / evaljs / sys 三个工具生效，且仅在 execq 非主人通道强制（主人 / 本地全信任）。代码命中以下任一模式即阻断：
禁用模式拦截意图
processbuilder禁止创建进程
runtime.getruntime / runtime.exec禁止通过 Runtime 执行命令
system.exit禁止退出 JVM
class.forname / reflect禁止反射绕过
file.delete / files.delete / .exec(禁止文件删除与进程执行
QQ Permissions

QQ 通道权限细节

🛡️

execq 工具集

仅保留 NapCat 群管/媒体工具 + web/readfile/readdir/weather/time/remember/correct/note/searchnote/balance/vision + 表情包 + setimageremark + 好友申请/群邀请决策 + 捐赠工具 + 好感度三工具 + 跨群操作 + alarm 系统闹钟 + searchglobal/markmessage + call_agent/ask_agent。移除 sys/evaljs/download/schedule/skillextract/superise/editprompt。

🔐

cmd 权限门禁

execq 的 cmd 仅允许 help（格式：组件名/help 或 /help），其他命令越权立即终止并告知无权限。

⚡

eval 严格受限

execq 不注册 evaljs。eval 仅限多对象拆分搜索的联网抓取，禁止文件系统操作、进程执行、反射、类加载（受高危代码拦截）。

👑

修改型指令仅主人

setname / setsignature / settrigger / sendgroupmsg 等修改型指令加 MASTER 权限拒绝，非主人调用立即终止并告知无权。
