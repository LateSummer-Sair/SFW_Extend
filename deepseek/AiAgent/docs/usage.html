想做什么
怎么做

这一页按"我要做某件事"来写：怎么跟她说话、怎么起停、怎么改配置、怎么看数据与日志、出问题先看哪里。 每一条都写了"做完会看到什么"，让你自己能确认成功。某条命令的参数细节在命令参考。

① 跟她说话 → 启动 / 关停 出问题先看哪里
说话

怎么跟她说话

两个入口：QQ（私聊 / 群聊）与控制台 ai/chat。三个入口走的是同一条链路，差别只在"回复发到哪里"。

入口怎么触发你会看到
QQ 私聊 直接发消息就行 她回一条（或按分段规则回几条）消息
QQ 群聊 @ 她一下才会进入处理 被 @ 的那条消息会得到回复；没 @ 的消息她不进入处理（连模型都不调）
控制台 ai/chat ai/chat 你好 回答直接打在控制台（本地控制台 ≡ QQ 里的主人）

"引用了她的消息但没 @" 不会触发 —— 这是设计，不是故障：群聊的触发判据是"这条消息是否 @ 到了她自己"（QqGateway.java）；技能触发词命中时由技能投票另起一轮，不走这一条。所以只引用、不 @ 时判定为否，不产生回合、不会回复。要想让她接话，@ 一下即可。

三个容易被当成故障的正常行为

① 事件缺 self_id 就不认 @

她怎么知道"被 @"？靠事件里带的 self_id；缺这个字段时判定恒为否 —— 表现就是群里 @ 了也不理。

出处：qq\Ev.java。

② 一次回复可能被拆成几条

长回复按分段规则拆开发送（分段开关、长度与延迟都是配置键）。

出处：term\Segmenter.java（replySplit / replyMaxChars / replyGroupMaxChars / replySplitDelayMs / replySplitJitterMs），键登记在 Conf.java。

③ 发图她能看图

消息里带图时，图可以被直接挂进这一轮请求做理解（走 native 档）；这是图片专有能力：语音 / 视频 / 文件段只出标签、不做识别。

出处：qq\MediaAttach.java、ctx\CtxBuild.java、qq\MediaRender.java（图）对比 （语音/视频只有标签）。

起停

启动、重启、关停

先分清三件事：起基板（ai/start）、重启基板（ai/restart）、结束进程（/exit 或按精确 pid）。

启动基板：ai/start

角色：唯一的"加载并运行"命令。它读 config.json、跑 19 步装配。

做完会看到：控制台逐行打印装配进度；结束后 ai/status 显示 ready=1；如果哪一步失败，会点名失败步骤（未启动时是 ready=0 reason=not_started）。出处：Cmd.java。

重启基板：ai/restart

先停旧基板 → 重读 config.json → 重新装配 19 步；不并发：已经在装配/重启时会被明确拒绝（回 BUSY 一句）。

做完会看到：一行"重启已受理"，随后又是一轮装配进度行，最后 ai/status 的「待生效」清单变空。出处：Cmd.java、V4Activity.java。

关停：ai/exit 不是"退出程序"

ai/exit 只停基板

命令表写的是"框架转发到组件 exit()：停基板（不改配置、不卸载插件；之后可再 start）"。

行为：基板停下之后，调试口会随之关闭，而 JVM 进程仍然活着；在没有控制台的场景下，这时无法再 start。这是当前实现的行为，未计划修改。出处：Cmd.java、V4Activity.java。

真正结束：/exit 或按精确 pid

要真正关停，用框架控制台的 /exit（框架自带文档：/exit = 退出 SFW），或者按精确 pid 结束进程。

进程由 SairFrameWork\run.bat 里的 javaw -jar SFW.jar 拉起；框架文档见 SairFrameWork\readme\pages\plugin-dev.html。按进程名批量结束容易误伤同机的其它实例。

想开机就自动跑几条命令：启动脚本可以带一个 .ir 文件，里面每行就是一条控制台命令，随启动依次执行：run.bat "<路径>.ir"（run.bat 用 %* 透传参数）。仓库根就有一个示例脚本，第 5-10 行是逐行命令。

配置

改配置：写完不等于生效

这是最容易踩的一条：除 ai/start / ai/restart 外，所有命令只改配置文件。

怎么改

ai/config 看全部、ai/config <键> 看一个、ai/config set <键> <值> 写一个。写完不会生效，要 ai/start（没在跑）或 ai/restart（已经在跑）。

做完会看到：改完那一行会带"未生效"的提示；ai/status 的「待生效」段会点名这个键；重启后这一段变空。出处：Cmd.java、Conf.java。

谁会被加密

三个敏感键（apiKey / napcatToken / relayToken）密文落盘，回执只回"已设置 / 长度"，绝不回值。

密文与启动目录绑死：密钥派生包含 user.dir。换机器 / 用户名 / 工作目录会解不开 —— 这时把该键改成明文让它重新加密。出处：Conf.java、kit\Crypto.java。

哪些键写进去也没用（三类分开看，别混）

类别键写进去会怎样
有真读者（放心用）mediaVision、visionModels、mediaAttachMax、mediaAttachMaxBytes、mediaExpandQuote、mediaCacheHours正常生效（读取点分别在 ctx\CtxBuild.java、qq\QuoteCache.java）
有键无读者 · 尚未接线mediaRender、mediaRenderMaxChars改了没有任何效果（既不报错也不生效）
有键无读者 · 尚未实现mediaExpandForward、mediaExpandMaxNodes、mediaExpandMaxDepth、mediaExpandMaxChars计划中／未实现：折叠转发的"展开"这件事本身还没做，现状只出一行 [折叠转发 id=… 未展开]

登记处 Conf.java（getter 见）。逐键说明与命令见配置页 · 其余键。把"尚未接线"与"尚未实现"分开写，是因为前者只差一次接线、后者还差功能本身。

动配置之前先存字节：改之前把 config.json 与权限文件各复制一份（带时间戳），再动。理由是配置里既有密文（解不开就白改）、又有人工写的授权清单 —— 权限文件按归属分散：基板内置工具那份是数据根下的 perms-core.jsonc（路径也写在这一份里），每个技能自己那份在它的目录里（三个域各自分层，写坏了只能靠备份回滚）。这两类文件的落点：SairFrameWork\data\AiAgent-V4\（数据根由 Conf.java 拼出，权限文件的读写见 auth\Acl.java）。

提示词

提示词：看、读、改、注入

提示词是数据根里的文件，不是编译进程序里的字符串。控制台 ai/prompt 负责查看与重载。

子动作做什么做完会看到
ai/prompt show看当前生效的提示词按分节打印正文
ai/prompt list列出可读的提示词条目一份清单
ai/prompt sections列出身份提示词的分节分节名与位置
ai/prompt read 名读某一条该条正文
ai/prompt stat看规模与状态字节 / 字符 / 分节等统计
ai/prompt reload重新从文件加载提示词一行"已重载"；这条不需要 ai/restart
ai/prompt inject <slot> <key> <文本>往某个槽位注入一段文本注入结果回执（slot 取 system / context / tool / arg）

出处：Cmd.java（命令表原文）（提示词正文有它自己的热重载）。冷启动只建 0 字节空壳文件、不带任何文案（Boot.java）—— 所以"提示词是空的"是没放文件，不是坏了。文件落点与加载顺序见文件页 · 提示词。

权限

权限与好感：两个不同的东西

一句话分工：ai/perm 管"能不能做"（技能管控表），ai/favor 管好感度；改判据是改技能管控表，不是改好感度。

ai/perm：看技能管控表

打印整张表 + 一段怎么用。判据是那些按归属分散的权限文件：基板内置工具那份在数据根下的 perms-core.jsonc，每个技能自己那份在它的目录里，装载时两者合并成一张表，分成技能（谁能用哪个 op）、数据（谁能改、谁能读哪类数据）、文件（谁能碰哪些路径）三个域，每个域里是自己的层，规则键写成中括号数组；没列到的按该域的默认值走 —— 技能不能用、数据能读不能改、文件不能碰，同一把键上 Ban 压过允许，更具体的键优先。

身份三类 MASTER / SYSTEM / ALLUSER；主人（MASTER）与她本人（SYSTEM）恒全权，不受表影响。出处：Cmd.java、auth\Auth.java、auth\Acl.java。

ai/favor：好感度

ai/favor 看榜单、get 看一个人的数值与档位、set 直改、reset 清成初值。好感度不是权限，也不参与任何判定——它只影响回话热络。

出处：Cmd.java，auth\Favor.java。想给别人放开某项能力：在那个键归属的那份权限文件的对应层里补一个身份（技能自己的工具与它的数据在该技能目录的 perms.jsonc；基板内置工具、其余数据键与全部路径在数据根的 perms-core.jsonc），或在控制台敲 ai/perm run <op> <身份>、ai/perm db|file … <身份>。

默认对非主人是全关的：表里没列到他，就是一个 op 都没有，数据不能改、路径不能碰；三个域里只有数据那一域的"读"是例外 —— 没列到时默认可读（装载时会点名列出来）。同一把键上 Ban 压过允许，更具体的键优先。主人（MASTER）与她本人（SYSTEM）恒全权、任何条目都影响不到他们。出处：auth\Acl.java。

调试

调试面：两个口，一条命令管起停

调试面与基板相互独立：不需要先 ai/start，它自己就能开。

两个口是什么

输出口默认 2660：接进来就能读状态与执行调试命令；输入口默认 2661：可以把一段"外部事件"喂进来，走和真实事件同一条链路（仿真开关默认开）。两个口都只绑回环地址，并且都要带 token。

出处：Conf.java（2660）（2661）（仿真出厂值）；实现 dev\DebugPort.java、dev\DebugSimPort.java。

怎么开、怎么关

ai/debug on [token] 开（token 不给就现生成一个，只落进数据根的 debug-port.json，不进 config.json）、ai/debug status 看状态、ai/debug off 关、ai/debug simulate on|off 切输入口的仿真。

做完会看到：on 之后回一行"调试面已开"加端口与 token 指纹；status 打印两个口的监听状态。只有这条命令能起停这两个口；ai/restart 不会把它关掉。出处：Cmd.java。

客户端脚本：连这两个口用的是仓库根随附的调试脚本（形如 _sim.ps1 / _dbg.ps1）。本文档只写"口是什么、怎么开关、连上要带 token"，没有逐条核实这些脚本自身的参数 —— 用法以脚本自身为准（这一条属未核实项，明确标出）。

数据

数据、日志与备份

预算有限的话只记一句：要备份就复制数据根里的那几个文件，程序与目录结构可以不动。

东西是什么你要注意什么
v4.db唯一的数据文件（业务库 + 运行表 + 全文索引都在里面）备份就是复制它；它的表结构交给基板自己维护就好
config.json配置文件（已知键 94 个）含密文；换启动目录会解不开
perms-core.jsonc基板侧的权限文件（主人写的，三个域各自分层，路径也写在这一份里）写坏了只能靠备份回滚
skills\<技能名>\perms.jsonc技能自己的权限文件（只写这个技能提供的工具与属于它的数据键；目录里没有它 = 它的 op 都不授权）跟着技能目录走：删掉目录，它的授权也一起消失
prompts\提示词文件ai/prompt reload 即可重载，不必重启
files\下载 / 图片落点，库导出也落这里体积会随使用增长
日志目录运行期日志，按大小滚动、只增不删排障先看这里；不会自动清理

数据根 = SairFrameWork\data\AiAgent-V4\（路径拼接见 Conf.java）；日志滚动口径见 dev\DebugLog.java。更细的逐文件说明见文件页 · 数据根。

用 ai/store 做维护与搬运

子动作做什么做完会看到
ai/store stat看每个库的条数与占用一份库清单 + 总条数 + 文件大小（含 WAL 占用）
ai/store maintain按保留期清理过期流水清理结果回执；清理不会自动缩小文件
ai/store export <库>把某个库导出成文件一行"已导出 <绝对路径>"，落点在 files\（Cmd.java）
ai/store import <库> <路径>从文件导回某个库一行"已导入 N 条"

出处：Cmd.java。保留期三把尺子（记忆 / 对话 / 群聊）默认 30 / 180 / 30 天，<=0 = 不过期（Conf.java）。

故障

出问题先看哪里

顺序固定：先 ai/status，再看控制台/日志里的那一行，最后才动配置。

现象先看什么常见原因与处理
聊天不回、命令说"未装配" ai/status 还没 ai/start（ready=0 reason=not_started）；或某一步装配失败 —— status 会点名失败步骤与原因
改了配置没反应 ai/status 的「待生效」段 ai/config 只写文件；用 ai/restart 让它生效
ai/restart 回 BUSY 它自己的回话 已经有一条装配/重启在跑 —— 等它结束再试，不用连着敲
QQ 侧没反应 ai/napcat status 监听失败（端口被占）或 token 不匹配；本地交互不受影响。非本机监听 + 空 token 会直接拒绝启动监听
群里 @ 了也不理 消息里 @ 到的是不是她；事件里有没有 self_id 只 @ 才触发；缺 self_id 时判定恒为否
密钥解不开 解不开时的提示行（只含因子描述、不含密钥） 换了机器 / 用户名 / 工作目录 —— 把该键改成明文让它重新加密
外挂层某个单元没起来 ai/status 的步骤台账 装载失败只让那一项能力缺位，装配继续往下走；ai/status 能看出缺了哪一项（技能怎么写见 11 · 技能开发）
程序还在、基板没了 进程是否仍在 这是 ai/exit 的行为：只停基板、调试口随之关闭而 JVM 仍活；要真正关停用 /exit 或按精确 pid

出处：状态与失败步骤 Cmd.java；NapCat 监听与降级 Boot.java、qq\Link.java；重载口径 Cmd.java；装配失败继续 Boot.java；关停 Cmd.java、V4Activity.java。

安全重启的标准动作：① ai/status 记下当前状态与「待生效」清单 → ② 需要的话先备份 config.json 与那几份权限文件（perms-core.jsonc 与各技能目录里的 perms.jsonc）→ ③ ai/restart → ④ 等装配进度打完 → ⑤ 再 ai/status 确认 ready=1 且「待生效」为空 → ⑥ 群里 @ 她发一条测试消息。

确认

做完怎么确认成功

把"成功的样子"列成表：看不到这些，就说明还没成，别当成已经生效。

你做了什么成功的样子
ai/start装配进度打完 + ai/status 里 ready=1
ai/restart一行"重启已受理" + 新一轮装配进度 + 「待生效」清单为空
ai/config set …回执提示"未生效"，并且 ai/status 的「待生效」段出现该键
ai/prompt reload一行重载回执，不需要重启
ai/debug on一行"调试面已开"+ 端口信息；ai/debug status 显示两个口的状态
群里 @ 她她回消息（不 @ 不回，属正常）
要结束进程进程消失（/exit 或按 pid）—— 只用 ai/exit 时进程仍在，这是预期
