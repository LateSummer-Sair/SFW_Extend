技能系统

AI 执行轨迹自动蒸馏为可复用技能，分层技能库（general/execq/task/persona）。 支持内置技能、三方技能（一技能一文件夹：md 文档 + Java 源码）、路径权重路由。

技能文件夹（md + Java）

工具技能 = data/skills/<名>/：<名>.md（元数据 + 说明）+ *.java（实现，可多个文件，辅助类一起编译）。代码只支持 Java，md 里的 <java start> 内嵌代码段已废弃。入口方法固定叫 airun，多个类都有 airun 时用 entry: 指定；airun.params 支持 default/enum/example/items 声明式入参，returns 写明返还内容，context: true 注入只读上下文（通道/群号/QQ号/是否主人/好感度），timeout 与 state 控制执行。加载即编译注册（改 md 或 .java 都新替旧，调用期不再动态编译，编译失败在控制台点名）。声明后自动注册为 FC 工具 tp_<name>（或 tool: 顶替内置工具），工具名自动规范化为 ^[a-zA-Z0-9_-]+$。

Builtin

内置技能库（已整体迁出）

硬编码技能文档已全部迁出到 data/skills/*.md：SystemSkillLib（31 条系统技能）与 NapCatSkillLib（52 条 NapCat API 技能）的正文都不再以 Java 字符串常量存在。

🧰

SystemSkillLib

只剩两件事：RETIRED_BUILTINS 名单（功能已整体移除的技能，无条件下线）与 retireSupersededBuiltins()（库里存在同名 .md 就把旧内置记录 deprecateSkill() 下线）。技能内容一律来自 data/skills/，改文案不用改代码、不用重打包、不用重启。

🐱

NapCatSkillLib

同样只保留退役名单；52 条 NapCat API 技能文档（消息发送 / 群管操作 / 好友管理…）已迁出为单文件 .md，其中的工具类能力（发图 / 群管 / 跨群 / 打标）仍由 Java 侧的 onebot 包实现，只是说明书搬到了文件里。

💡
旧库里的 builtin 记录靠条件式退役下线：只有同名 .md 真的存在时才下线，所以「先拷 .md 再上线」不会出现文档空窗；内容保留可查（skillinfo 按 id 查回），只是不再进索引与检索。
Third Party

三方技能（一技能一文件夹 + Java 实现）

data/skills/ 下「一技能一文件夹」（md 文档 + Java 源码），WatchService 监听根目录与各技能文件夹。

放入技能文件夹 / .md 文件data/skills/<名>/（md + Java）或纯文档 data/skills/*.md
ThirdPartySkillStore 扫描parseMarkdown 提取元数据 + 文件夹里的 Java 源码（只认 .java）
加载期编译注册Java 源码一次编译进注册表 · 改文件新替旧 · 调用期不再编译
动态注册工具airun 签名 → tp_技能名，Function Calling 直接调用
SkillCodeRunner 执行airun 入口（强制返回值）
三方技能代码段执行链路
⚠️
代码段权限受 /setthirdpartycode 控制：on=放权（所有通道含 QQ）；off=仅 execs/本地可用。
