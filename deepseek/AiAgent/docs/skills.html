技能开发 · 从零写一个

一个文件夹
就是一个能力

技能是外挂层：一个文件夹 + 一份同名 md，再加任意几份 .java，就是一个能力。 基板启动时把它编进内存、注册成工具、挂上事件钩子与扩展点；文件夹删掉，这个能力就彻底消失。 这一页把每一样东西该怎么写讲到底 —— 目录怎么摆、md 的每个键填什么、 代码里 call 与 Host 怎么用、perms.jsonc 怎么填、 钩子与四个扩展点接口各管什么，最后给一份从零到能用的清单。

01 / 布局

一个技能长什么样：目录与每个文件

技能的最小单位是一个文件夹。文件夹名字就是技能名，文件夹里那份同名 md 是它的身份证 —— 少了那份 md，这个文件夹等于不存在。剩下的东西按需要放：要提供工具就放 .java，要给模型一句更清楚的话就写 airun，要存文案与阈值就放 prompt.md，要让别人也能用就放 perms.jsonc。

目录长这样（把每个位置都标出来）

text<数据根>\skills\例子\ 的完整形状
<数据根>\                              数据根出厂是 SairFrameWork\data\AiAgent-V4\
└─ skills\                             技能库：这一层下面每个文件夹就是一个技能
   └─ 例子\                            技能名 = 文件夹名（可用中文）
      ├─ 例子.md                      必需：与文件夹同名的 md（front matter 声明 + 正文说明书）
      ├─ Example.java                 可选：工具入口类，几个都行
      ├─ Helper.java                  可选：同一个技能里的其它类，一起编译
      ├─ prompt.md                    可选：文案 / 阈值 / 词表，技能运行时自己读
      ├─ perms.jsonc                  可选：权限表（谁能用这个技能的工具）
      └─ assets\                      可选：自带的图片、词典、模板等，基板不读，技能自己读
         └─ hi.png

技能名 = 文件夹名 = Host.skillName() 的返回值；md 名也要与它逐字一致。中文技能名可以照用（真技能几乎都是中文名），只有工具名那一项要合接口规范，见下面「技能名带中文会怎样」。

每个位置放什么、少了会怎样

位置必需吗它是干什么的少了 / 写错了会怎样
<技能名>.md 必需 这个名字的 md 是技能身份。开头的 --- 之间是 front matter（机器读的声明），下面的正文是给人看的说明书。 找不到 → 这个技能状态 ERROR，错误是「缺少同名文档 <技能名>.md」，它在工具面里不存在。
*.java 可选 技能的可执行代码。运行期编译到内存里，磁盘上不留 .class 文件。 一份都没有 → 这个技能是纯文档 / 纯钩子状态：md 里的 tool: 声明了工具也不会注册（没代码可跑）。
prompt.md 可选 两件事：① 技能运行时用 Host.skillDir() 读它，把文案、阈值、词表放在里面（改完即时生效，不用重编译）；② md 里写了 inject: 时，装载期把整篇注入到那个槽位。 不写也能跑，但技能里就得把文案硬写在 java 里；声明了 inject: 却没有这份文件 → 什么也不注入（不会报错）。
perms.jsonc 可选 这个技能提供的工具给谁用。与 md 同级放在技能目录里。 不写 → 这个技能的全部 op 对 ALLUSER 一律不授权（默认拒绝），工具只有主人与她本人用得到。详见第 04 节。
图片、词典、模板等 可选 技能自己的数据。基板不解析它们，也不会因为多一个文件而多做一件事。 没影响。技能用 h.skillDir() 拿到自己的目录再去读。
*.class / *.jar 不要放 — 技能目录不是 classpath：编译在内存里做，磁盘上的类文件不会被加载，放了也没有作用。

扫描只认这些名字：md 是 文件夹名 + ".md"，代码是 .java，两者之外的扩展名基板都不看。目录里可以再建子目录，技能目录本身以及它下面两级子目录里的 .java 都会被编进去。

md 名要不要跟目录名一致：要，而且 name: 也要一致

md 名要与目录名逐字相同

装载器直接按 目录名 + ".md" 找文件，所以 data\skills\天气查询\天气查询.md 是唯一会被读到的路径；叫 weather.md 就等于这个技能没有 md。

front matter 里如果写了 name:，它的值也要与目录名逐字相同。不同 → 状态 ERROR，错误文案会同时点名声明名与文件夹名（front matter name 与 文件夹名 不一致）。中文、数字、下划线都行，差一个空格也算不一致。

真技能是怎么写的

真技能一律让三者对齐：目录 天气查询\、md 天气查询.md、front matter 里 name: 天气查询。name: 这一行其实可以不写（不写就不做校验），但写上以后，技能名在 md 里一眼可见，改动时不容易错。

tool: 与技能名是两件事：技能叫天气查询，工具可以叫 weather。

放几个 .java、类名有没有要求

份数零到任意多份一起编译
怎么摆
同一个技能目录里的所有 .java 一起编译、共用一个类加载器，类和类之间可以互相引用（情绪 这个技能就是 7 份 java 放一起）。
一句话说明
工具入口放一个类，扩展点放另一个类是最自然的写法；基板会扫这个技能的每个顶层类，谁实现了接口就注册谁，不用把两件事硬塞进一个类。
类名与包名类名不限，不写 package真技能都是这样
怎么写
类名随你起，不写 package，类的全名就是类名本身（WeatherSkill）。要用基板的类就 import sair.v4.skill.Skill; 这样引进来。
入口类怎么定
按这个次序找：① md 里写了 entry: 就用它（写短名或全名都认）；② 第一份实现了 Skill 接口的顶层类；③ 带 airun 方法的顶层类；④ 第一个顶层类。同一批类名按字母序，所以每次装出来的入口都是同一个。
找不到入口
有 java 却没找到任何顶层类 → 状态 ERROR，错误是「找不到入口类」。
内部类可以写，但不当身份跳过
规则
名字里带 $ 的内部类、匿名类不会被当成插件身份（不拿来当入口类，也不拿去注册扩展点），但可以被自己的外部类正常使用。

技能名带中文会怎样：目录与 md 保持中文，工具名自动英文化

能带中文的部分

文件夹名、md 名、front matter 的 name:、description:、正文、prompt.md 全都可以是中文，真技能几乎全是中文名。

可执行代码里的中文也一样正常，源码按 UTF-8 编译。

不能带中文的那一处：tool:

模型接口对函数名只收 [a-zA-Z0-9_-] 且不超过 64 个字符。技能 md 的 tool: 是手写的，写成中文（tool: 发表情包）不是「这个工具不可用」，而是服务端直接拒掉整条请求。

基板的做法不是报错，而是自动英文化注册：把声明名转成 tp_ 前缀的名字 —— 名字里的 ASCII 字母数字保留，再加一段由声明名算出来的稳定短后缀（同一份 md 每次算出来都一样，重启也不变）；纯中文名就是 tp_ 加那段后缀。撞车时按确定规则让位（-2、-3）。目录名与 md 名保持中文不动。

注册名才是能用在各处的那个名字：权限表里的 op、ai/perm run 敲的参数、代码里 h.need("…") 传的名字，用的都是注册名。声明名与注册名的对照，启动时打一行 [skills] 日志，技能列表里也带 tool_declared 与 tool_note 两句说明。所以新技能最省事的写法就是一开始就把 tool: 写成 ASCII 名字，别让基板替你改名。

工具名与基板内置工具重名 = 直接失败：基板自己那批工具名是保留名（napcat、console、exec、prompt、model、perm、store、tools、skill、ctx、config、agent、alarm、sendimage 这一类）。技能声明的工具名撞上它们 → 状态 ERROR，错误是「与基板工具重名（基板工具名是保留名，请改名）」，这个技能整条不装。

一个技能提供几把工具

一个技能最多一把工具：tool: 是单个名字，不是数组。工具里的「多个功能」靠一个选择子参数（真技能里习惯叫 op）分动作，权限按 工具名.动作名 一条条分开写 —— 这样「允许他记一笔」与「允许他删别人的」在表里就是两行，而不是一个开关。

另一种技能干脆不提供工具：md 里不写 tool:，只写 hooks: 与 java 里实现的扩展点接口。这种技能在 ai/tools 里看不到，模型也不能调它，它的能力全挂在事件与回合上（私聊输入态、情绪 都是这一种）。

最小可用技能 与 完整技能

最小可用：一个文件夹 + 两份文件

只做一件事、只给一个动作、不需要配置与权限口子：

textdata\skills\例子\（最小可用）
例子\
├─ 例子.md          写死工具名与参数表
└─ Example.java     implements Skill，call() 里先判 op 再干活

这样就能被 ai/tools 看到、被模型调用；perms.jsonc 不写就是「只有主人与她本人能用」。

完整技能：该有的都摆上

多动作、要配置、要别人也能用、还挂一个回合钩子：

textdata\skills\例子\（完整）
例子\
├─ 例子.md          声明 tool / hooks / airun（说明、返回值、参数表）
├─ Example.java     implements Skill, Hooked：工具入口 + 消息钩子
├─ ExampleProvider.java  implements ContextProvider：每轮注入一段
├─ prompt.md        全部文案、阈值、词表（运行时读，改完即时生效）
├─ perms.jsonc      这个技能的工具与它的数据给谁用（可选）
└─ assets\hi.png    技能自己的素材

两个类各管一件事、一起编译，基板两个都会注册。

改完什么时候生效

基板不监听目录：加载时机只有两个 —— 启动时扫一次，以及显式重载（控制台 ai/skill reload，或模型侧 skill 工具的 op=reload）。改了 md、java、prompt.md 之后不重载，就看不出任何变化。

重载会不会重编，看这个技能目录的内容有没有变（md 的修改时间与大小、每个 .java 的修改时间与大小、prompt.md 的修改时间与大小）。只改了技能自己读的素材文件（比如 assets 里的图片）不在这个判断里，但那种文件本来就是运行时现读的，不影响。

02 / 文档

同名 md 怎么写：front matter 逐键讲解

md 分两半。上半是夹在两行 --- 之间的 front matter，机器只读这一半：工具叫什么、给模型看什么话、参数表长什么样、挂哪些钩子。下半是正文说明书，给人看的，基板一个字都不喂给模型。这一节把上半能认的每个键都列出来，并给一份能直接抄的模板。

先认边界：front matter 从哪开始、到哪结束

认边界的三条规则

  • 文件第一处非空行要是 ---（前后空格随便），它才是起始行；第一处非空行是别的内容，整个文件按「没有 front matter」处理，于是所有声明键都不生效 —— 这时候 md 只是一份说明书，技能不提供工具。
  • 再往下找到下一个 ---，它是结束行。两行之间的内容才是声明区。
  • 结束行下面的全部内容就是正文说明书，ai/skill read <技能名> 会把它原样打出来。

声明区认的语法（一个很小的 YAML 子集）

text声明区能写的四种形状
key: value              一行一个键，冒号后面是值
key: [a, b, c]          行内数组，按逗号切开
key:                    冒号后面留空 = 下面是个子块
  sub: value            子块（缩进决定层级）
list:
  - a                   子块也可以是一串列表项
  - b

除此之外还有两件小事：整行以 # 开头的行是注释（跳过）；值两端成对的单引号或双引号会被剥掉。锚点、多行块、引号转义这些高级写法都不认。

缩进只用空格，一行一个冒号：认缩进时只数行首的空格数，Tab 不算 —— 一个 Tab 会被当成第零层。缩进比上一层更深的行如果不在子块位置上，会被整行跳过，于是那个键就像没写过一样。声明区里也只看每行第一个冒号：值是 时间: 12:30 这种带冒号的东西时，键会被切错，把值整体加引号也救不回来（引号是在切分之后才剥的）。

每个键：名字、取值范围、默认值、写错的后果

name字符串，默认空技能名
它是干嘛的
技能名，字符上要与文件夹名逐字相同。
怎么写
name: 天气查询。可以不写；写了就参与校验。
写错的后果
与文件夹名不一致 → 这个技能状态 ERROR，整条不装，错误文案点名两个名字。
description字符串，默认空一句话
它是干嘛的
一句话概括这个技能。它有两个用处：技能列表里显示的那一句；以及当 airun.description 没写时，顶上来当工具说明给模型看。
怎么写
一句短话，说清「提供什么能力」，不要在这里讲权限、不要写长段落。
写错的后果
写空不报错，但模型看不到这把工具是干什么的，容易猜错用法。真要给模型看的说明写在 airun.description 里更准确（那里的写法要求不同，见下）。
tool字符串，默认空决定有没有工具
它是干嘛的
这把工具给模型看、给模型调用的名字。不写 tool: 就没有工具：即使 java 里实现了 Skill，也只在事件钩子与扩展点上生效，模型看不到它。
取值范围
只收 a-z A-Z 0-9 _ -，1 到 64 个字符。中文名会被自动英文化成 tp_ 前缀的注册名（见第 01 节）。基板内置工具名是保留名，撞上就是 ERROR。
写错的后果
不合规范 → 改名注册，权限表与 h.need(...) 里要跟着用注册名；与基板工具重名 → 整条不装。
hooks数组，默认空事件钩子
它是干嘛的
声明这个技能想接哪些事件。取值只有四个：on_timer（基板唯一心跳）、on_message（一条入站 QQ 消息）、on_request（好友申请 / 群邀请）、on_notice（通知类事件：戳一戳、撤回、进群、禁言这类，只读留痕）。
怎么写
行内数组 hooks: [on_message, on_timer]，或逗号（空格也行）分隔的一行 hooks: on_message, on_timer。两者都认。
写错的后果
名字写错 → 这个钩子永远不会被派到这个技能，启动日志里会有一行说明「声明了钩子 X，但入口类里没有匹配的方法」只有在名字对而上层没实现时才会出现；名字拼错时连这一行都没有，只能靠 ai/skill list 里显示的 hooks= 去对。
inject字符串，默认空配 prompt.md 用
它是干嘛的
把同目录 prompt.md 的整篇文字注入到某一类提示词槽位里，让每轮模型都看得到。槽位四个：system、context、tool、arg。
怎么写
inject: context 这一类。注进的是全局作用域，键是 skill:<技能名>。
写错的后果
槽位名写错 → 那一串不会被任何地方读到（等于没注入）。没有 prompt.md，或者文件是空的 → 什么也不注入，不报错。改过 inject 或删掉这一行时，这个技能以前占过的四个槽都会被清一遍，不会留下旧内容。
entry字符串，默认空可选
它是干嘛的
直接指定哪个类是工具入口，跳过自动挑选。
怎么写
写短类名（WeatherSkill）或全名都认。
写错的后果
写了一个不存在的类名 → 自动挑选取代它（挑不到才 ERROR）。一个技能有多个类、又想让某个特定类当入口时，用它最省事。
airun子块，默认空给模型看的那一份
它是干嘛的
工具的名片：说明、返回值说明、参数表、用法示例、实例复用口径。模型的工具清单就是从这里生成的。
子键
description（工具说明，空则退回顶层 description）、 returns（返回值说明）、 params（参数表，见下一段）、 examples（用法示例）、 state（per_call 默认，每次调用新建实例；shared 表示整个进程复用同一个实例）。
写错的后果
整块不写 → 工具仍会被注册，但参数表是空的（模型只能瞎填），说明退回顶层 description。
permission不读，写它没有效果已退休
现在的口径
旧「权限档位」那一套已经整批退休。技能列表里那个 permission 字段恒为空串，装载时被固定清空；写任何值都不会生效，只会让下一个人以为档位还活着。
权限现在写在哪
技能目录里的 perms.jsonc，见第 04 节。

除上面这些之外的键，解析器一律收进声明区但没人读它们（不报错、不生效）。键名区分大小写。

参数表 airun.params 怎么写

一个参数一个子块

参数名就是键，值是一个子块，里面每个字段决定模型看到的 JSON Schema 长什么样。字段与它们的别名（两套写法都认）：

  • type / 类型：string（不写时的默认值）、integer、number、boolean、array、object；
  • description / 说明 / desc：给模型看的那句解释，写得越具体，模型填得越准；
  • example / 示例：会以「示例：…」的形式拼到说明后面；
  • enum / 取值：行内数组，把可选值钉死（多动作技能的 op 参数就靠它）；
  • default / 默认：默认值；
  • required / 必填：写成 true（也认 1、yes、on、是）；
  • type: array 时再加两个：items / 元素（元素类型，默认 string）与 items_description / 元素说明（元素说明）。

掺平写法与漏写的兜底

参数值直接写一句话（不是子块）时，就当成「类型 string，这句话是说明」。所以 city: 城市名 这种偷懒写法能用，但拿不到 required 与 enum。

写进 required 列表的参数，模型不给就会被服务端拦一次；代码里仍然要判 —— 模型可能不遵守，也可能别的技能直接调你。参数缺失时用 a.missing("参数名") 拿到一句现成的说明（内容是「缺少参数 参数名」），把这句话原样返回给模型，它下一轮就会自己补。

类型标 integer 的参数，代码里用 a.l("名字", 0L) 或 a.i("名字", 0) 取，不要用 a.str(...) 再自己转 —— 参数的强类型取法就是为了躲开「字符串带引号」这类坑。

text参数表的两种写法（推荐左边那种）
params:                           params:
  op:                               city: 城市名，不填按出口 IP 定位
    type: string
    required: true
    enum: [one, two]
    description: 操作：one=做第一件事，two=做第二件事
    example: one
  text:
    type: string
    description: 要处理的文本
  tags:
    type: array
    items: string
    items_description: 每个标签一个词

说话的那几个键：给模型看的话怎么写

键谁看写什么写法要点
description技能列表 + 工具说明的兜底一句概括短。这里是给人扫列表用的，不是给模型挑工具用的。
airun.description模型（工具说明）「什么时候该用它 + 它做什么 + 别拿它干什么」可以写长一点，把触发场景写进去（「问天气 / 要不要带伞 / 冷热时用」）。多动作工具在这里把每个动作点名一遍，模型才知道该给哪个 op。
airun.returns模型成功时返回什么形状、失败时返回什么形状把失败前缀也写进去（真技能都写「失败返回以 [weather] 开头的说明」），模型才知道那不是在骂它。
airun.examples模型（拼进工具说明）一行一条「用户这么说 → 走哪个 op」行内数组或逗号分隔的一行都认。写 2 到 4 条就够，覆盖最容易搞混的那几个动作。

正文那半是给人看的：讲清楚动作、返回、失败形态、边界。它不会进模型上下文 —— 想让模型每轮都看到一段固定的话，用 inject: 加 prompt.md，或者在扩展点里每轮产一段（见第 05 节）。

分类与顺序：没有这种键

md 里没有分类键，也没有排序键：技能表、工具表、权限表里的顺序都不是从 md 来的。工具清单按名字排序（大小写不敏感）；权限表的分组与顺序来自装载期声明的 op 清单，同一个工具下的动作按名字排序；技能列表按技能名排序。所以想让工具在清单里靠前或者归到某一类，办法不在 md 里 —— 唯一的表达位置是 description 那句话和 declareOps 里每个 op 后面那句中文释义。

权限表里那些中文释义（// ── 查天气 这类注释行）就是 declareOps 的第三个参数；工具分组上那一句括注来自工具自己的说明（技能不用自己补，注册时基板会取）。工具级的那条键只覆盖它已经注册的动作：没声明过的动作不会被旧授权顺手放行。

扩展点在 md 里怎么声明：不声明，靠 implements

钩子要写 hooks:

on_message 这种名字本身不带类型信息，所以要在 md 里点名。声明了却没人实现，启动时会有一行说明。

四个扩展点接口不用写

ContextProvider / OutboundStage / LifecycleHook / TriggerVoter 这四个，类上写了 implements 就已经表明了意图。基板装载时扫这个技能的每一个顶层类，谁的接口对得上就注册谁 —— 再在 md 里抄一遍接口名，只会多出一个「抄错了就静默不生效」的坑。

另外一条容易踩：钩子只派给入口类。扩展点扫每个顶层类，Hooked 却只在入口类上找。所以 Hooked 要写在入口类那一份 java 里（TriggerSkill 就是 implements Skill, Hooked），扩展点可以另开一个类。

## 两个动作
- `one`：做第一件事。写清它需要哪些参数、返回什么。
- `two`：做第二件事。写清它和 `one` 的区别，免得用混。

## 失败长什么样
- `[example] 缺少参数 text` —— 参数没给够，模型看到这句会自己补。

## 权限
这个技能提供 `example` 一把工具，两个动作各是一个 op（`example.one` / `example.two`），

写作规范（照这几条写就不会出怪事）

项怎么写为什么
缩进只用空格，一层两个空格，同一个子块的兄弟键对齐认缩进只数空格；Tab 会被当成第零层，子块整段失效
冒号键后面紧跟冒号，再空一格写值只看每行第一个冒号；键名本身不能带冒号
引号可省。值里有逗号、方括号或前后空格时，用引号包起来更稳行内数组与行内子块按逗号和花括号切分，引号是在切分之后才剥掉的
中文值里随便用中文，参数名建议用 ASCII参数名就是模型看到的字段名，ASCII 更不容易出岔子
注释声明区里整行以 # 开头的行是注释；行尾注释没有（行尾的 # 会被当成值的一部分）只跳过整行注释
一个 md 声明几个工具只能一个。要提供两把工具就建两个技能目录tool: 是单个字符串，一个技能只注册一把工具
多动作怎么写一把工具 + 一个选择子参数 + declareOps 里一个动作一条权限、清单、ai/perm 的分组都按这些 op 名走
正文用 Markdown 写，怎么排版都行正文不参与解析，只被原样打印给人看

别把 airun: 块和 airun 方法搞混：airun: 是 md 里的名片块，只填说明与参数表；另外还有一条反射回退的路 —— 入口类如果没实现 Skill 接口，但它有一个叫 airun 的方法，基板会去调那个方法（形参按能不能接受实参匹配，依次尝试 airun(Map, Map)、airun(Map, JSON)、airun(Args, Host)、airun(JSON, Map)、airun(JSON, JSON)、airun(Map)、airun(JSON)、airun(Args)、airun()）。这条路是给「不想写 import 的小技能」用的，跟 airun: 块没有关系；两者都存在也不会互相影响。真技能走的是 Skill 接口那条路。

03 / 代码

java 怎么写：Skill、Args、Host 三个面

技能代码只有三条边：实现 Skill（工具入口）、从 Args 取参数、通过 Host 调度基板资源。加一条规矩：每个动作分支开头用 h.need("工具.动作") 自查一次权限。这一节把三个面逐条讲完，最后给两个骨架 —— 一个最小的，一个带参数校验、多动作、用业务库、会拒错的。

装载一次都发生了什么（知道顺序就不容易懵）

步基板做的事对你的代码意味着什么
①读同名 md，解析 front matter键写错在这一步就暴露：名字不一致、工具名撞保留名，都会停在 ERROR。
②把这个目录里的 .java 一起编译到内存里编译不过 → 状态 ERROR，这个技能的全部能力都不在（工具、钩子、扩展点一起没有），别的技能不受影响。
③挑出入口类，建立类加载器与 Class入口类要有一个公开的无参构造函数。
④对每个实现了 Skill 的顶层类各调一次 declare(Libs) 与 declareOps(OpList)表要在这里声明，op 要在这里点名；这一步在注册工具之前，所以表一定比用它的工具先存在。
⑤注册扩展点 → 注册工具 → 挂事件钩子 → 装注入片段扩展点扫每个顶层类；钩子只在入口类上找；inject 要配 prompt.md。

Skill 接口：三个方法

Object call(Args a, Host h)唯一的抽象方法工具入口
拿到什么
a 是这一次调用的参数包（模型填的），h 是这一轮的基板能力面。实现这个接口，这个类就被当成技能的工具入口。
返回什么
返回的东西会被规整成文本再交给模型：String 原样、JsonObject / JsonArray / Map / List 转成 JSON 文本、null 等于「成功但没有输出」、其它类型走 String.valueOf。所以最省事的做法是返回一句话：给模型看的成功结果，或者失败原因。
失败怎么写
返回的文本第一行如果是 [<工具名>] ok=0 … 这个形状，主循环会把它认成一次失败。抛异常也一样算失败，但基板接住后拼出来的文本会带上调用栈，模型看到更懵 —— 自己拼一句说明更好。
void declare(Libs libs)默认空实现声明自己的表
它是干嘛的
装载期声明这个技能要用到的业务表。表结构由用到它的技能声明，基板只给注册表、按声明建表补列（幂等）。
什么时候调
入口类实例化之后、注册工具之前，只调一次。表要比用它的工具先存在。
谁会被问
这个技能编译出来的每个实现了 Skill 的顶层类都会被问一次，谁实现谁声明；同一个技能声明两次同一张表是幂等的。所以纯行为插件（只挂扩展点、不提供工具）想建表时，加一个只写 declare、call 直接 return null 的壳类就行（md 里不写 tool: 就不会注册任何工具）。
出错的后果
入口类的声明失败 → 这个技能整条 ERROR（其余技能照常）；非入口类声明失败 → 只一行提示、跳过那个类。表名或别名被别的技能占了 → 这个技能声明失败。
void declareOps(OpList ops)默认空实现管控表的骨架
它是干嘛的
声明这个技能有哪些 op（动作）。权限表按这些名字放行或封禁，ai/perm 的分组与释义也从这里来。不声明也能跑，但管控表里这个工具就只有工具名那一层，动作分不开。
怎么写
单动作工具：ops.add("example", "", "做一件事")（动作名传空串，op 就是工具名）。多动作工具：每个动作一条 ops.add("memory", "remember", "记一件事")。第三个参数是一句中文说明，只用于列表展示。
还可以写
ops.tool("example", "这把工具是干什么的") 登记工具分组上那句括注。一般不写 —— 工具注册时基板会从工具说明里自动补一句。
出错的后果
声明过程抛异常 → 只让这个技能的 op 退化成「工具名一个 op」，技能照常可用，判定与权限表都还认工具名那一层。

@Override
public void declare(Libs libs) {
    libs.register(new LibSpec("example_note", "例子便签", "例子")
            .ts()                                  // 常用组合：ts INTEGER NOT NULL DEFAULT 0
            .col("content", "TEXT", "''")           // 列名 / 类型 / 默认值
            .col("owner_qq", "TEXT", "''")
            .fts("content")                         // 参与全文检索的列
            .alias("例子便签", "便签")                // 中文别名：模型可以用中文指这个库
            .idx("idx_example_note_ts", "ts"));     // 索引名显式给，不靠推导
}

@Override
public void declareOps(sair.v4.auth.OpList ops) {
    ops.add("example", "add", "记一条便签");
    ops.add("example", "list", "看自己的便签");
    ops.add("example", "drop", "删自己的一条便签");

id 与 ts 两列由基板统一补，声明里不用重复写（ts() 是写法糖）。列名与表名是 SQL 白名单的唯一来源，写 SQL 之前基板按声明校验列名。表名、列名、索引名一旦上线就不能改 —— 改结构等于迁移。

Host：能力面逐个讲

下面这些是 Host 接口上的全部方法。它是一个只读能力面：能调度基板已有的资源，改不动权限判定、也改不动基板骨架。

身份与会话给你什么什么时候用它
caller()真实发送者：谁在说话、在哪个会话、好感度多少做策略判断（熟人优先、群规、称呼）。不要拿它判权限 —— 判定主体是下面那个 subject()。
subject()这一次调用的判定主体要自己问权限面「他能用这个吗」时。h.need() 内部用的就是它。

toolName()注册后的英文工具名要在反馈里告诉模型「你用哪个名字调我」，或者拼 op 名时。
skillDir()技能自己的文件夹读同目录的 prompt.md 与素材文件 —— 文案与阈值外挂在这里，改完即时生效。
session()会话键：console / qq:123 / group:456按会话存东西（冷却、上次说的、投递目标）。

selfIsGroupAdmin(groupId)机器人在这个群是不是管理员 / 群主审核、禁言这类动作出手前先看有没有执法权。NapCat 没连上时返回 false。

need(op)放行返回 null，否则是可直接回给模型的拒绝原文每个动作分支开头一次，见下一段。

store()六库的通用读写口存自己的数据：put / get / list / search / update / delete / count，以及 kv / kvSet 这种小键值。跨调用要记的东西都放这里（不要放 static）。

模型与平台给你什么什么时候用它
ai()模型客户端技能里要直接问一次模型（分类、摘要、改写）时。
napcat()NapCat 动作接口，带权限闸门要发 QQ 动作（拒绝申请、改名片、禁言）时。动作名就是 op（napcat.set_group_ban 这种），没授权会被拒。NapCat 没连上时每个动作返回 error=Napcat 没有连接。

inboundImageUrl(file)最近入站消息里某个图片值对应的直连 URL跨机部署时本地路径读不到，这条 URL 是取到图的线索。查不到返回空串。

说话、派活、控制台给你什么什么时候用它

host.need("工具.动作") 这道自查门

为什么每个动作分支都要先判一次

工具入口只判一次「这把工具交不交给他」：整把工具放行，或者它任一动作放行，这把工具就会出现在他的调用清单里。所以一个只被放行了 example.list 的人，照样点得动 example 这把工具。

这时候如果 drop 分支不自己判一次，他就把 drop 干成了 —— 权限表里那一行的「没给」等于白写。每个分支开头各判自己的 op，「允许他记一笔」与「允许他删别人的」才是两件事。

判完怎么用

放行返回 null，否则返回一句能直接回给模型的拒绝原文：[权限阻断] 「example.drop」没有授权给你（未列到 = 未授权）。命中黑名单时那句是 [权限阻断] 「example.drop」在技能管控表的黑名单里；这一行写出来了却给了空数组，那句是 [权限阻断] 「example.drop」没有授权给你（列出来了，但谁都没给）。权限面没装配时是 [权限阻断] 权限面没有装配（auth == null），按拒绝处理：example.drop。这几句的尾部都会说明是哪一层挡的。

把这句话原样返回给模型，别改写、别删掉 [权限阻断] 这个标记：识别面认它，主循环的连续失败闸门也靠它把这一次算成失败。

    String deny = h == null ? null : h.need("example.drop");   // 这个动作自己的 op

    // …过了这道门，才轮到"这是不是你的数据"那类归属判断…
}

判定用的主体是 h.subject()：工具调用时是触发者（「她能替这个人碰什么」看这个人），钩子与扩展点调用时是她自己（自动禁言、自动审批这类是她的自动策略，按触发者判会被陌生人的默认状态当场拒掉）。主人与她本人恒全权，不受表影响。所以判权限不要拿 h.caller() 去问别的地方，统一走 need。

异常、超时、返回值：把话说清楚

抛异常基板会接住算一次失败
会发生什么
基板接住并回给模型一段 [<工具名>] ok=0 <技能名> 执行异常: <原因>，后面跟最多 5 行调用栈。这一次会被算作失败，连续失败闸门靠它计数。
怎么写更好
把可预期的坏情况翻译成一句人能读的说明返回（「没找到这个城市」「返回里没有观测数据」），真正的意外才让异常抛上去。
超时工具调用没有基板层超时扩展点有
工具这条路
技能的 call(...) 本身没有基板给的超时。要发网络请求就自己给超时（真技能里 Http.get(url, headers, 12000) 这样，12 秒），别让一次调用挂住不放。
钩子与扩展点那条路
每次调用都有独立超时，配置键 extTimeoutMs，出厂 200 毫秒。超时只丢这一次调用，打一行 [ext] timeout name=… ms=…，其余照常。所以钩子里不要做慢活：等网络、扫全库这类事放别的路上去做。
返回值String / JSON / null模型看到的样子
约定
成功就把要说的话拼好返回；没有话可说返回 null（模型看到的是空结果，那不等于失败）。返回对象或列表时基板转成 JSON 文本，模型看到的就是那段 JSON。
长度
工具结果会被配置里的上限截断（toolResultMax）。所以别把整库倒给模型：先筛、先截、先归纳，再返回十几行。
static 状态重载后一定丢别用它记状态
为什么
热重载会把技能重新编译一遍，并换上一个新的类加载器：旧类连同它的 static 字段一起作废，新实例看到的是全新的初值。所以「把计数、缓存、锁表放在 static 里」在重载之后就是空的 —— 计数归零、缓存没了、锁也换了一把。
那放哪
跨调用要记住的东西放 h.store()（六库或 kv）里；只在一次调用内部用的临时量放局部变量。同一次装载里 static 是共享的，多条会话会同时读写它，要用就得自己加锁 —— 这一条也是「能不用就不用」的理由。
跟实例的关系
默认每次都新建实例（airun.state: per_call），实例字段活不过一次调用；写成 shared 时整个进程复用一个实例，同一个技能同一时刻只跑一个调用，但实例字段在重载后同样是新的。

javadata\skills\例子\Example.java（完整：三个动作、自己的表、归属硬判）
import com.google.gson.JsonObject;

import java.util.List;

import sair.v4.kit.J;
import sair.v4.kit.Out;
import sair.v4.kit.Str;
import sair.v4.skill.Args;
import sair.v4.skill.Host;
import sair.v4.skill.Skill;
import sair.v4.store.LibSpec;
import sair.v4.store.Libs;
import sair.v4.store.Store;

/** 完整技能：三个动作各判自己的 op，数据落自己的表，非主人的越权访问一律拒。 */
public class Example implements Skill {

    private static final String TOOL = "example";
    private static final String NAME = "例子";
    private static final String LIB = "example_note";

    /** 装载期：声明自己那张表（谁写入、谁声明）。 */
    @Override
    public void declare(Libs libs) {
        libs.register(new LibSpec(LIB, "例子便签", NAME)
                .ts()
                .col("content", "TEXT", "''")
                .col("owner_qq", "TEXT", "''")
                .fts("content")
                .alias("例子便签", "便签")
                .idx("idx_example_note_ts", "ts"));
    }

    /** 装载期：三个动作各声明一个 op。 */
    @Override
    public void declareOps(sair.v4.auth.OpList ops) {
        ops.add(TOOL, "add", "记一条便签");
        ops.add(TOOL, "list", "看自己的便签");
        ops.add(TOOL, "drop", "删自己的一条便签");
    }

    @Override
    public Object call(Args a, Host h) {
        if (h == null || h.store() == null) return "[" + TOOL + "] ok=0 数据层不可用";
        Store s = h.store();
        String op = Str.trim(a.str("op")).toLowerCase();
        if (op.isEmpty()) op = "list";
        try {
            if ("add".equals(op)) return add(a, h, s);
            if ("list".equals(op)) return list(a, h, s);
            if ("drop".equals(op)) return drop(a, h, s);
            return "[" + TOOL + "] ok=0 未知 op：" + op;
        } catch (Throwable t) {
            log(h, "op=" + op + " 出错：" + t);
            return "[" + TOOL + "] ok=0 执行异常：" + t;      // 兜住意外，别把栈丢给模型
        }
    }

    // ---------------------------------------------------------------- 三个动作

    private static String add(Args a, Host h, Store s) {
        String deny = h.need(TOOL + ".add");                 // ① 这个动作的 op
        if (deny != null) return deny;
        String content = Str.trim(a.str("content"));         // ② 参数校验
        if (content.isEmpty()) return a.missing("content");
        if (content.length() > 200) return "[" + TOOL + "] 内容太长（上限 200 字）";
        JsonObject row = new JsonObject();                   // ③ 归属写进自己的行里
        row.addProperty("content", content);
        row.addProperty("owner_qq", String.valueOf(qq(h)));
        long id = s.put(LIB, row);
        return id > 0L ? "已记下 #" + id : "[" + TOOL + "] ok=0 写入失败";
    }

    private static String list(Args a, Host h, Store s) {
        String deny = h.need(TOOL + ".list");
        if (deny != null) return deny;
        int limit = a.i("limit", 10);
        if (limit <= 0) limit = 10;
        JsonObject f = new JsonObject();
        f.addProperty("owner_qq", String.valueOf(qq(h)));    // 只看自己的
        List<JsonObject> rows = s.list(LIB, f, limit, "ts DESC");
        if (rows == null || rows.isEmpty()) return "还没有便签。";
        StringBuilder sb = new StringBuilder();
        for (JsonObject r : rows) {
            sb.append('#').append(J.l(r, "id", 0L)).append(' ')
              .append(Str.cut(Str.oneLine(J.s(r, "content", "")), 80)).append('\n');
        }
        return sb.toString().trim();
    }

    private static String drop(Args a, Host h, Store s) {
        String deny = h.need(TOOL + ".drop");
        if (deny != null) return deny;
        long id = a.l("id", 0L);
        if (id <= 0L) return a.missing("id");
        JsonObject row = s.get(LIB, id);
        if (row == null) return "[" + TOOL + "] 没有这条便签";
        // 归属硬判：op 过了之后，"这条是不是你的"仍然要自己判一遍。
        // 主人与她本人不受限；别人只能删自己的行。
        if (!master(h) && !String.valueOf(qq(h)).equals(J.s(row, "owner_qq", ""))) {
            return "[权限阻断] 只能删自己的便签。";
        }
        return s.delete(LIB, id) ? "已删掉 #" + id : "[" + TOOL + "] ok=0 删除失败";
    }

    // ---------------------------------------------------------------- 小工具

    private static long qq(Host h) {
        try { return h == null || h.caller() == null ? 0L : h.caller().qq(); }
        catch (Throwable t) { return 0L; }
    }

    private static boolean master(Host h) {
        try { return h != null && h.caller() != null && h.caller().master(); }
        catch (Throwable t) { return false; }
    }

    private static void log(Host h, String msg) {
        try {
            Out o = h == null ? null : h.out();
            if (o != null) o.dim("[" + NAME + "] " + msg);
        } catch (Throwable ignored) { }
    }
}

这道骨架里有两层判定，别混在一起：h.need(op) 回答的是「这个动作给不给他用」，判据是权限表；owner_qq 那次比较回答的是「这一条数据是不是他的」，判据是代码里的归属。第二层跟权限表无关，权限表全放行也照样要有 —— 否则「允许所有人多看一条」会变成「允许所有人看别人的」。

归属判据本身也要念一遍：MASTER 与 SYSTEM 不受限，受限的只有普通用户；拿不到身份时按受限处理。

04 / 权限

权限表 perms.jsonc 怎么填

技能目录里那份权限文件回答的是：这个技能提供的工具，谁能用；如果这个技能还带着自己的数据，它也能在这里声明它管的数据谁能改、谁能读。文件放在技能目录里、与 md 同级，文件名固定 perms.jsonc。规则写在三个域里 —— 技能（op）、数据（数据类别）、文件（路径）；每个域各有自己的层，没列到的按该域的默认值走（技能不能、数据能读不能改、文件不能碰）。一份都没有的技能，默认只有主人与她本人用得到。

文件放哪、谁写它、不写会怎样

放哪

技能目录里，与同名 md 同级：<数据根>\skills\<技能名>\perms.jsonc。技能目录里没有这份文件 = 这个技能的全部 op 对普通用户一律不授权（未列到 = 未授权）。

它只写这个技能自己提供的工具的 op，以及属于这个技能的数据键；路径块不写在这里（详见下面「越界条目会被忽略」）。

谁写它

三条写入路径：主人在控制台敲 ai/perm 那一族命令 —— 这一族里才有 db / file 两条改数据与路径的命令；她手上那个内置的 perm 工具管的是授权、封禁、撤回、重排这几支，没有 db / file。两条入口都只对主人开放。或者主人直接手改文件再敲一次 ai/perm reload。它们都会当场落盘，落盘用「先写临时文件再改名」的原子替换。

技能自己写不了它：技能写入的那条路（新增、覆盖、草稿、草稿提升）碰到 perms.jsonc 会跳过或挡回，回的原话是「拒绝写入 perms.jsonc：… —— 权限文件（谁能用这个技能）只能由主人用控制台 ai/perm 写，技能不能给自己开口子」。所以技能拿不到给自己授权的能力。

完整格式（照这个写就不会错）

json<数据根>\skills\<技能名>\perms.jsonc

层长什么样基板怎么读
version"version": 6读到上一版的 5 会按旧语义读并给一行提示；比这一版新也给一行提示，认得的字段照读。
_readme一段给人看的用法说明不参与任何判定。
域Skill / DB / File拼错的域名整块忽略并点名。技能文件里写 File 块属于越界，整块不生效。
层Run / Read / Ban技能只有 Run / Ban；数据与文件三个都有。在某一域里写它没有的那一层、或者把层名拼错，整层忽略并点名。
规则键["memory.remember", "memory.recall"]: ["ALLUSER"]一律带中括号；只有一个键时也带（["weather"] 与裸写 "weather" 等价）。一次可以并列几个键。
身份数组["ALLUSER", "user:123"]数组里有这个身份就算命中。字面空数组是一条“谁都不给”的决定，不再回落到更宽的键：数据与路径两域照写（写成空表的读侧就是不能读）；技能域里它与「没列到」等效，重排后不再保留。

注释怎么写：以 // 开头的整行是注释，写在被注释内容的前一行，读之前整行丢掉。行尾注释没有 —— 一行 JSON 后面直接跟 // 说明，会让这一份文件整份读不出来（当成空表 = 一切未授权，并打一行提示）。所以释义单独占一行：域上面一行 // ── 技能：谁能用哪些 op，层上面一行 // ── 谁能用（没列到 = 未授权），键上面一行 // 记一件事，键本身是纯名字。

整份文件不是合法 JSON 时，这一份按空处理（它管的 op 一律未授权），并打一行提示；认不出的身份写法会被原样留着并点名，不会被「猜着用」。

三域各自的默认值与优先级

域改 / 用读
SkillBan > Run > 没列到 = 不能用不设（读归数据与路径两域）
DBBan > Run > 没列到 = 不能改Ban > Read > 没列到 = 能读（全表唯一默认放开的一处）
FileBan > Run > 没列到 = 不能改Ban > Read > 没列到 = 不能读

三句要记住的规矩

  • Ban 压过允许：同一把键上，只要这个身份命中任何一条 Ban 就拒 —— 数据与路径两域连 Read 也一起压。
  • 更具体的键优先：pref.donation 比 pref 具体；路径按最长优先，子目录里的禁止压过父目录里的允许。
  • 同一个键写多处 = 取并集：要收窄只能用 Ban，这是设计如此。

判定时更具体的键没给这个身份任何决定，才落到更宽的键。两种宽键别混：技能这一域写工具名的那条只覆盖装载时这把工具已经注册的动作（新加的动作不会被旧授权顺手放行）；数据与文件两域的宽键按它自己的身份表命中，连表里没一一列出的那层子键也照它判。只有“完全没有决定、而且没有被任何已知宽键覆盖”的键才会得到一个专门的拒绝说明（就是装载时点过名的那些认不出的键）。

数据那一层还要看“这一行归谁”

DB 的 Run 命中之后还要过行归属：那一行的归属主体必须等于调用者（自己那一份 / 自己所在的群）。要让某个人改别人的行，必须把他本人指名写进 Run；靠 ALLUSER 命中的只动得了自己那一份。没有归属的共享行，也只有被指名的身份动得了。

想给某个技能的数据开口子，就在那个技能目录里的文件里写它自己的数据键；不属它的数据键（以及全部 kv.* 抽屉）归基板，要开得写到基板那份里。

身份写法逐个

写法是谁怎么用
ALLUSER除主人与她之外的所有人放开给所有人时写它。它是 user: 与 group: 的底稿（写它就等于给每个人、每个群都放行）。
user:<QQ号>某一个具体的人给单个用户开口子时最常用。
group:<群号>某一个群里的所有人把同一件事放开给整个群时用。
裸 QQ 号同 user:<QQ号>纯数字就是人，不用加前缀。数字要是纯数字，带别的字符会被拒收。
MASTER / SYSTEM—不用写：两人恒全权。手写进文件里的那几行整行忽略 —— 不报错、不生效，也不占「已经声明过」的位置；在控制台写命令里这两个身份会被直接回绝。

表里还认几个中文写法（全体 / 所有人 / 全部 等于 ALLUSER，群号… / 群… 等于 group:，用户… 等于 user:，另外 qq: 前缀也认）。控制台敲命令时按最规范的那三种写最省心：ALLUSER / user:123456 / group:123456。

工具名与动作名怎么写

工具级与动作级

["weather"]: ["ALLUSER"] —— 整把工具一条，覆盖它已经注册的全部动作。

["memory.remember"]: ["ALLUSER"] —— 只放开这一个动作；同一把工具别的动作照旧没给。几个动作可以并在一行里写：["memory.remember", "memory.recall"]: ["ALLUSER"]。

上一版那种「工具里再嵌一层动作」的写法（"memory": { "remember": [...] }）与动作键写 * 的老写法照旧能读，但装载时会提示建议敲一次 ai/perm gen 重排 —— 重排只产出中括号键那种形态，不写 *，也不给技能域留空身份表的占位行。

名字用哪一个

用注册名：md 里 tool: 声明的名字如果合规范就是它本身；中文名会被自动英文化（tp_ 前缀那一套），那么表里的键、ai/perm run 敲的 op、代码里 h.need(...) 传的名字都要用注册名。

拿不准的时候看 ai/tools：它列出的就是当前工具面里真实存在的名字。

越界条目会被忽略

技能文件里只写它自己的：读到技能目录里的 perms.jsonc 时，基板会拿 op 的工具名去问「这个工具归哪个技能」，也会拿数据键去问「这类数据归哪个技能」。三条越界都不生效，并在启动时点名一行：

  • 写了别人的、或者基板内置工具的 op —— 形如 [acl] 越界忽略：技能「天气查询」的 perms.jsonc 里写了不属于它的 op「send.group」（属技能「消息发送」）—— 这一条不生效；认不出归属时那一行写的是「不是任何技能提供的工具」。
  • 写了不属它的数据键 —— 同一句话的另一种形态，末尾点明这类数据归基板还是属别的技能，那一条不生效。
  • 写了 File 块 —— 整块不生效（路径属于部署，不属于某个技能），原句形如「…里写了 File 块（路径属于部署，只许写在基板那份 perms-core.jsonc 里）—— 整块不生效」。

所以要给某个能力开口子，就写到那个能力归属的那份文件里：技能自己的工具与自己的数据写到自己的 perms.jsonc，基板内置工具、其余数据键与全部路径写到数据根下的 perms-core.jsonc。用 ai/perm run 敲的时候不用操心这件事 —— 它按归属自己选文件，回执里会写明写到了哪一份。

还有一条更早的门槛：装载权限表要问「哪把工具归哪个技能」，而这份归属来自工具面。工具面还没装配好时读到技能权限文件，那一轮技能文件一律不读，并打一行「拿不到工具归属（注册表还没装配）—— 技能权限文件本次一律不读：ALLUSER 按未授权处理」。这种情况在装配完成后再敲一次 ai/perm reload 就好。

05 / 钩子与扩展点

六件套：接口挂上去，能力就长出来

技能能被基板调用的方式一共六种：Skill（模型点得动的工具）、Hooked（事件钩子）、以及四个扩展点 —— ContextProvider（每轮往上下文里加一段）、OutboundStage（发送前改正文）、LifecycleHook（回合开始 / 发送 / 结束）、TriggerVoter（这条消息要不要自动回）。Skill 与 Hooked 在第 03 节讲过，这一节把剩下五个按同一套问题逐个讲清楚。

先记住两条识别规则：钩子要在 md 里写 hooks:，而且实现要写在入口类上（只在入口类上找）。四个扩展点不用在 md 里写任何东西 —— 类上写了 implements ContextProvider 就是声明，基板扫这个技能的每个顶层类，谁的接口对得上就注册谁。一个类同时实现两个接口也行，那样它一个人挂两条。

Hooked：事件钩子

问题答案
它是干什么的把基板的事件交给你。基板只提供事件，怎么处理完全在技能里 —— 钩子在，这个能力就在；技能删掉，能力彻底消失。
要写哪几个方法void on(String hook, JsonObject payload, Host h)。一个方法接全部四个钩子，用第一个参数分辨是哪一个。
在 md 里怎么声明hooks: [on_timer] 或 hooks: on_message, on_timer。取值只有四个：on_timer / on_message / on_request / on_notice。
什么时候轮到你on_timer：基板唯一心跳，周期是配置键 tickMs（出厂 20 秒）。on_message：一条入站 QQ 消息。on_request：一条好友申请 / 群邀请。on_notice：一条通知事件（戳一戳、撤回、进群、禁言这类）。
payload 长什么样on_timer 是基板自己造的：{"tick":n,"ts":毫秒}。on_message / on_request / on_notice 就是那条事件的 JSON 原文，常用键有 post_type、message_type、sub_type、user_id、group_id、message_id、raw_message、sender；申请类还带 request_type、flag、comment；通知类还带 notice_type、target_id、operator_id。取键用 J.s(payload, "raw_message", "") 这种带默认值的取法。
判定主体是谁钩子里的动作按她自己（SYSTEM）算 —— 自动禁言、自动审批这类是她的自动策略，按触发者判会被陌生人的默认状态当场拒掉。所以钩子里 h.need(op) 恒放行。而 h.caller() 仍然是真实发送者（谁在说话），做策略判断用那个。
能改什么消息类钩子里可以接管这一轮：把 payload 的 _handled 置 true，表示「这条我接管了」，基板就不再自己回一轮；也可以投一票「回 / 不回」（_reply 为 true / false，理由是 _reply_reason）。通知类那条路上不读这两个键，置了没有效果：那条路只记账，不能发言、也起不了一轮。

钩子是同步跑完的：基板要等它返回才知道 _handled 是什么，所以钩子会跑在一个有界执行池里（池满时就地在调用线程跑）。结论是：钩子里别做慢活，等网络、扫全库这类事交出去做（派子 Agent，或者记一笔等下一次心跳处理）。

javadata\skills\例子\Example.java（入口类上的钩子）
import com.google.gson.JsonObject;

import sair.v4.kit.J;
import sair.v4.skill.Host;
import sair.v4.skill.Hooked;
import sair.v4.skill.Skill;

/** 入口类同时是工具入口与钩子入口：implements 两个接口即可。 */
public class Example implements Skill, Hooked {

    @Override
    public Object call(sair.v4.skill.Args a, Host h) {
        return null;                                  // 这个技能不给工具也行，md 里不写 tool: 就不会注册
    }

    @Override
    public void on(String hook, JsonObject payload, Host h) {
        try {
            if ("on_message".equals(hook)) {
                String text = J.s(payload, "raw_message", "");
                if (text.contains("羊")) {            // 命中就接管这一条
                    payload.addProperty("_handled", true);
                    if (h != null) h.spawn("有人提到羊了，接一句", null, true, null, null, true);
                }
            } else if ("on_timer".equals(hook)) {
                long tick = J.l(payload, "tick", 0L);
                if (h != null) h.out().dim("[例子] 心跳 " + tick);
            }
        } catch (Throwable ignored) {
            // 钩子里抛出去只会被记一行；自己吞掉更清楚
        }
    }
}

还有一条兼容路径：入口类里直接写一个与钩子同名的方法（on_message(JsonObject payload, Host h)、on_message(JsonObject)，甚至无参的）也能被调到。新技能走 Hooked 这一个方法更整齐。

OutboundStage：发送前改正文

问题答案
它是干什么的管「发出去的东西」：洗 AI 味、给提问者加 @、追加一张表情包、剥离不该外泄的标记。位置在分段之后、发送之前，所以看到的是已经分好的一条条消息。
要写哪几个方法int order()（抽象方法，要写）；String transform(Outbound m)、List<String> extra(Outbound m)、boolean veto(Outbound m)、List<String> finish(List<String> parts, Outbound m) 四个都有默认实现，按需要覆盖。
什么时候轮到你每一次要往外发话（群、私聊、定时任务的落点）都会走一遍。逐条口会对每一条各调用一次。
每个口的分工veto：一票否决，true = 这一条不发（整条丢，不做「改一点点再发」）。transform：改正文，返回 null = 不改（这是「没意见」的默认），返回空串或全空白 = 这一条会被丢掉。extra：追加独立消息（再追一张表情包这种），只在还有话要发的时候收一次，追加的消息不再过 stage（否则插件之间会互相追加、无限繁殖）。finish：整批收尾，拿到最终的整条消息表（已含追加的消息），返回新表就整表替换，返回 null = 不改；返回空表 = 这一批一条都不发。
顺序按 order 小的在前，同序按插件名。一轮下来是：逐条 veto → 逐条 transform → extra → finish。同一批里前一个 stage 的 transform 结果就是后一个 stage 看到的正文。
能改什么、不能改什么能改正文、能决定这一条发不发、能追加消息。不能改「发给谁」—— 落点是调度与会话的事。
在 md 里怎么声明不用声明，implements OutboundStage 就够了。

Outbound 上有什么

text() 这一条当前的正文；session() 会话键；group() / target() 群还是私聊、目标号；caller() 调用者（定时任务的落点上是 null，要容忍）；echo() 这一条会不会也打进控制台；host() 当前 stage 所属技能的只读能力面（可能为 null）。

位置三件：index() 本次发送里第几条（0 起）、total() 一共几条、first() / last() 是不是首条 / 末条。逐条阶段的下标是分段结果里的位置；extra 与 finish 阶段指向本批最后一条，total 是含追加消息的最终条数。

为什么要有 finish

有些事天然是「整条回复」级别的，逐条口做不对。典型是把 @ 提问者加在首条：首条要是真正会发出去的那一条，而在逐条口里看不到后面哪条会被别的 stage 丢掉或者洗空 —— 结果 @ 挂到了一条根本没发的消息上。「末条补个标点」「整批去重」也只有在这里才准。

注意：finish 返回空表就是这个能力（等于整批不发），用的时候心里有数；表里的元素按原样发，不再过 stage。

ContextProvider：每轮往上下文里加一段

问题答案
它是干什么的每一轮装配上下文时往里面加一段（情绪状态、用户画像、群成员映射这类）。内容与文案全在你的插件里，基板只负责三件事：顺序、段位、预算。基板自己不产生任何一条上下文内容。
要写哪几个方法boolean stable()（抽象方法，要写）、int order()（抽象方法，要写）、String build(BuildContext b)（抽象方法，要写）；int maxChars()（默认 1200）、boolean appliesTo(BuildContext b)（默认 true，返回 false 就是这一段这一轮不出现，不算异常）。
什么时候轮到你每一次装配上下文（主回合、后台收尾回合）都会问一遍。
稳定段与前缀缓存stable() 返回 true 的块排在同一条系统提示词之后、事实块之前，它们一起构成可复用的前缀。模型服务的前缀缓存按前缀一字不差地命中，所以稳定块的内容要「同输入一字不差」—— 时间戳、随机数、当前消息正文都别放进去。返回 false 的块排在事实块之后（每轮都可能变），顺序仍按 order 与插件名确定。
两级预算裁剪先按 maxChars() 逐段截断（丢尾巴，保留开头），再按全局预算 ctxBudgetChars（出厂 6000）从 order 最大的开始整段丢，并打一行 [ext] budget over …。所以 order 大的段先被丢：重要的段要给小号，同时把 maxChars() 收紧到够用就好。
能改什么、不能改什么只能通过返回值产出这一段。拿到的 BuildContext 是只读口：不暴露回合对象，也不暴露消息数组 —— 拿到消息数组就能往这一轮里塞任意内容，等于绕过装配骨架的顺序与预算。要写东西就写自己的库 / 自己的 kv。
在 md 里怎么声明不用声明，implements ContextProvider 就够了。

BuildContext 上有什么

caller() 调用者（出站路径上可能为 null）；session() 会话键；text() 本轮正文（装配期是用户输入，出站期是将要发出去的正文）；host() 只读能力面（可能为 null）；group() / groupId() / qq() / master() / console() 从调用者派生出来的一组判断；state(key, def) 按 key 读本轮事实；subagent() / agentLabel() 这一轮是不是子 Agent。

本轮事实的既有键：media（媒体段）、chat_window（本会话最近若干条聊天记录）、subagent（子 Agent 标签）。出站路径上没有回合，state(...) 一律返回你给的默认值 —— 落点信息在 Outbound 上。

产出怎么落地

返回值会被去掉首尾空白，然后按「一段一条系统消息」装配。返回空串或 null 就是这一段不出现（正常，不是错）。appliesTo 说不适用时同样不出现，而且不会被记成异常。

每轮都会调用，所以不要在这里打日志刷屏 —— 诊断行基板自己会打（一行 [ext] provider=… chars=… ms=…）。

LifecycleHook：回合的开始、发送、结束

问题答案
它是干什么的「记账与清理」：写对话历史、记调用量、清临时态、私聊「正在输入」。不是改内容 —— 改内容那条路是 OutboundStage，所以这里拿到的是只读的 BuildContext，根本没有可改的正文。
要写哪几个方法int order()（抽象方法，要写）；void onTurnStart(BuildContext b)、void onSend(BuildContext b)、void onTurnEnd(BuildContext b, String reply, String error) 三个都有默认空实现，按需要覆盖。
时序onTurnStart（装配完、还没跑）→ 模型跑（可能多次工具闭环）→ onSend（真要说话了）→ 落点发出 → onTurnEnd。
每个口的时机onTurnStart 在装配完之后、跑之前触发（那时「本轮输入、本轮事实」才齐）；onSend 是这一轮马上要对外说一句话了，含失败兜底那一句 —— 只挂在成功分支上会让「失败了也要做点什么」的插件永远收不到通知；onTurnEnd 在正文发出（或失败）之后触发，失败时 reply 是空串、error 非空，两种结果都会通知一次。
管哪些回合只管主回合，以及后台收尾回合（那一类会触发 onTurnStart 与 onTurnEnd，但不派 onSend）。子 Agent 不触发生命周期钩子。
在 md 里怎么声明不用声明，implements LifecycleHook 就够了。

reply 是这一轮产出的正文 —— 那一刻还没剥标记、也可能还没发出去。要读「最终发出去的样子」，那条路在 OutboundStage。

TriggerVoter：这条消息要不要自动回

问题答案
它是干什么的给「这条消息要不要自动回」投一票。它不是一个新机制，而是把原来只有技能能投的那一票升级成插件公共：三态、有顺序、有缘由。
要写哪几个方法int order()；Vote vote(Ev ev, Caller c)；String reason()（默认 plugin，只在投「不回」时有意义，会写进跳过那一行的 reason= 里）。
三态ANSWER = 回（即使没被 @、也不是主人，例如触发词命中）；DECLINE = 不回（直接结束，省掉一整轮模型调用）；ABSTAIN = 不管（交给下一个）。返回 null 等同于 ABSTAIN。
谁先投谁生效按 order 小的在前、同序按插件名依次问，第一个非 ABSTAIN 的票生效，后面的不再问。不是多数决 —— 改成投票制会让「谁回谁不回」依赖插件数量；顺序确定，结果才确定。全都不管时，基板按原有的地址规则走。
超时与异常投票抛异常或超时 = 这一票作废（当 ABSTAIN），打一行 [ext] timeout|error …。别阻塞：宁可不管，也别在这里等网络 —— 超时上限就是 extTimeoutMs，超了这一条消息就按「没人表态」处理。
在 md 里怎么声明不用声明，implements TriggerVoter 就够了。

五个接口共用的护栏（每条都能省一次排错）

单次调用超时extTimeoutMs，出厂 200 毫秒丢一次，不丢一轮
怎么表现
超时只让那一次调用作废（provider 的那一段不出现、stage 的那一条保持原样、钩子这一票作废），打一行 [ext] timeout，其余照常。
怎么用
钩子与扩展点里只做轻活。真要等网络，交给子 Agent 或者下一次心跳。
异常只影响它自己那一次一行 [ext] error name=… err=…基板照常回话
意味着什么
插件崩了不会拖垮这一轮对话，也不会影响别的插件。但插件不该依赖这层护栏：自己 catch 住、少做点事，比让基板替你收尾更清楚。
实例是长活的装载时建一次调用被串行化
意味着什么
扩展点实例在装载期创建一次，之后每轮复用；同一个插件实例的扩展点调用被串行化（同一时刻只跑一个），所以插件作者不用自己处理并发。代价：同一个插件的两轮不能同时用它 —— 这比「读-改-写互相覆盖」划算得多。
视图不要存起来BuildContext / Outbound只在这一次有效
为什么
这两个对象是「这一轮 / 这一条」的视图，出站路径上连回合都没有。要留状态就留在自己的库或 kv 里，别抓住对象不放。
host() 可能为 null绑不上就是没有容忍它
什么时候会 null
宿主没绑定到这个插件（例如外部直接注册的合成实现、插件已经被卸载）。写法是「拿不到就少做点事」，绝不抛异常；Outbound.host() 同理。
热重载别用 static换类加载器状态会丢
后果
重载会把技能重新编译并换一个新的类加载器，static 字段随旧类一起作废 —— 计数、缓存、时间戳全归零。跨轮要记住的东西放 store 或 kv 里。
总开关配置键 extEnabled零开销
怎么表现
没有任何扩展点（或总开关关掉）时，装配、出站、投票、生命周期这四个接线点一行代码都不多走 —— 行为与没有这一层时一字不差。让插件全部失效的开关在这里，不在插件里。

一个类同时挂两个接口

下面这个类既是入口（Skill）又挂 Hooked 与 ContextProvider：钩子从事件累积状态，provider 每轮把状态读出来拼一行。两个身份写在同一个类里，是因为这个技能的事就是一件（Hooked 只认入口类），扩展点身份顺路带上。

import com.google.gson.JsonObject;

import sair.v4.ext.BuildContext;
import sair.v4.ext.ContextProvider;
import sair.v4.kit.J;
import sair.v4.kit.Str;
import sair.v4.skill.Args;
import sair.v4.skill.Host;
import sair.v4.skill.Hooked;
import sair.v4.skill.Skill;
import sair.v4.store.Store;

/** 入口 + 钩子 + 上下文提供者：一个类挂三条身份。 */
public class Example implements Skill, Hooked, ContextProvider {

    // ---------------- 工具入口（md 里没写 tool: 时不会注册，写个空实现即可）

    @Override
    public Object call(Args a, Host h) {
        return null;
    }

    // ---------------- 钩子：每来一条消息就把次数记进 kv

    @Override
    public void on(String hook, JsonObject payload, Host h) {
        if (!"on_message".equals(hook) || h == null) return;
        try {
            Store s = h.store();
            if (s == null) return;
            long qq = h.caller() == null ? 0L : h.caller().qq();
            if (qq <= 0L) return;
            String key = "example:count:" + qq;
            int n = 0;
            try { n = Integer.parseInt(Str.trim(s.kv(key, "0"))); } catch (Throwable ignored) { }
            s.kvSet(key, String.valueOf(n + 1));
        } catch (Throwable ignored) {
            // 钩子不向外抛
        }
    }

    // ---------------- 上下文：每轮把那行状态加进去（易变段）

    @Override
    public boolean stable() {
        return false;                 // 每轮都可能变，别放进稳定前缀
    }

    @Override
    public int order() {
        return 80;                    // 数字越大越靠后；预算不够时也越先被整段丢掉
    }

    @Override
    public int maxChars() {
        return 200;                   // 这一段自己能有多长；基板还会按全局预算再裁一次
    }

    @Override
    public boolean appliesTo(BuildContext b) {
        return b != null && b.qq() > 0L;      // 没有具体的人就没有这一段
    }

    @Override
    public String build(BuildContext b) {
        try {
            if (b == null || b.host() == null) return "";
            Store s = b.host().store();
            if (s == null) return "";
            int n = 0;
            try { n = Integer.parseInt(Str.trim(s.kv("example:count:" + b.qq(), "0"))); } catch (Throwable ignored) { }
            return n > 0 ? "这个人今天已经说了 " + n + " 次话。" : "";
        } catch (Throwable t) {
            return "";                // 插件绝不拖垮一轮对话
        }
    }
}

一个完整的技能：从零到能用

先把「完整」这个词摊开：一个技能可以只有两份文件，也可以有十来样东西。这一节先给一张清单（每项少了的后果都写清楚），再给一次端到端的走法 —— 建目录、写 md、写 java、写权限表、放进去、重载、看清单、授权、试用，每一步都写「做完应该看到什么」。

清单：一个「完整」技能具备哪些东西

东西作用少了它会怎样
一个文件夹，名字就是技能名技能的身份与容器没有它就没有技能 —— 技能的最小单位就是这个文件夹
同名 md（<技能名>.md）身份校验 + front matter 声明 + 给人看的说明书状态 ERROR，错误是「缺少同名文档」；这个技能在工具面里不存在
md 里的 tool:决定这把工具叫什么、有没有这把工具不写 = 不注册工具：模型看不到也调不动，只剩钩子与扩展点
md 里的 airun（说明 / 返回值 / 参数表 / 示例）模型挑工具与填参数的全部依据工具仍在，但说明为空、参数表为空，模型只能瞎猜

declareOps 里把每个动作声明一条权限表与 ai/perm 的骨架：动作能分开管不声明也能跑，但管控表里只有工具名那一层，动作分不开

prompt.md文案、阈值、词表放这里，改完即时生效不写就要把文案硬写在 java 里，改一句话也要重载；声明了 inject: 时它还是注进上下文的那一段

库声明 declare(Libs)（用到业务表时）表结构由用到它的技能声明，基板按声明建表补列没声明就直接用那张表 → 报「没有这个库」，工具每次调用都失败
hooks: + Hooked（要接事件时）在事件上干活：定时维护、消息累积、申请审批基板只提供事件，不接就永远不会被叫醒（例如没有任何钩子的技能不会自己跑）
四个扩展点接口（要插进管线时）每轮加一段上下文 / 发送前改正文 / 回合时序 / 触发投票不挂就没有这些时机，能力只能靠模型主动调用工具来触发
归属硬判（多用户数据时）回答「这一条是不是他的」权限表全放行时会变成「允许所有人看别人的」，这是比权限本身更严重的一类问题

07 / 排错

常见坑与怎么查

技能这一层的毛病，绝大多数落在四件事上：文件没被读到（名字不对、没重载）、声明没被解析（键写错、缩进不对）、权限没给（默认拒绝）、代码里的判定漏了一层（只判了入口，没判动作）。下面按「先看什么」的顺序排，照着走一般都能定位。

现象先看什么原因与怎么处理
技能装了，但普通人用不了，主人自己能用 技能目录里有没有 perms.jsonc 默认拒绝：没有这份文件 = 这个技能的全部 op 对普通用户一律不授权，这是出厂口径，不是坏掉。ai/perm list <工具名> 会显示一条都没有；敲一次 ai/perm run <op> <身份> 就会顺手把它建起来。
权限文件里明明写了，还是不生效 启动日志里那一行 [acl] 越界忽略：… 越界条目整条不生效：技能文件只认它自己提供的工具与它自己的数据键，写了别人的、或者基板内置工具的 op，那一条被忽略并点名一行；写了 File 块则整块不生效。要开就写到那个键归属的那份文件里（技能自己的 → 技能目录，基板工具、其余数据键与全部路径 → perms-core.jsonc）。用 ai/perm run 写不会踩这一条：它自己按归属选文件。
技能里想给自己开权限，被挡住 skill_write 的返回 技能写入的那些动作（新增 / 覆盖 / 草稿 / 草稿提升）碰到 perms.jsonc 会跳过或挡回，回一句「权限文件（谁能用这个技能）只能由主人用控制台 ai/perm 写，技能不能给自己开口子」。这是刻意的：技能拿不到给自己授权的口子。
昨天还好好的，重载之后计数器 / 缓存清零了 代码里有没有 static 字段存状态 热重载会换一个新的类加载器，旧类连同它的 static 字段一起作废，新实例看到的是全新的初值 —— 计数归零、缓存没了、锁也换了一把。跨调用要记住的东西放 store（六库或 kv）里。
md 里写了 tool:，但工具面里没有这把工具 ai/skill list 那一行的状态，以及启动日志里的工具名对照行 四种常见原因：① 名字不合规范被自动英文化了 —— 表里与代码里的 op 名要用注册名，对照看启动日志那一行或技能列表里的 tool_declared / tool_note；② 名字撞上基板内置工具（保留名）→ 状态 ERROR；③ 目录里没有 .java 或编译没过 → 没有代码可跑，不注册工具；④ tool: 那一行被写进了正文（在结束的 --- 之后），没被当成声明。
声明改了没反应 是否敲过 ai/skill reload 基板不监听目录：加载时机只有启动扫一次与显式重载。md、java、prompt.md 改完都要重载；prompt.md 被技能运行时现读的那种用法，改完下一轮就生效，但重新解析 md 与重新编译还是要重载。技能正在编译时 reload 会被拒一次（「技能正在编译中，本次 reload 未执行」），编完再敲。
md 里的键像没写一样 第一处非空行是不是 ---，缩进用的是不是空格 第一处非空行不是 --- → 整个文件按「没有 front matter」处理，所有键都不生效。缩进里混了 Tab → 那一行被当成第零层，子块整段失效（认缩进只数空格）。缩进比上一层更深、又不在子块位置的行会被直接跳过，键就像没写过。
参数表里某个参数不见了 那个参数块的缩进 参数名下面的字段要比参数名多缩进一层，兄弟字段对齐。多缩一层会被当成「意外缩进」跳过；行内数组里有逗号的值会被切开（用引号也救不了，切分在剥引号之前）。
钩子一次都没被叫到 ai/skill list 里的 hooks=，以及启动日志里「声明了钩子…但入口类里没有匹配的方法」那一行 三种原因：① md 的 hooks: 里钩子名拼错（列表里就会显示成你写的那个名字）；② 值写成了别的形状（应写数组或逗号分隔的一行）；③ 实现没写在入口类上 —— 钩子只在入口类上找，写在别的类里等于没写。另外通知类事件那条路只记账，不能发言、也起不了一轮。
扩展点没生效 启动日志里的 [ext] 行 接口名写错（implements 了一个不存在的名字编译就过不去，所以更常见的是写在一个基板不扫的位置：内部类、匿名类会被跳过）；实例化抛异常时日志会写「不能用作扩展点（已跳过）」，插件其余部分照常。总开关 extEnabled 关掉时全部扩展点都不走。
注入的上下文偶尔整段不见 日志里的 [ext] budget over … 与 [ext] timeout 两级预算：先按 maxChars() 逐段截断，再按 ctxBudgetChars 从 order 最大的开始整段丢。所以 order 大的段先被丢、内容长的段先被截。做法：重要的段给小的 order、把 maxChars() 收到够用就好。超时（extTimeoutMs，出厂 200 毫秒）也只丢这一段，慢活不要放在 build 里。
出站改正文没起作用 是不是 transform 返回了 null transform 返回 null 就是「不改」（这是默认口径）；要改就把新正文返回回去。返回空串或全空白会让这一条被丢掉。另外 extra 只在还有话要发的时候收一次，追加的消息不再过 stage。
她说「发不出去」，但权限是给了的 那句拒绝原文，以及 ai/perm 里这个 op 的条目 技能门与动作门：入口判一次（整把工具或任一动作放行，工具才可见），工具内部每个动作再判一次自己的 op。只放行了一个动作时，别的动作仍会被拒 —— 这是设计，不是 bug。要开就到 Skill 的 Run 里补那个动作，或者整把工具一条放行。另外两道闸门管的是别的东西：数据那一层管「这类数据能不能改 / 能不能读、这一行是不是他的」，路径那一层管「这个路径能不能碰」。
工具里报「没有这个库」 有没有 declare(Libs)，以及表名是否被别人占了 业务表由用到它的技能声明。没声明就直接用 → 每次调用都报没有这个库；表名或别名被别的技能占了 → 声明失败、技能整条不可用，日志里会写「表名或别名已被别的库占用」。
代码改动之后「那一项能力」整块不见了，别的技能没事 启动日志里的 [skills] … ERROR 行 .java 编译失败或找不到入口类时，这个技能状态是 ERROR：它的工具、钩子、扩展点全部不装，但装配继续、别的技能照常。所以「刚才还能用的一项功能突然没了」先去看那一行，改完重载即可。
失败没被当成失败（她像没看见一样继续） 返回文本的第一行形状 失败文本照 [<工具名>] ok=0 … 这个形状写，主循环才认得出它是失败；权限阻断那句话里的 [权限阻断] 标记也一样，别改写、别删。识别面是包含这个标记，所以前面多几个字不影响。
定时任务说出的话打到控制台去了 派子 Agent 时有没有带上目标会话 心跳钩子没有自己的会话，落点是控制台。要让它说回原来的群 / 私聊，用带 session 的那个重载，把建任务时记下的会话键交下来；认不出来时宿主回落控制台，任务不会丢。另外「到点才跑」的派发要用带主体的那一个重载，否则普通人建的任务会继承钩子主体（等于借定时任务升权）。
host() 是 null 时插件崩了 插件里有没有做 null 判断 BuildContext.host() 与 Outbound.host() 都可能为 null（宿主没绑定到这个插件、外部直接注册的合成实现、插件已被卸载）。写法是「拿不到就少做点事」，绝不抛异常；同理 caller() 在定时任务的出站路径上也可能是 null。

日志里该看哪几行

看哪里能看到什么
ai/status装配到哪一步、有没有失败。技能扫描是装配中的一步，装配整体失败时先看这里。
ai/skill list每个技能的名字、状态、工具名、钩子清单。状态只有三种：LOADED（装好了）、MD_ONLY（只有 md，没有可执行代码）、ERROR（装不上，错误原话在 ai/skill validate 里）。
ai/skill validate技能库体检：ERROR 的逐条原因（编译失败、名字不一致、工具名重名、库声明失败），以及「声明了 tool 但没有 .java 代码」这种不一致。全部没问题时回一句「技能库无问题（共 N 个）」。
ai/skill read <技能名>这个技能的 JSON 概览（名字、说明、工具、注入槽、钩子、状态、文件数、目录、错误）与 md 正文。
ai/tools当前工具面：每把工具的名字、对当前调用者的管控状态（Run / Ban / -）、来源（基板还是哪个技能）、一句话说明。
ai/perm / ai/perm list <op>合并后的权限表、来源汇总、每个 op 谁能用、归属文件在哪。授权与封禁的回执也在这里看。
启动日志 [skills]扫描了哪个目录、每个技能的装载结果（[skills] <名字> → LOADED 工具=… 钩子=…）、工具名自动英文化的那一行对照、缺 md / 编译失败 / 名字不一致的原话、扫完的总数（技能几个、工具几个、钩子几个）。
启动日志 [acl]权限文件读到了几份、哪一份版本对不上、越界条目那一行（[acl] 越界忽略：…）、认不出的条目、拿不到工具归属时的说明。
启动日志 [ext]挂了几个扩展点、每个插件挂了哪些、每次调用的一行耗时与字符数、超时（[ext] timeout）、异常（[ext] error）、预算丢段（[ext] budget over）、不能用作扩展点的类。
启动日志 [store]库声明与建表的结果：库名冲突、建表失败、「库声明后建表失败（不影响插件装载）」。看到这个说明技能装上了，但那张表没建出来。

排错的顺序（省时间的那种）：① ai/skill list 看状态 —— ERROR 就 ai/skill validate 读原话，这一步能解决一大半；② 状态正常但工具不在 ai/tools 里，就看 md 的 tool: 与注册名；③ 工具在但普通人用不了，看 ai/perm list <op>；④ 都能用但行为不对，看 [ext] 与技能自己打的诊断行。
