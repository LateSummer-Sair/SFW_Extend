01 / KEYS

键面总览

基板只认一份扁平 JSON（数据根下的 config.json）。已知键共 94 个，分 11 个面；想改哪儿、去哪儿查，看这一张就够。

键面是什么

Conf.knownKeys()（src\sair\v4\Conf.java）返回的是全部已知配置键，顺序就是书写顺序。它满足两条硬口径：

  • 含"只靠默认值生效"的键：config.json 里没写、靠出厂默认跑起来的键（例如 agentMaxRounds、subagentMaxRounds、historyLimit）也在表里，值就是"出厂默认照原样生效"的那个值；缺省值一律从 Conf 自己的 getter 来，表里不重抄一份常数（Conf.java）。
  • 只登记"有人读"的键：每个键都有活着的消费者，getter 就是那个消费者的同一个口（Conf.java）。

knownKeys() 给的是已生效的值；fileKeys()（Conf.java）给的是文件里的值，多一位 pending() 标记。控制台 config 与模型侧 config 工具读的都是文件面。

键从哪来：文件里登记的与出厂默认的一共 94 个；差出来的那一批，是"出厂不写盘、靠默认值生效"的。

一个键的值可能从哪来

三种来源：文件里写了（首次启动由 ensureDefaults() 写下一份带默认值的 config.json，Conf.java）；文件里没写（回落到 getter 默认值 —— 33 个键属于这一类，config 清单照样列出并显示生效值）；运行期内部写入（Conf.set(String,Object)，Conf.java，例如文件外链 token 留空时自动生成并写回，Conf.java）。

不在这 94 个里的名字：写进去没人读。控制台 config set 会明确回一句"不在已知键表里（没有消费者读它）"（src\sair\v4\term\Cmd.java），模型侧 config op=get 同口径（src\sair\v4\Builtins.java）。相关的命令与参数见 控制台命令 · 配置。

02 / MODEL

模型与对话

接口凭据、模型名、采样参数、历史注入预算，以及回复怎么拆成几条发出去。21 个键。

接口与模型

apiKey默认 ""密文落盘
含义
模型接口的密钥。它是 SECRET_KEYS 之一（src\sair\v4\Conf.java），盘上是 AES-GCM 密文，内存里始终是明文（Conf.java）。
怎么调
控制台 config set apiKey sk-xxxx，或模型侧 config op=set；也可以直接手改 config.json。写进去的明文会在下次保存时自动变密文（Conf.java）。
调错的后果
空值 = 接口没配好，ai/status 的 api_key_set 为 false（src\sair\v4\Boot.java、Boot.java），对话一路失败。值写错 = 每次调用返回失败。换了机器 / JVM / 用户名 / 启动目录会让密文解不开：启动时只打一行告警并把原值原样保留、绝不二次加密（Conf.java、Conf.java）。
apiUrl默认 "https://api.deepseek.com"出厂写盘
含义
接口基址。末尾多余的斜杠会被去掉（Conf.java）。
怎么调
config set apiUrl https://…。指向自建或代理网关时改这里。
调错的后果
写错 = 模型调用全失败。指向不受控的地址等于把 apiKey 发到那台机器上。
model默认 "auto"出厂写盘
含义
主模型名。auto（或空）= 用 autoModel，不做任何路由判断（Conf.java）。
怎么调
config set model deepseek-pro。装配时会打一行"模型 X → Y（auto=默认模型，无路由）"（Boot.java）。
调错的后果
写成不存在的模型名 = 每次调用失败；写成 auto 之外的空串也会回到 autoModel。
autoModel默认 "deepseek-flash"出厂写盘
含义
model=auto 时实际调用的模型。
怎么调
config set autoModel deepseek-flash。
调错的后果
它被清空而 model 又是 auto，解析出的模型名就是空 —— 调用直接失败。
visionModel默认 "deepseek-flash"出厂不写盘
含义
具备视觉能力的那一档模型。主模型看不了图时，用它兜底（Conf.java）。
怎么调
config set visionModel deepseek-flash。事实块里的 models.vision 就是它（src\sair\v4\ctx\CtxBuild.java）。
调错的后果
填一个不支持视觉的模型，识图子 Agent 会一路失败。它与复数的 visionModels 是两个键（见 其余键）。

采样参数

temperature默认 1.3出厂写盘
含义
采样温度，随每次请求发出（src\sair\v4\ai\DeepSeek.java）。
怎么调
config set temperature 1.0（支持小数，控制台按 -?\d+\.\d+ 解析成数值，Cmd.java）。
调错的后果
过高 = 回复发散、跑题；过低 = 回复变得刻板。超出接口允许范围会被接口侧拒绝。
topP默认 -1.0 = 不发送出厂不写盘
含义
核采样阈值。负值表示"这一项不放进请求体"（DeepSeek.java）。
怎么调
config set topP 0.9；要关掉就写回 -1。
调错的后果
写 0 或其他极小值会让输出退化到几乎固定；它与 temperature 同时生效，两个都调偏很难归因。
maxTokens默认 0 = 不发送出厂不写盘
含义
单次回复的 token 上限，0 表示不带这一项（DeepSeek.java）。
怎么调
config set maxTokens 2048。
调错的后果
设得太小，长回复会被硬截断；设得过大等于没限制。

历史注入

historyLimit默认 60 条出厂写盘
含义
每回合带进上下文的历史条数（Conf.java）。
怎么调
config set historyLimit 40。消费者在 ctx.ChatWindow.java 与 ctx.CtxBuild.java，都是每次现读。
调错的后果
调大 = token 与耗时同步上涨，可能撞上下文预算；调小 = 明显健忘（这一条历史只吃"最近 N 条"，不会自动补摘要）。
historyMaxChars默认 24000出厂写盘
含义
历史正文的字符预算；超预算时从最旧的整条丢，留最新的（Conf.java）。
怎么调
config set historyMaxChars 12000。<=0 = 不限。消费者 ChatWindow.java、CtxBuild.java。
调错的后果
调得太小会成片丢历史（丢的是整条，不是截一半）；<=0 时条数上限还在，不会无限膨胀。

身份与地址

selfId默认 0出厂写盘
含义
基板自己那个 QQ 号。用来判"这条是不是她发的"（src\sair\v4\QqGateway.java、QqGateway.java），以及窗口里的"我"是谁（ChatWindow.java）。
怎么调
config set selfId 2671623601。填成与 NapCat 登录的号一致就好。
调错的后果
留 0 或写错号，她自己发的消息可能被当成别人发的 —— 轻则历史里出现"自己跟自己对话"，重则成回路。落群聊行时这一列就是它（QqGateway.java）。
masterQQ默认 0出厂写盘
含义
主人 QQ。权限判定里 SYSTEM 主体、优先道判定、控制台身份都取它（Boot.java、Cmd.java、QqGateway.java）。
怎么调
config set masterQQ 1284688456（纯数字会被解析成长整型，Cmd.java）。
调错的后果
写错号 = 主人不再是 SYSTEM，很多"只有主人能改"的动作会被拒；反过来，把这个号写成别人，等于把主人权限给了那个人。权限模型本身见 基板能力 · 权限。
masterQQs默认 "" （额外主人列表）出厂不写盘
含义
除 masterQQ 之外还要当主人看的号码，逗号分隔。装配时并进主人集合（QqGateway.java）。
怎么调
config set masterQQs 111111,222222。
调错的后果
格式写错只会少解析出一条，不会报错 —— 这是"悄悄多给/少给主人身份"的地方，顺手到 权限 那节对一遍会更稳妥。

回合与回复分段

chatTimeoutMs默认 180000出厂写盘
含义
控制台 chat 等回合结束的上限（毫秒），超时就先回话，绝不把控制台永久卡住（Conf.java）。
怎么调
config set chatTimeoutMs 300000。消费者 term.Cmd.java。
调错的后果
调小 = 长回合会看到"超时"回话（回合本身仍在后面跑完）；调很大 = 控制台在慢回合里长时间没有回显。
turnMergeMaxChars默认 4000出厂写盘
含义
同一会话里后到的消息并进"还在排队的那一条"时，合并正文的字符上限；装不下就不再合并（Conf.java）。
怎么调
config set turnMergeMaxChars 2000。入站路径读它（QqGateway.java）。
调错的后果
调大 = 单回合正文可能很长，token 与耗时上升；调小 = 连发消息不再合并，变成多回合。合并不腰斩正文，装不下就另起一条。
replySplit默认 true出厂写盘
含义
回复分段总开关（src\sair\v4\term\Segmenter.java）。
怎么调
config set replySplit false。相关四个键的机制都在 term.Segmenter（Segmenter.java）。
调错的后果
关掉 = 一条发完（极端超长仍会硬切），长回复在群里会很突兀。
replyMaxChars默认 1000出厂写盘
含义
单条回复的字符上限；超过就按"空行段落"拆开（Segmenter.java、Segmenter.java）。
怎么调
config set replyMaxChars 600。
调错的后果
调太大 = 单条又长又闷；调太小 = 段落被拆得零碎。拆点优先落在空行，不会从句子中间切。
replyGroupMaxChars默认 180出厂写盘
含义
群聊里再压短一档的单条上限（Segmenter.java、Segmenter.java）。只对群生效。
怎么调
config set replyGroupMaxChars 300。
调错的后果
设得比 replyMaxChars 还大，群里的拆条行为会与私聊趋同 —— 不是错误，但"群聊短句优先"的手感就没了。
replySplitDelayMs默认 800出厂写盘
含义
拆出来的几条之间基础停顿（毫秒），Segmenter.java。
怎么调
config set replySplitDelayMs 1200。
调错的后果
写 0 = 连着发出去，一眼就是机器；写太大 = 整段回复拖得很慢。它只影响已拆开的多条之间的间隔。
replySplitJitterMs默认 1200出厂写盘
含义
在基础停顿上再加的随机抖动上限（毫秒），Segmenter.java、Segmenter.java。
怎么调
config set replySplitJitterMs 2000。
调错的后果
写 0 = 间隔完全固定，节奏变得可预测；调很大 = 相邻两条之间可能出现明显空档。
msgDedupWindowSec默认 600出厂写盘
含义
入站去重窗口（秒）：同一条 message_id 在窗口内只处理一次（src\sair\v4\qq\Seen.java）。
怎么调
config set msgDedupWindowSec 60。消费者 QqGateway.java。
调错的后果
写 0 = 关闭判重，重连重放会让同一条消息被回答多次；调得很大 = 短期内重复投递的同一条会被吞掉（这是期望行为，但排障时容易误判成"没收到消息"）。
03 / NAPCAT

NapCat 与文件外链

反向 WS 监听与"把本地文件变成只读 URL"的中转。10 个键，其中 2 个是密文落盘。

共同的生效口径：napcat on|off、napcat relay on|off 这两条控制台命令也只改文件；真正重绑端口要 ai/restart（Conf.java、Cmd.java、Cmd.java）。

NapCat 反向 WS

napcatEnabled默认 false出厂写盘
含义
是否在装配期起反向 WS 监听（Boot.java）。
怎么调
config set napcatEnabled true，或控制台 napcat on（等价，只写文件）。首次部署时把它改成 true 就可以用了。
调错的后果
false = QQ 侧完全不通，本地控制台与已有数据照常可用；改了文件但没 ai/start／ai/restart，跑着的基板仍按旧值走。
napcatPort默认 8082出厂写盘
含义
反向 WS 监听端口，Link.java、Link.java。
怎么调
config set napcatPort 8083，然后 ai/restart。NapCat 侧的反向地址要同步改（见 部署 · NapCat）。
调错的后果
端口被占用 = 监听失败，控制台打一行原因，本地交互不受影响（Boot.java）。两边端口不一致 = NapCat 连不上，控制台会回「Napcat 没有连接」那类明确失败。
napcatHost默认 "127.0.0.1"出厂不写盘
含义
反向 WS 绑定的地址，Conf.java、Link.java。
怎么调
config set napcatHost 0.0.0.0（NapCat 在别的机器上时才需要）。
调错的后果
默认只听本机回环；绑到别的地址而没设 token，基板拒绝启动这个服务（Conf.java）。绑 0.0.0.0 就把它暴露给了同网段。
napcatToken默认 ""密文落盘
含义
NapCat 接入 token，握手时校验（Link.java、Link.java）。V4 把它一并加密落盘（Conf.java）。
怎么调
config set napcatToken <token>，与 NapCat 侧配置保持一致。
调错的后果
空值只在"NapCat 同机"时是安全的；跨机且不带 token，等于同网段谁都能冒充 WS 客户端。两边不一致 = 握手被拒，控制台看到连接进不来。
napcatTimeoutMs默认 10000出厂不写盘
含义
调用 NapCat 动作的等待上限（毫秒），Link.java。
怎么调
config set napcatTimeoutMs 20000。
调错的后果
太小 = 慢动作（发文件、拉群成员）被当成失败；太大 = 对方不回时这一路要等到超时。

文件外链中转

先看清楚它是什么：它把"要发给 NapCat 的本地文件"变成一个只读 URL，由 NapCat 自己来取。它只认 GET／HEAD、URL 带随机 token（不对就 404），但它能读出本机任意文件（不做目录白名单）。只在确实跨机时开（Conf.java）。

relayEnabled默认 false出厂写盘
含义
是否起文件外链中转，src\sair\v4\qq\Relay.java。
怎么调
config set relayEnabled true，或控制台 napcat relay on；开之前先填 relayPublicHost（Cmd.java 会当场提醒）。
调错的后果
默认关；开着等于给"能访问该端口的人"一条读本机任意文件的只读通道。不用时顺手关掉再 ai/restart。
relayPort默认 2671出厂写盘
含义
中转监听端口，Relay.java；写 0 = 让系统挑一个空闲端口（实际端口在状态里给出，Conf.java）。
怎么调
config set relayPort 2671。
调错的后果
端口被占用 = 中转没起来，控制台会说明"本地文件仍按 file:/// 交给同机 NapCat"（Boot.java）。
relayPublicHost默认 ""出厂不写盘
含义
对外主机名／地址，NapCat 那台机器用它来取文件（Conf.java、Relay.java）。
怎么调
config set relayPublicHost 192.168.1.254。留空 = 用本机探测到的地址。
调错的后果
跨机时留空不可靠；填公网地址会把这条只读通道放到公网上（Relay.java 会让基板自己提醒一次）。
relayToken默认 ""密文落盘
含义
URL 里的随机 token 前缀。留空时基板在启动时生成并写回这份配置（Conf.java、Conf.java），所以它不是手填才有意义。
怎么调
一般不用手填；要轮换就 config set relayToken <新值> 再 ai/restart。
调错的后果
手改错或与运行中的实例不一致，取文件会 404；日志里 token 只留前 4 位。盘上是密文，换运行环境后解不开只影响自省面显示，基板保留原值不覆盖。
relayTtlMinutes默认 0 = 不过期出厂写盘
含义
链接有效期（分钟），到点中转自己停（Conf.java、Relay.java）。
怎么调
config set relayTtlMinutes 30。
调错的后果
0 = 一直可读；填一个很小的值，长时间发送任务会在中途失效。
04 / RETENTION

保留期与自维护

这是本项目里唯一会删数据的一组旋钮。三把尺子互相独立，另有自维护间隔与全文索引开关。6 个键。

动手前先读这一条：删掉的行不可再生。所以保留期这里 <=0 的含义一律偏向不删（Conf.java）。改小之前先确认数据能不能再生会更安心。

grouplogKeepDays默认 30出厂写盘
含义
群聊历史表的保留天数（Conf.java、Conf.java）。群消息动辄几十万行，它是体积的主要来源。
怎么调
config set grouplogKeepDays 7；自维护每次心跳读一次（Conf.java）。也可用 store maintain 手动跑一次并临时覆盖（Cmd.java）。
调错的后果
调小 = 超龄群消息被真删；<=0 = 一条不删（盘会一直涨）。删行不会立刻还盘，文件大小要另外做 VACUUM 才缩。
dialogKeepDays默认 180出厂写盘
含义
私聊与控制台对话历史的保留天数（Conf.java、Conf.java）。它比群聊宽松，因为私聊量小、记忆价值高。
怎么调
config set dialogKeepDays 365。
调错的后果
与群聊共用一把尺子就只能二选一（要么撑爆盘、要么丢私聊），所以这里刻意分开。<=0 = 不过期。
keepDays默认 30出厂写盘
含义
"记忆／笔记类"的通用保留天数（老键，向后兼容）。只管记忆表的超龄低重要度行（importance <= 4，src\sair\v4\store\Store.java）与运行台账（停用闹钟、已完成任务）；笔记从不被维护删除（Conf.java、Store.java）。
怎么调
config set keepDays 90。Tick.java 与 Builtins.java 读它。
调错的后果
调小会删掉低重要度的旧记忆；<=0 沿用内置 30（不是"不删"）—— 这是三把尺子里唯一"0 不等于不过期"的一个，容易配错。
maxLowImportance默认 500出厂写盘
含义
维护时"低重要度记忆"最多留几条（Conf.java、Conf.java）。
怎么调
config set maxLowImportance 2000。Tick.java 与 Builtins.java 读它。
调错的后果

调错的后果

含义

调错的后果

08 / EFFECTIVE

改配置与生效

一条口径：改文件 ≠ 生效。改完要 ai/start；已经在跑则 ai/restart。

这条口径覆盖所有键：config set 只改 config.json 这个文件，运行中的基板一个键都不动。原来那套"即时生效 / 改了要重启"的两张尺子已经整条退休，现在只有一条路（Conf.java）。

两个面：文件面与已生效面

面谁在写谁在读代码位置
已生效面（内存）只在装配第一步由 load() 从文件读一次；运行期内部代码可用 set() 改全部业务 getterConf.java、Conf.java、Conf.java
文件面（config.json）控制台 config set、模型侧 config op=set、手改文件config 清单与单键查询、待生效判定Conf.java、Conf.java
  • fileSet(String,Object)（Conf.java）是写文件的唯一入口：读原文件 → 只替换这一个键 → 原样写回；其余键（含解不开的密文）逐字保留（Conf.java）。
  • 文件不存在或为空时会先落一份出厂默认再改它（Conf.java），避免"我改的键被冲掉"的错觉。
  • 控制台 config set 的回执明说"未生效 —— 要 ai/start；已在运行则 ai/restart"（Cmd.java）。
  • config reload 已退休：命令保留，但只回一句"基板不再热读配置"（Cmd.java）。提示词正文有它自己的热重载（Cmd.java）。

怎么看见"改了还没生效"

pendingKeys()（Conf.java）逐个比对文件值与已生效值，不一样的就是待生效。判据只对"文件里真的写了"的键成立 —— 文件里没写的键跑出厂默认，不算待生效（Conf.java）。三处都能看见它：控制台 config 总览列出待生效的键并排给出"已生效的值"（Cmd.java）；控制台状态带 pending=（数量 + 最多 8 个键名，Cmd.java、Cmd.java；还没加载过配置时是 -1，Cmd.java）；模型侧 config op=list 逐个键标「待生效（要 ai/start）」（Builtins.java）。

三个键是密文落盘

键为什么代码位置
apiKey接口凭据Conf.java（清单）、Conf.java（保存时加密）、Conf.java（单键写入时加密）
napcatToken拿到就能冒充接入端
relayToken文件外链的读取凭据
  • 算法：AES/GCM/NoPadding，随机 12 字节 IV，认证标签 128 位，存储为 Base64(IV ‖ 密文 ‖ tag)（src\sair\v4\kit\Crypto.java）。
  • 密钥由六项因子派生：VM 名、架构、用户名、主机名、启动目录、固定尾串；解析不出主机名时整项跳过（Crypto.java、Crypto.java）。
