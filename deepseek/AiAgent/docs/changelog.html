当前版本 · V4.2

这一版是 V4.2，版本号不变：基板的九件事不变，权限机制换成了按归属分散的权限文件（基板侧一份，每个技能写自己目录里那份），判定从「身份 × op」扩成技能 / 数据 / 路径三个域；同时新增 ai/favor，把好感度与权限彻底分开。上一版的能力面照旧 —— 到点的事（待办与闹钟同一张账、可顺延可收尾）、群里 @ 谁与引用哪条由她自己决定、输出的纯文字口径，都保持不变。按时间从新到旧，细节见下方条目。

这一条记录当前线上这一版的内容：能做什么、有哪些限制、哪些还没落地，都照实写。 历史条目按版本号从高到低排在后面，改了什么一目了然。

  1. V4.2（续）

    2026-09-20 · V4.2：权限模型升级为三个域，权限文件按技能归属分散

    版本号不变，仍 V4.2。这一条记的是权限这一次升级：判定从"一个 op 一把尺"扩成三个域，每域各有自己的层，权限文件按归属分散到基板与各技能，控制台补上了数据与路径两种写命令。

    ① 三个域，各自的层与默认值：Skill（谁能用哪个 op）、DB（谁能改、谁能读哪类数据）、File（谁能碰哪些路径）。 Skill 与 File 有 Run / Ban（数据和路径两域另有 Read）。没列到时：技能不能用、数据能读不能改、文件不能碰； 其中"数据能读"是全表唯一默认放开的一处，所以装载时会把"没有显式声明过读"的类别逐个点名列出来。
    · 同一把键上 Ban 压过允许；更具体的键优先（pref.donation 比 pref 具体；路径按最长优先，子目录的禁止压过父目录的允许）；同一个键写多处取并集。
    · 改数据命中之后还要看这一行归谁：靠 ALLUSER 命中的只动得了自己那一份，要让某人改别人的行，必须把他本人指名写进去。
    · 数据键是那份固定的类别表（含一批 kv.* 抽屉）；认不出的键装载时点名，并且一律不生效。

    ② 权限文件按归属分散：基板侧那份在数据根下的 perms-core.jsonc，每个技能写自己目录里的 perms.jsonc。 技能文件里只许写自己的 op 与属于自己的数据键，路径块只许写在基板那份；越界的那一条（或整块）被忽略并在启动日志里点名一行。 写盘时也守同一条口径：给技能写文件时永不产出路径块、数据块只在它确实带着自己的数据规则时才写 —— 写出来的每一份文件都必须能被读回来时不报越界。
    · 规则层写法统一成中括号键：["a", "b"]: ["身份…"]，一个键也带括号；// 开头的整行是注释。
    · 旧格式照读：上一版的嵌套写法与旧的统一表都还能读进来，装载时提示建议重排一次；老文件里没写数据与路径两域时按该域的默认值走，不会因为"没写"而放宽。
    · 落盘按归属重排：任何一次写命令都会把它管到的已有权限文件按这一版的形状排一遍，排出来与盘上逐字节相同就跳过写；回执里的"已写入 X"指的是这条规则归属的那份文件。

    ③ 控制台新增两种写命令：ai/perm db run|read|ban <数据键> <身份…> 与 ai/perm file run|read|ban <路径> <身份…>（目录末尾带斜杠 = 整棵子树，路径含空格整段用双引号）； ai/perm revoke <键> <身份> 现在自动认这个键属于哪一块（op / 数据 / 路径）。ai/perm 的看表多了数据与路径两个域的规则行、那一行"未声明 Read 的类别"、以及一行装载汇总。

    ④ 行为收紧点（如实写）： · 普通身份的通用库写入默认被拒 —— 技能自己那条正门照旧，但走通用写口去改数据不再是"有 op 就能改"，要先过数据那一域、再过行归属； · 行级数据只读自己的 —— 读口补上了作用域收口（本人 / 本群 / 全体），原来"拿到读口就能看任意一行"那条路没有了； · 文件默认不能碰 —— 取路径的写口（本地文件改写、外链地址产出、导出与导入）都先过路径那一域，没列到就是拒，而且拒绝文案不透露允许范围； · 越界的技能文件条目、认不出的数据键、认不出的路径写法，全部点名 + 不生效；方向只会更严，不会更宽。

    ⑤ 不变的部分：版本号仍是 V4.2；基板九件事不变；[权限阻断] 这个前缀一字不改（这一版只在它后面补了"是哪一层挡的"这句说明）；主人与她本人恒全权，不受任何块影响；ai/perm gen 照旧只在已有的权限文件里重排、不新建文件。
  2. 当前版本

    2026-09-19 · V4.2：权限机制换成按归属分散的权限文件；新增 ai/favor

    这一版是什么：基板只做九件事 —— 通用存储、热插拔与动态执行、提示词加载与注入、Agent 架构、上下文装配、权限与好感度、模型客户端、QQ 连接、控制台交互。 业务能力都搬到了 data\skills\ 下的外挂扩展里：放一个目录就多一项能力，删掉就彻底消失，一个扩展都不装，基板也照常运转。

    ① 线上这一版：线上插件是 <框架目录>\plugins\exection\ai.jar（<框架目录> 指 SFW 的安装目录，下同）， 仓根产物是 AiAgentV4.jar，两者是同一份；落位后按文件名得到控制台前缀 ai/。
    ② 源码结构：src\ 下 114 个 .java，分 17 个包（1 个根包 + 16 个子包）。
    ③ 提示词文件：data\prompts\ 下有 identity.md（身份）、subagent.md（子 Agent 公共部分）、 tools-index.md（文案与能力索引）三份，正文由你自己写 —— 冷启动只建 identity.md 与 subagent.md 两个空壳，tools-index.md 要自己放。
    ④ 配置键面：Conf.knownKeys() 一共 94 个键，登记在 src\sair\v4\Conf.java 里， 这 94 个键都登记在键表里，其中 6 个媒体类键目前还没有读取方（见本节 ⑨）；config.json 出厂时写入的是它的一个子集。 本机调试面的四个键早已从配置面整条撤出（不是这一版的改动），读法见配置页 · 键表。
    ⑤ 控制台命令面：以 ai/help 的实现为准 —— 文本在 src\sair\v4\term\Cmd.java， 路由分支共 20 条（其中 acl 与 execs／execq／execfc／orchestrate 已退休、只回一句指路）。按用途分组（ai/ 是这个实例的命令前缀）： 入口 help；对话 chat（别名 say）／stop／reset； 生命周期 start／restart；状态与配置 status／tools／config／tick／alarm； 能力面 prompt／perm／favor／napcat／store； 另有两条命令（外挂库维护、本机调试面开关），名称与用法同样以 ai/help 原文为准。 execs／execq／execfc／orchestrate 属于已经删除的「通道」概念，敲下去只会回一句「直接用 ai/chat」。 生效口径只有一条：start 与 restart 之外，其余命令都只改配置文件，改完要么 start（没在跑）、要么 restart（已经在跑）才生效。 逐条细节见命令页 · 生命周期。
    ⑥ 群聊触发口径：只有 @ 才触发。判据在 src\sair\v4\QqGateway.java 的 shouldAnswer(Ev, Caller)： 私聊一律回，群里唯一的判据是 return ev.atSelf();，口径就是「群里：只认被 @」； 主人在这里也没有豁免。所以只引用她、却没 @ 她的那一条，不会触发任何处理。
    ⑦ 关停口径：ai/exit（框架转发到组件 exit()）只停基板 —— 不改配置、不卸载插件，之后还能再 start。 走卸载这条路时，本机调试面会一并关闭（停两个口 + 关落盘句柄 + 注销控制台捕获），而 JVM 仍然活着； 反过来，ai/start／ai/restart 收的只是基板，观测面照旧（相关说明在 src\sair\v4\V4Activity.java），这一点与 V4 的设计一致。 要真正关停 JVM，用框架自己的 /exit，或者按精确 pid 结束进程。

    ⑧ 当前功能面（下面每一条都是现在就能感受到的行为）：
    · 权限按三个域判：技能（谁能用哪个 op）、数据（谁能改、谁能读哪类数据）、路径（谁能碰哪些路径）；每一域里 Ban 压过允许，更具体的键优先； 没列到时技能不能用、数据能读不能改、文件不能碰（"数据能读"是全表唯一默认放开的一处，装载时会点名列出来）。 原先那套按资源分类的「资源位」不再有 —— 资源对主人与她本人完全可见可改可执行，对其他人是黑盒，要过得过技能、数据、文件三道闸门； 消息里自称「我是主人」不构成任何授权。
    · 权限文件按归属分散：基板侧那份（NapCat 动作，以及 console／exec／prompt／model／perm／store／tools／skill／ctx／config／agent／alarm 这些，外带全部路径）写在数据根 perms-core.jsonc； 每个技能写自己目录里的 perms.jsonc，只写它自己提供的工具与属于自己的数据键；装载时合并成一张判定表，ai/perm 会打出来源汇总。
    · 默认拒绝：技能目录里没有那份文件，它全部 op 对普通用户就不授权（主人与她本人照旧全权）；删掉技能目录，它的权限也一起消失。
    · 越界忽略：技能文件里写了不属于它的 op（或不属它的数据键）整条忽略，写了路径块则整块忽略，都在启动日志里点名（那一行会写出真归属）；skill_write 不能写这个文件名，技能没法给自己开口子。
    · 权限文件人可读：三个域在外、层在内，规则层的键一律写成中括号数组（["a", "b"]: ["身份…"]），// 注释独占一行写在内容的前一行（基板读之前整行丢掉）； ai/perm 打合并视图 + 数据与路径两域的规则行 + 「另有 N 个动作没在表里（= 未授权）」+ 装载汇总；ai/perm gen 只在已有的文件里重排、补注释，不新建文件； ai/perm run|ban|db|file|revoke 写回该键归属的那一份，并在回执里写明是哪个文件。
    · 新增 ai/favor：榜单 / get / set / reset 四支，写命令只有主人能跑；好感度与权限彻底分开 —— 它只是一份数据，不参与任何判定（src\sair\v4\term\Cmd.java、auth\Favor.java）。
    · 配置生命周期只有一条规则：写命令只改文件，ai/start 才「加载并运行」（ai/restart = 停旧基板 → 重读文件 → 重新装配）； ai/status 会把「文件里的值 ≠ 已生效的值」的键列出来，没启动过的实例是正常的 ready=0 reason=not_started。
    · 调度按会话分道：同一会话严格保序、同一时刻只跑一条，不同会话互不阻塞；队列装不下时优先把后到的同会话消息并进还在排队的那一条， 真的装不下才按策略处置并回一句可配置文案（消息不会静默消失）；模型调用有并发闸门（modelConcurrency）。
    · 上下文每回合现查：每触发一个回合就现查本会话最近 chatWindowSize 条聊天记录，逐字照抄、单条不截断 （默认 30，这个键定义在 src\sair\v4\Conf.java，读口在 ctx\ChatWindow.java）。
    · 事实块里带模型自知与原生附图：模型自知那行固定 8 个键、键序固定 （self／self_has_vision／main／main_has_vision／vision／mode／recognizer／recognizer_uses， 装配处在 src\sair\v4\ctx\CtxBuild.java），说明这一轮真正会用哪台模型、它能不能看图； 附图只在第一次请求带图，没挂上的图会如实报出来（不静默）。说明见实现页 · 上下文。
    · 通知类事件一律入库留痕，但零触发：戳一戳／撤回／进退群／禁言／表情回应等都落成一行确定性标签进聊天记录， 只落库、不派发、不调模型、不发消息；它们进模型的唯一通路是聊天窗口 （入库与去向在 src\sair\v4\QqGateway.java；标签只由 qq\NoticeRender.java 一处产出）。
    · 被引用消息按需取回：优先查本地库，没命中才走 NapCat；取回的引文会拼在窗口对应的那一行上，取不到就不写这个键（不写填充词） （取回逻辑在 src\sair\v4\qq\QuoteCache.java）。
    · 她自己的出站消息进她自己的记账：发出去的每一条都落一行自我标记行，窗口里显示成「我」，所以她看得见自己刚说过什么、发过哪张图 （头部文法在 src\sair\v4\qq\SelfEcho.java）。
    · 出站正文过一道结构闸门：命中「工具调用标记」形状的那一条整条丢弃、其余条照发（不删字符后照发，也不连坐）； 正常文本里的尖括号（List<String>、x < 0 > y）不受影响 （判定在 src\sair\v4\qq\ToolMarkup.java，落点在 term\Sinks.java）。
    · 控制台：装配跑在基板自己的守护线程上（敲命令、看界面立刻有响应）；对话正文单独落一页面板，主输出框只留过程日志； 控制台输出有独立捕获缓冲；help／status／tools／config 四条不依赖模型、数据库与 QQ，任何装配异常下都能用。
    · 数据面：群聊／私聊／记忆各有独立保留天数（笔记不自动删除），另有两步空间回收命令（合并索引空洞 → 回收空闲页）； 模型密钥、QQ 接入 token、中转 token 三个敏感项加密落盘，与运行环境绑定（相关实现在 src\sair\v4\Conf.java）。
    · 进出网都要过的门：抓取网页与下载文件时拦截指向内网、本机、云元数据地址的请求，且每一跳跳转都重新校验； 网页与文本按「编码标记 → 响应声明 → 页面内声明 → 逐一试探」的顺序解码；写入前做内容查重。
    · 本地文件外链中转：NapCat 与插件不在同一台机器时，把本地文件变成一个只读链接交给它自己取；只支持读取、链接带随机前缀、可设有效期，默认关闭。

    ⑨ 目前还没有落地的部分：折叠转发的展开还没有落地 —— 窗口里仍然只有一个「折叠转发未展开」标签， 对应的开关键 mediaExpandForward（在 src\sair\v4\Conf.java 的键表里）目前没有任何读取方，改它不会有任何效果。 6 个媒体类配置键只在键表里登记、目前没有代码读它们：mediaRender／mediaRenderMaxChars 与 mediaExpandForward／mediaExpandMaxNodes／mediaExpandMaxDepth／mediaExpandMaxChars（都登记在 Conf.java 的键表里），改它们一样不影响行为； 同一组里的 mediaExpandQuote 与 mediaCacheHours 是有真实读取方的（读口在 qq\QuoteCache.java），这两类和上面那 6 个不是一回事。 识图组件那两格事实照实报：组件不在工具面就答 off / 0，不会编别的值（相关实现在 CtxBuild.java）； 「装了哪个组件、装的哪一份」属于外挂层，不在本文档范围内。

外挂层（技能）不在本文档范围内。

  1. V4.0

    外挂扩展协议化：声明式参数、加载期编译注册、83 条内置工具说明整体迁出

    内置工具说明整体迁出：83 条内置工具说明（52 条 QQ 动作类 + 31 条系统类）不再以代码里的字符串常量存在， 而是全部变成 data\skills\ 下的单文件说明；外挂形态收敛为「单文件 + 一层子目录」，同名三方优先于内置，删文件即移除、改文件即生效。 参数协议化：入参从一个 JSON 字符串／一个 Map 升级为声明式签名 —— 类型（含别名）、是否必填、说明、默认值（没填时由框架补齐）、 枚举取值范围、用法示例、数组元素类型，另加返回值说明、只读上下文投影（调用者身份／会话／好感度等纯数据），以及单次调用超时与实例复用策略。 工具实现继续剥离：20 个内置工具的实现随后也搬出核心代码（核心代码因此瘦了一大圈），改由外挂目录里的源码提供 —— 删掉目录，工具就真的不存在； 安全判定刻意留在核心代码里（执行确认闸门、内网拦截、权限矩阵、QQ 路径规则）：剥出去的是业务逻辑，不是安全判定。 这个版本的外挂层细节不在本文档范围内。
  2. V3.14

    正确性与成本治理：中文检索召回、跨群污染、永久丢失、前缀缓存、上下文扩容

    中文检索召回从≈0修到满召回：分词器原先把整段中文当成一个 token，中文子串检索几乎全部失效（几十万条群聊记录里基本召回不到）； 现在索引全部迁移到三字滑窗分词（启动时后台重建），查询构造统一化并给兜底查询补上转义 —— 原先每次 1.16–1.21 秒、且持有全局库锁、 在 82.98% 的消息上触发的检索，降到了 1–5 毫秒。 跨群串味与并发：对话去重改为「同来源 + 同发送者 + 同角色 + 120 秒内」；去重命中时补写消息号不再按内容全局乱匹配； 群聊提示词不再注入「与该用户的私聊历史」；即时情绪按用户／按群隔离；停止标记改为按请求闭锁；线程池丢任务不再静默； 好感度与每日互动改为原子读改写；工具集序列化缓存改为单一不可变对象（原先并发下会把另一渠道的工具集发给模型）。 永久丢失修复：文件读取的偏移／长度从「先截断再切片」改为「在完整文本上切片」；CQ 码不再无声删除，降级为可读占位符； 回复与记忆的清洗从「通配剥离所有尖括号」改为只剥约定的控制标记；引用图片的地址与校验值改为成对存储；超大帧改为读完丢弃，而不是断开连接。 前缀缓存与上下文扩容：上下文重构成「稳定段 + 易变段」两段式，逐条消息变化的内容全部后移；印象里的精确计数改为粗粒度分档， 这样就不会每条消息都把稳定段的内容改掉、打断前缀缓存。
  3. V3.13

    长折叠 / 嵌套折叠处理：结构化递归展开 + 分段分析 + 折叠图片全识别

    长折叠不再被静默截断：原先两处长度上限会把长折叠的尾巴整段丢掉，现在统一放宽到 20000 字，超长部分改由分段分析处理 （按消息边界切块 → 逐块交给段落 Agent → 再由段落 Agent 合并成一份结论），内容不再静默丢失。 嵌套折叠层层递归：新增结构化解析，保留图片真实地址与嵌套折叠编号；渲染时内嵌折叠就地递归展开， 每一层内嵌折叠单独唤起一个段落 Agent 分析，并把结论内联进上层正文（层级上限 3 层、单条消息段落 Agent 调用预算 10 次）。 折叠消息里的图片修复为可见：原先只渲染成字面量、连地址都没有，模型既看不到图也无法调用识图；现在输出可读地址并按多模态内容提交（单次附加上限 20 张）。 段落结论回传上限从 1200 提到 3000 字符；收藏失败时回传具体原因；消息打标改为按消息号精确写入。
  4. V3.12

    Agent 职责重划分：折叠消息全交段落 Agent + 视觉 Agent 转为兜底 + 模型能力感知

    引入模型能力感知：具备原生视觉的模型，由主／段落 Agent 直接看原图；没有原生视觉的模型，交给视觉 Agent 兜底识图， 无原生视觉时该 Agent 自动启用、有则自动不启用。 折叠消息（不论是否引用）一律交给段落 Agent 分析，结论标注回该条消息并标识「已分析」，下一轮先按消息号精确查、再按内容兜底查， 命中即复用结论、不重复分析。视觉 Agent 的执行模型写死为具备视觉的那一档；主／段落 Agent 的工具集与 Agent 间唤起按视觉能力动态门控。 另支持按引用／按消息号精确打标，私聊会话表补消息号列，Agent 间结果缓存对超长任务跳过以防内存膨胀。
  5. V3.11

    模型迁移 + 原生多模态视觉 + 取消引用改 @ + 移除工具调用上限

    跟进模型服务方 API 变更：模型名迁移到新的 Flash 档（性能／费用／速度全面超越上一档）， 并统一模型解析规则 —— 只有配置写 auto 才走自动路由，写了具体模型名就严格按该名称调用、所有通道一律照用不做替换； 业务代码中残留的 9 处硬编码模型名全部改为走配置读取。 取消独立视觉模型：识图不再「先单独调视觉模型转文字再注入上下文」，改为把图片直接作为多模态内容随用户消息提交（省一次调用与一轮 token）。 清理已废弃的采样参数下发，长度上限对齐官方档位，流式解析增加空行与注释行容错。 取消机器人主动引用回复：引用错乱（甲提问却回复到乙）的根因是引用编号与消息归属不匹配，改为系统自动 @ 提问者，并强化「本次回复对象」标识。 移除 Agent 工具调用次数硬上限（原主循环 60 次、子 Agent 8–12 次），改由 Agent 自身判断任务是否完成，仅在连续失败与显式停止时终止；戳一戳改为系统直接拦截。
  6. V3.10

    存图多智能体协作 + 表情包保留治理 + 提示词 md 化 + 卡片消息识别

    存图机制重构为多 Agent 协作：主 Agent 打包候选 → 段落 Agent 找图 → 视觉 Agent 识图 → 按「单张脸 + 文字不超过 20 字 + 无违规」判断 → 收藏 → 打标。 表情包保留策略重做为被动／主动双通道（保底 15 / 阈值 30 / 上限 60，超时回收），并删掉收集冷却与识图冷却。 提示词 md 化：两段提示词从配置文件独立为 md 文件（md 提供身份设定，代码侧只做后置拼接）。 卡片类消息（群邀请／好友申请等）解析出人可读内容并注入拦截结果，修掉模型看到空消息的问题。 另外还修了回复附带用户原话、工具调用配对与识图缓存串扰、线程池扩容异常等问题。
  7. V3.9

    性能深度治理：热路径提速 + token 去重 + 前缀命中 + 写放大治理

    每条消息的纯文本只提取一次并贯穿复用（原先约 10 次正则剥离）；稳定的外挂扩展索引前置到用户消息首部以命中前缀缓存，动态历史不再破坏前缀稳定； 群管理员／群昵称／群名／个人昵称映射加短 TTL 缓存，并移除原本每条群消息都失效缓存的逻辑，让读缓存真正生效； 偏好与日志上下文加内存缓存、写入即失效，不再每条消息重复查库拼接；工具集序列化与请求体按对象身份缓存； 遥测与轨迹改为异步落库，工具执行与主链路不再同步等数据库写入；语音／识图结果缓存改为有界 LRU，防止长期运行无限增长； 群成员角色／昵称／成员关系写库去重，大幅降低每条群消息的写放大；补上热路径索引，会话裁剪改为每 50 次写入执行一次，消除全表扫描； 短消息（去标点不足 4 字）不再触发检索门控；群回复后总是给被回复的那条打上「已回复」标记，已回答的问题不会被重复回答。
  8. V3.8

    跨机器媒体发送修复 + 记忆通道修复 + 运行时状态
