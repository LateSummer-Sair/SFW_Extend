当前版本 · V4.3

这一版是 V4.3。九件事、权限三域、命令表结构都不变；变的是三件与她"本人"有关的事：身份（同一个人在别的群里叫什么，基板直接给她一格事实；每一轮还多一行"本轮说话人"钉在最近处）、记忆（从冷查变成热查：拿"这句话 + 最近几轮"一起去检索）、出站纪律（协议暗号不只整条拦，贴在句子首尾也剥掉，被长度分段劈成两半的也不再进群）。另外把"给她的东西"按提供 + 引导再收了一遍：对方情绪标签还给她、用词表替她判"正经办事"的那条否决删掉、技能说明书的读法补全。按时间从新到旧，细节见下方条目。这一版之后，2026-10-01 又续了一条 V4.3（续）：事实块多三行纯数据事实（clients: / cmdish: / addressed:）与三个开关，加一道「其他」归属闸，见下方最新条目。

这一条记录当前线上这一版的内容：能做什么、有哪些限制、哪些还没落地，都照实写。 历史条目按版本号从高到低排在后面，改了什么一目了然。

  1. 当前版本 · V4.3（续）

    2026-10-01 · V4.3（续）：事实块多三行（clients: / cmdish: / addressed:）与「其他」归属闸；误投指令改为"先问一句"

    版本号不变，仍 V4.3；九件事、权限三域、命令表结构都不变。这一条记的是"给她的东西"又收了一遍：三行纯数据事实各配一个开关，加上一道把"别家机器人"从"她说的"里分出去的归属闸。按时间从新到旧，一条一句：
    · 三行新事实 + 三个开关（新）：事实块末尾多三行，都由 ctx\CtxBuild.java 的 facts(turn) 产出，每行各有自己的出现条件（条件不成立就整行不出现，绝不写空值）—— clients: 本账号另有机器人服务在发言；窗口里标「其他」的行不是人，也不是你说的（只在这一轮的窗口里确实有外部来源行时才出现；逐字文案冻结在基板里，不猜"可能是谁"）； cmdish: '#'（或 cmdish: '/'，只报形状：这一轮的正文以 # 或 / 开头；不给归属结论、也不影响这一轮要不要回，基板里没有关键词表、也没有忽略名单）； addressed: <值>（这一轮怎么被叫到的，六个封闭枚举：at 群里被 @／private 私聊／master 主人那条没有 QQ 地址的控制台或面板入口／trigger 触发词或插件投票起的那一轮／self 她自己的自主或内部回合／system 定时、闹钟、任务投递；由起这一轮的那个产者在提交时塞进回合，facts 只渲染、一个字都不重推，渲染前还过一次白名单 —— 产者没塞过 ⇒ 这一行整个不出现，绝不写空值、也绝不出现自由文本）。 三个开关 clientsFacts / cmdishFacts / addressedFacts 都在 Conf.knownKeys() 里登记（ai/config 看得见、能 get／set），出厂值都是 true，并且都不进 ensureDefaults() —— 出厂不写进 config.json，靠默认值生效；关掉任意一个只少对应那一行事实，不改变任何一次判定。
    · 「其他」归属闸（修的缺陷）：同一个 QQ 账号下有三个机器人服务在发言（我们 / 云崽 / 舞立方），NapCat 把 message_sent 广播给所有连接 ⇒ 别家发出去的消息在我们这边收到的是与她自己的逐字同形的帧（user_id == selfId）。改之前"台账里查不到就当她说的"写一行 ⇒ 别家机器人的话被记成她说的，窗口显示「我」，还进她的记忆与印象素材。现在只认正向证据才算她的（自带台账行 / 本进程内存环 / 台账点查命中 / 台账已裁过时目标会话近期行里已有这个 id 的自我行）；拿不到 ⇒ 改写外部来源行（不写自我记账头、extra.foreign=true、窗口标「其他」、私聊那侧 dialog.role=foreign）。归属只有二元：「我」 vs 「其他」，标签逐字冻结在 ChatWindow.FOREIGN，不带 QQ 后缀、不带昵称 —— 帧里没有识别"是哪一家"的字段，所以她也永远不会被告知是哪一个别的机器人在说话。三处读侧同判：窗口标注（群里与私聊/控制台两支）先判它、对话历史不收它（CtxBuild.appendHistory 只收 user／assistant）、person 那行六库聚合在 Java 侧剔掉它（store\Person.java 的 mayOwnForeignRows；拼进 SQL 会让覆盖索引回表，实测话痨库单次构建从 <50ms 打到 183ms）。
    · 误投指令改为"先问一句"：data\prompts\identity.md 新增「这个号不止我一个」一节 —— 在叫我（addressed: 有值）、这条像别家指令（cmdish: 只报了形状）、记忆里又没有"这类不是给我的" ⇒ 必须先疑惑地问一句"这条是发给我的吗？群里回我时 @ 我一下，不然我收不到"（措辞她自己定；不许静默、不许先答内容）；他答"不是给我的"就记进记忆，此后这类指令不再重复问、也不再响应，但照样被唤起思考（看见、想过，不接话）。基板一个字都不判 —— 三行只给事实，结论归提示词层。
    · 已知限制（照实记，这一版不修）：群里一条没有 @ 她的普通消息不起回合 —— QqGateway.shouldAnswer 在群里只认 ev.atSelf()（私聊一律算）。所以群友用引用她的消息来接她的问、却没有 @ 她时，这条到不了她那里（引用只是消息段，不构成"被叫到"）；跳过时控制台只留一行 skip reason=not_addressed。私聊不受影响。
    · 当前规模（照实核过）：src\ 下 119 个 .java、配置键 114 个（Conf.knownKeys()；本批新增 clientsFacts / cmdishFacts / addressedFacts 三个，全部默认 true、出厂不写盘），文档仍 12 页。
  2. V4.3

    2026-09-28 · V4.3：身份铁律（跨群同一人认得出、本群不串身份）；记忆从冷查改热查；协议暗号贴边外泄收口

    九件事不变、权限三域不变、命令表结构不变。按时间从新到旧，一条一句：
    · 本轮说话人锚点（新）：每一轮在"本轮这句话"前面最近处固定插一条 system：【本轮说话人】<昵称>(QQ n)——本轮就他在说话；窗口/历史/记忆里别人的行，别算他头上。 号码只取本轮真正的触发者（不从窗口/历史/记忆里认人、不编号、不硬编码任何人）；昵称与窗口里的角色标注词（我/对方）逐字相同时退回 #QQ；收尾回合（没有本轮 user）不插；没有触发者时（钩子/无 caller）那一条如实写「本地控制台(没有 QQ)」、她自己的自主行为写「她自己(自主行为，无触发者)」—— 而真正的控制台回合仍按"主人"带其 QQ（控制台调用者的身份就是主人）。固定成本 ≈ 42 字符 + 昵称 + QQ 位数。
    · 跨群合并 person.aka（新）：事实块的 person 行多一格 aka，把同一个 QQ 在别的群里叫什么直接列出来（形如 群888888:张三，最多 3 条、每条 ≤24 字、顺序确定）；只列别的群、本轮这个群不重复。 数据源是「群成员映射」插件已经加载的那份内存快照 —— 不新开查询、不发 SQL、一次都不调 NapCat；拿不到（插件没装 / 快照是空的 / 是控制台或她自己的自主行为）就一个字符都不加，person 行与没有这一格的旧版本逐字节相同。
    · 群窗口每一行带 QQ：群里聊天记录行的"谁"写成 昵称(QQ n)；这一行的昵称与角色标注词（我/对方）逐字相同、或昵称为空时退回 #QQ，取不到 QQ 如实标 (QQ ?)（绝不编号）。归属信息在窗口里就是逐行可读的。
    · 记忆召回改"热查"：查询串 = 本轮正文 + 最近 8 条本会话对话（整串上限 600 字，超了留最新；本轮正文一个字都不截），门槛判在合并串上（最小查询字数: 2）⇒「还有吗？」这类没有关键词的短追问在活跃会话里也会去查；取回量 条数 12、跨群条数 8、本段 预算 2000（单条上限 仍 300）；并且把本轮窗口里已经有的行按行身份剔掉 —— 同一句不会在两处各注入一遍。这些键都在 data\skills\记忆召回\prompt.md（热读，改完保存下一轮生效）。
    · 协议暗号收口（<silent> 一族）：出站拦截原来只认"整条正文就是暗号"，真机上出现过"句子后面缀着 <silent>"和"句子前面顶着 <silent>"两种漏法 ⇒ 现在贴边（首/尾）也剥掉；只剥带括号的那六种写法（尖/方/圆、半角全角、大小写、半角空格都认），夹在句子中间的一律不动、裸词（silent/不语/不发言）也一律不动 —— 「她发不发言我哪知道呀」这类真实中文不受影响；剥完继续走红线那几道闸，不是"剥完就放行"。 长度分段正好把暗号劈成两半（… <sil + ent>）时，两个半截也不再进群；工具发送路遇到跨段残片整条拒发（fail-closed，宁可少发一句）。
    · "提供 + 引导"落到两处语义面：① 把对方最近的情绪标签交还给她，并在说明书里补上"怎么用"的引导句；② 删掉情绪状态机里那条用词表替她判"正经办事"的否决（词-正经）—— 什么时候该正经属于语义，归她自己判；打扰别人 / 越权 / 泄密那一面仍由基板硬兜底。
    · 说明书与工具面：skill 工具新增 op=read 分段读（offset/limit 窗口 + 尾部续读坐标，防"明明读到一半却当成功"）；store_write 补成三段式说明；技能可以自报它要用的 op（declareOps）；14 个技能说明书的 front matter 与正文对齐；store 工具的自述改成"六库 + 插件库"。
    · 好感度与权限分开：favor 档位变成只读授权（档位表恰好 4 个 op、没有通配；900 档只放这 4 个，320 档一个都不放，主人与她本人逐字节不变）；13 类好感加减各自的区间逐条夹取；情绪扩到 14 态（含新档与"敬重档 ≥700"：不许发火、语气要敬）。
    · 安全与打扰面：控制台的"主人"算他自己的私聊（不许把东西从一个人的私聊转到另一个人的私聊，无对手方时 fail-closed）；硬禁名单绝对化（任何例外表都翻不过来）；红线例外改成成对写法；找人打 这类歧义子串收窄（正常句「找人打听」不再被整条静默）。
    · 观测面：新增只读控制台命令 ai/facts（把每轮的事实块逐字打出来，不截断、不写库、不调模型）；ai/store export 默认落 tmp\（不再落进"放权给群友可读"的 files\）；蒸馏类技能"还没到间隔"那一行从每 20 秒一行收敛到每小时最多一行（判定与模型调用次数一个字没改）。
    · 当前规模（照实核过）：src\ 下 119 个 .java、out\ 里 344 个 .class、随包技能 33 个、工具面 39 个、prompts\ 4 个文本文件、文档 12 页。
    · 版本号口径：产品版本号只有一处真源（V4Activity.VERSION），控制台启动横幅与降级命令表都由它拼出来 —— 从这一版起不再各处硬编码。

  4. V4.2（续）

    2026-09-20 · V4.2：权限模型升级为三个域，权限文件按技能归属分散

    版本号不变，仍 V4.2。这一条记的是权限这一次升级：判定从"一个 op 一把尺"扩成三个域，每域各有自己的层，权限文件按归属分散到基板与各技能，控制台补上了数据与路径两种写命令。

    ① 三个域，各自的层与默认值：Skill（谁能用哪个 op）、DB（谁能改、谁能读哪类数据）、File（谁能碰哪些路径）。 Skill 与 File 有 Run / Ban（数据和路径两域另有 Read）。没列到时：技能不能用、数据能读不能改、文件不能碰； 其中"数据能读"是全表唯一默认放开的一处，所以装载时会把"没有显式声明过读"的类别逐个点名列出来。
    · 同一把键上 Ban 压过允许；更具体的键优先（pref.donation 比 pref 具体；路径按最长优先，子目录的禁止压过父目录的允许）；同一个键写多处取并集。
    · 改数据命中之后还要看这一行归谁：靠 ALLUSER 命中的只动得了自己那一份，要让某人改别人的行，必须把他本人指名写进去。
    · 数据键是那份固定的类别表（含一批 kv.* 抽屉）；认不出的键装载时点名，并且一律不生效。

    ② 权限文件按归属分散：基板侧那份在数据根下的 perms-core.jsonc，每个技能写自己目录里的 perms.jsonc。 技能文件里只许写自己的 op 与属于自己的数据键，路径块只许写在基板那份；越界的那一条（或整块）被忽略并在启动日志里点名一行。 写盘时也守同一条口径：给技能写文件时永不产出路径块、数据块只在它确实带着自己的数据规则时才写 —— 写出来的每一份文件都必须能被读回来时不报越界。
    · 规则层写法统一成中括号键：["a", "b"]: ["身份…"]，一个键也带括号；// 开头的整行是注释。
    · 旧格式照读：上一版的嵌套写法与旧的统一表都还能读进来，装载时提示建议重排一次；老文件里没写数据与路径两域时按该域的默认值走，不会因为"没写"而放宽。
    · 落盘按归属重排：任何一次写命令都会把它管到的已有权限文件按这一版的形状排一遍，排出来与盘上逐字节相同就跳过写；回执里的"已写入 X"指的是这条规则归属的那份文件。

    ③ 控制台新增两种写命令：ai/perm db run|read|ban <数据键> <身份…> 与 ai/perm file run|read|ban <路径> <身份…>（目录末尾带斜杠 = 整棵子树，路径含空格整段用双引号）； ai/perm revoke <键> <身份> 现在自动认这个键属于哪一块（op / 数据 / 路径）。ai/perm 的看表多了数据与路径两个域的规则行、那一行"未声明 Read 的类别"、以及一行装载汇总。

    ④ 行为收紧点（如实写）： · 普通身份的通用库写入默认被拒 —— 技能自己那条正门照旧，但走通用写口去改数据不再是"有 op 就能改"，要先过数据那一域、再过行归属； · 行级数据只读自己的 —— 读口补上了作用域收口（本人 / 本群 / 全体），原来"拿到读口就能看任意一行"那条路没有了； · 文件默认不能碰 —— 取路径的写口（本地文件改写、外链地址产出、导出与导入）都先过路径那一域，没列到就是拒，而且拒绝文案不透露允许范围； · 越界的技能文件条目、认不出的数据键、认不出的路径写法，全部点名 + 不生效；方向只会更严，不会更宽。

    ⑤ 不变的部分：版本号仍是 V4.2；基板九件事不变；[权限阻断] 这个前缀一字不改（这一版只在它后面补了"是哪一层挡的"这句说明）；主人与她本人恒全权，不受任何块影响（这是权限域内的口径；另有一道 op 级罢工闸，它不豁免 SYSTEM）；ai/perm gen 照旧只在已有的权限文件里重排、不新建文件。

    跟进模型服务方 API 变更：模型名迁移到新的 Flash 档（性能／费用／速度全面超越上一档）， 并统一模型解析规则 —— 只有配置写 auto 才走自动路由，写了具体模型名就严格按该名称调用、所有通道一律照用不做替换； 业务代码中残留的 9 处硬编码模型名全部改为走配置读取。 取消独立视觉模型：识图不再「先单独调视觉模型转文字再注入上下文」，改为把图片直接作为多模态内容随用户消息提交（省一次调用与一轮 token）。 清理已废弃的采样参数下发，长度上限对齐官方档位，流式解析增加空行与注释行容错。 取消机器人主动引用回复：引用错乱（甲提问却回复到乙）的根因是引用编号与消息归属不匹配，改为系统自动 @ 提问者，并强化「本次回复对象」标识。 移除 Agent 工具调用次数硬上限（原主循环 60 次、子 Agent 8–12 次），改由 Agent 自身判断任务是否完成，仅在连续失败与显式停止时终止；戳一戳改为系统直接拦截。
  6. V3.10

    存图多智能体协作 + 表情包保留治理 + 提示词 md 化 + 卡片消息识别

    存图机制重构为多 Agent 协作：主 Agent 打包候选 → 段落 Agent 找图 → 视觉 Agent 识图 → 按「单张脸 + 文字不超过 20 字 + 无违规」判断 → 收藏 → 打标。 表情包保留策略重做为被动／主动双通道（保底 15 / 阈值 30 / 上限 60，超时回收），并删掉收集冷却与识图冷却。 提示词 md 化：两段提示词从配置文件独立为 md 文件（md 提供身份设定，代码侧只做后置拼接）。 卡片类消息（群邀请／好友申请等）解析出人可读内容并注入拦截结果，修掉模型看到空消息的问题。 另外还修了回复附带用户原话、工具调用配对与识图缓存串扰、线程池扩容异常等问题。
  7. V3.9

    性能深度治理：热路径提速 + token 去重 + 前缀命中 + 写放大治理

    每条消息的纯文本只提取一次并贯穿复用（原先约 10 次正则剥离）；稳定的外挂扩展索引前置到用户消息首部以命中前缀缓存，动态历史不再破坏前缀稳定； 群管理员／群昵称／群名／个人昵称映射加短 TTL 缓存，并移除原本每条群消息都失效缓存的逻辑，让读缓存真正生效； 偏好与日志上下文加内存缓存、写入即失效，不再每条消息重复查库拼接；工具集序列化与请求体按对象身份缓存； 遥测与轨迹改为异步落库，工具执行与主链路不再同步等数据库写入；语音／识图结果缓存改为有界 LRU，防止长期运行无限增长； 群成员角色／昵称／成员关系写库去重，大幅降低每条群消息的写放大；补上热路径索引，会话裁剪改为每 50 次写入执行一次，消除全表扫描； 短消息（去标点不足 4 字）不再触发检索门控；群回复后总是给被回复的那条打上「已回复」标记，已回答的问题不会被重复回答。
  8. V3.8

    跨机器媒体发送修复 + 记忆通道修复 + 运行时状态

    图片／语音／表情包的本地文件增加内联兜底发送（解决对端在另一操作系统的机器上无法下载 Windows 本地路径的失败）； 发图不再误报成功，失败时返回真实原因；记忆写入在两条链路上统一落库；新增一条用于手动指定文件中转服务对外地址的配置命令； 新增运行时状态查询与工具调用轻量遥测；配置加载后增加校验日志，非法端口／越界参数回退到默认值。
  9. V3.7
