    2026-09-17 · 当前基线：九项能力的基板 + 可插拔外挂扩展

    ⑧ 当前功能面（收敛自 V4 段的过程记录；下面每一条都是现在就能感受到的行为）：
    · 权限按资源判：三个身份（主人／她自己／其他用户）× 五类资源（本机、运行时目录、数据、外部交互、工具入口）× 三个位（R/W/X）， 例外清单放在数据根的 perms.json 账本里，判定失败一律拒绝；消息里自称「我是主人」不构成任何授权。看账本用 ai/acl （只读那一支 src\sair\v4\term\Cmd.java:701）。
    · 配置生命周期只有一条规则：写命令只改文件，ai/start 才「加载并运行」（ai/restart = 停旧基板 → 重读文件 → 重新装配）； ai/status 会把「文件里的值 ≠ 已生效的值」的键列出来，没启动过的实例是正常的 ready=0 reason=not_started。
    · 调度按会话分道：同一会话严格保序、同一时刻只跑一条，不同会话互不阻塞；队列装不下时优先把后到的同会话消息并进还在排队的那一条， 真的装不下才按策略处置并回一句可配置文案（消息不会静默消失）；模型调用有并发闸门（modelConcurrency）。
    · 上下文每回合现查：每触发一个回合就现查本会话最近 chatWindowSize 条聊天记录，逐字照抄、单条不截断 （默认 30，src\sair\v4\Conf.java:179；读口 ctx\ChatWindow.java:143-146）。
    · 事实块里带模型自知与原生附图：模型自知那行固定 8 个键、键序固定 （self／self_has_vision／main／main_has_vision／vision／mode／recognizer／recognizer_uses， src\sair\v4\ctx\CtxBuild.java:331-345），说明这一轮真正会用哪台模型、它能不能看图； 附图只在第一次请求带图，没挂上的图会如实报出来（不静默）。说明见实现页 · 上下文。
    · 通知类事件一律入库留痕，但零触发：戳一戳／撤回／进退群／禁言／表情回应等都落成一行确定性标签进聊天记录， 只落库、不派发、不调模型、不发消息；它们进模型的唯一通路是聊天窗口 （入库与去向 src\sair\v4\QqGateway.java:203-239；标签只由 qq\NoticeRender.java:59 一处产出）。
    · 被引用消息按需取回：优先查本地库，没命中才走 NapCat；取回的引文会拼在窗口对应的那一行上，取不到就不写这个键（不写填充词） （src\sair\v4\qq\QuoteCache.java:78）。
    · 她自己的出站消息进她自己的记账：发出去的每一条都落一行自我标记行，窗口里显示成「我」，所以她看得见自己刚说过什么、发过哪张图 （头部文法 src\sair\v4\qq\SelfEcho.java:79）。
    · 出站正文过一道结构闸门：命中「工具调用标记」形状的那一条整条丢弃、其余条照发（不删字符后照发，也不连坐）； 正常文本里的尖括号（List<String>、x < 0 > y）不受影响 （src\sair\v4\qq\ToolMarkup.java:41，落点 term\Sinks.java:73）。
    · 控制台：装配跑在基板自己的守护线程上（敲命令、看界面立刻有响应）；对话正文单独落一页面板，主输出框只留过程日志； 控制台输出有独立捕获缓冲；help／status／tools／config 四条不依赖模型、数据库与 QQ，任何装配异常下都能用。
    · 数据面：群聊／私聊／记忆各有独立保留天数（笔记不自动删除），另有两步空间回收命令（合并索引空洞 → 回收空闲页）； 模型密钥、QQ 接入 token、中转 token 三个敏感项加密落盘，与运行环境绑定（src\sair\v4\Conf.java:57）。
    · 进出网都要过的门：抓取网页与下载文件时拦截指向内网、本机、云元数据地址的请求，且每一跳跳转都重新校验； 网页与文本按「字节序标记 → 响应声明 → 页面内声明 → 逐一试探」的顺序解码；写入前做内容查重。
    · 本地文件外链中转：NapCat 与插件不在同一台机器时，把本地文件变成一个只读链接交给它自己取；只支持读取、链接带随机前缀、可设有效期，默认关闭。

  2. V3.14

    正确性与成本治理：中文检索召回、跨群污染、永久丢失、前缀缓存、上下文扩容

    中文检索召回从≈0修到满召回：分词器把整段中文当成一个 token，中文子串检索实际全部失效（实测 36 万条群聊记录里召回几乎为 0）； 索引全部迁移到三字滑窗分词（启动后台重建），查询构造统一化并把兜底查询补上转义 —— 原先每次 1.16–1.21 秒、且持有全局库锁、 在 82.98% 的消息上触发的检索，降到 1–5 毫秒。 跨群串味与并发：对话去重改为「同来源 + 同发送者 + 同角色 + 120 秒内」；去重命中时补写消息号不再按内容全局乱匹配； 群聊提示词不再注入「与该用户的私聊历史」；即时情绪按用户／按群隔离；停止标记改为按请求闭锁；线程池丢任务不再静默； 好感度与每日互动改为原子读改写；工具集序列化缓存改为单一不可变对象（原先并发下会把另一渠道的工具集发给模型）。 永久丢失修复：文件读取的偏移／长度从「先截断再切片」改为「在完整文本上切片」；CQ 码不再无声删除、降级为可读占位符； 回复与记忆的清洗从「通配剥离所有尖括号」改为只剥约定的控制标记；引用图片的地址与校验值改为成对存储；超大帧改为读完丢弃而不是断开连接。 前缀缓存与上下文扩容：上下文重构为「稳定段 + 易变段」两段式，逐条消息变化的内容全部后移；印象里的精确计数改为粗粒度分档， 避免每条消息都把稳定段字节改掉从而打断前缀缓存。
  3. V3.13

    长折叠 / 嵌套折叠处理：结构化递归展开 + 分段分析 + 折叠图片全识别

    修复长折叠被静默截断：原先两处长度上限会把长折叠的尾巴整段丢掉，统一放宽到 20000 字，超长部分改由分段分析处理 （按消息边界切块 → 逐块交给段落 Agent → 再由段落 Agent 合并成一份结论），不再静默丢失内容。 嵌套折叠层层递归：新增结构化解析，保留图片真实地址与嵌套折叠编号；渲染时内嵌折叠就地递归展开， 每一层内嵌折叠单独唤起一个段落 Agent 分析并把结论内联进上层正文（层级上限 3 层、单条消息段落 Agent 调用预算 10 次）。 折叠消息里的图片修复为可见：原先只渲染成字面量、连地址都没有，导致模型既看不到图也无法调用识图；现输出可读地址并按多模态内容提交（单次附加上限 20 张）。 段落结论回传上限 1200 → 3000 字符；收藏失败时回传具体原因；消息打标改为按消息号精确写入。
  4. V3.12

    Agent 职责重划分：折叠消息全交段落 Agent + 视觉 Agent 转为兜底 + 模型能力感知

    引入模型能力感知：具备原生视觉的模型由主／段落 Agent 直接看原图，不具备视觉的模型必须由视觉 Agent 兜底识图， 无原生视觉时该 Agent 自动启用、有则自动不启用。 折叠消息（不论是否引用）一律交给段落 Agent 分析，结论标注回该条消息并标识「已分析」，下一轮先按消息号精确查、再按内容兜底查， 命中即复用结论、不重复分析。视觉 Agent 的执行模型写死为具备视觉的那一档；主／段落 Agent 的工具集与 Agent 间唤起按视觉能力动态门控。 另支持按引用／按消息号精确打标，私聊会话表补消息号列，Agent 间结果缓存对超长任务跳过以防内存膨胀。
  5. V3.11

    模型迁移 + 原生多模态视觉 + 取消引用改 @ + 移除工具调用上限

    跟进模型服务方 API 变更：模型名迁移到新的 Flash 档（性能／费用／速度全面超越上一档）， 并统一模型解析规则 —— 只有配置写 auto 才走自动路由，写了具体模型名就严格按该名称调用、所有通道一律照用不做替换； 业务代码中残留的 9 处硬编码模型名全部改为走配置读取。 取消独立视觉模型：识图不再「先单独调视觉模型转文字再注入上下文」，改为把图片直接作为多模态内容随用户消息提交（省一次调用与一轮 token）。 清理已废弃的采样参数下发，长度上限对齐官方档位，流式解析增加空行与注释行容错。 取消机器人主动引用回复：引用错乱（甲提问却回复到乙）的根因是引用编号与消息归属不匹配，改为系统自动 @ 提问者，并强化「本次回复对象」标识。 移除 Agent 工具调用次数硬上限（原主循环 60 次、子 Agent 8–12 次），改由 Agent 自身判断任务是否完成，仅在连续失败与显式停止时终止；戳一戳改为系统直接拦截。
  6. V3.10

    存图多智能体协作 + 表情包保留治理 + 提示词 md 化 + 卡片消息识别

    存图机制重构为多 Agent 协作：主 Agent 打包候选 → 段落 Agent 找图 → 视觉 Agent 识图 → 按「单张脸 + 文字不超过 20 字 + 无违规」判断 → 收藏 → 打标。 表情包保留策略重做为被动／主动双通道（保底 15 / 阈值 30 / 上限 60，超时回收），删除收集冷却与识图冷却。 提示词 md 化：两段提示词从配置文件独立为 md 文件（md 提供身份设定，代码侧只做后置拼接）。 卡片类消息（群邀请／好友申请等）解析出人可读内容并注入拦截结果，修复模型看到空消息。 另修复回复附带用户原话、工具调用配对与识图缓存串扰、线程池扩容异常等问题。
  7. V3.9

    性能深度治理：热路径提速 + token 去重 + 前缀命中 + 写放大治理

    每条消息的纯文本只提取一次并贯穿复用（原先约 10 次正则剥离）；稳定的外挂扩展索引前置到用户消息首部以命中前缀缓存，动态历史不再破坏前缀稳定； 群管理员／群昵称／群名／个人昵称映射加短 TTL 缓存，并移除原本每条群消息都失效缓存的逻辑，让读缓存真正生效； 偏好与日志上下文加内存缓存、写入即失效，不再每条消息重复查库拼接；工具集序列化与请求体按对象身份缓存； 遥测与轨迹改为异步落库，工具执行与主链路不再同步等待数据库写入；语音／识图结果缓存改为有界 LRU，防长期运行无限增长； 群成员角色／昵称／成员关系写库去重，大幅降低每条群消息的写放大；补热路径索引，会话裁剪改为每 50 次写入执行一次，消除全表扫描； 短消息（去标点不足 4 字）不再触发检索门控；群回复后总是给被回复的那条打上「已回复」标记，修复已回答的问题被重复回答。
  8. V3.8

    跨机器媒体发送修复 + 记忆通道修复 + 运行时状态

    图片／语音／表情包的本地文件增加内联兜底发送（解决对端在另一操作系统的机器上无法下载 Windows 本地路径的失败）； 发图不再误报成功，失败返回真实原因；记忆写入在两条链路上统一落库；新增一条用于手动指定文件中转服务对外地址的配置命令； 新增运行时状态查询与工具调用轻量遥测；配置加载后增加校验日志，非法端口／越界参数回退默认值。
