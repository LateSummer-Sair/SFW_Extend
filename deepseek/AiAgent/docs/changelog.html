    三方技能协议化：airun 声明式参数扩展、加载期编译注册、83 条硬编码技能整体迁出
    硬编码技能整体迁出为单文件 .md：SystemSkillLib 605→88 行、NapCatSkillLib 745→34 行，83 条内置工具文档（52 条 NapCat + 31 条系统工具）不再以 Java 字符串常量存在于代码里，全部变成 data/skills/ 下的单文件 .md —— 项目内 data/skills/ 现在是 100 个技能：80 条纯文档（52 条 execq,execs + 15 条全通道 + 13 条仅本地链路 console,execs）里包含从代码路径抽取的工具说明书 时间查询/快速笔记搜索/技能说明书查询，另 20 个工具技能（14 条全通道 + 6 条 console,execs）各自提供 20 个已剥离工具中的一个，技能库只剩「已退役内置」两张清单；多文件技能包（agentskills.io 标准、data/skillpackages）整体移除，技能形态收敛为单文件（根目录 + 一层子目录），同名三方技能优先于内置、删文件即移除、改文件即热重载。airun 参数协议化：入参从「一个 JSON 字符串 / 一个 Map」升级为声明式签名 —— params 支持 type（含 int→integer / bool→boolean / list→array 别名）、required、description、default（模型没填时框架补齐）、enum（写进 JSON Schema 限定取值）、example（拼进参数描述，显著提高模型填对率）、items + items_description（数组元素类型与说明；此前没有 items 的数组在 JSON Schema 里非法）；新增 is_master / affection / self_id / skill_name / source_file / data_dir / now / call_id 做成纯数据（Java 收 Map、JS 收对象、Python 收 dict），签名按 airun(Map,Map) → airun(Map,String) → airun(String,Map) → 文件，需要写操作时应走已有工具能力面。加载期编译注册：.md 一被加载就编译 airun 并登记进运行时注册表（按内容哈希比对：没改复用、改了新替旧、删了摘除），调用期不再动态编译（此前每次调用都走一遍编译缓存查找）；编译不过的技能在加载期就红字点名并记下原因，模型调用时直接收到该错误，不再白烧一轮模型往返。thirdskill validate：重扫目录 + 重编译 + 逐条点名「编译失败 / 没有 airun 入口 / 同时声明多语言只执行优先级最高的 / 工具名含非法字符被规范化为 tp_skill-<hash> / 未声明 channels 或 permission」，作者改完 md 不用重启客户端即可自查。失败可诊断：airun 抛异常时回显技能内栈帧（最多 5 帧）而不是一句 InvocationTargetException；技能里的 println/print 由线程级 tee 捕获并附在工具结果里（上限 4000 字符，互不串台）。实测发现并修复的数字类型 bug：Gson 默认策略把 JSON 数字全部解析成 Double，声明 type: integer 的参数到技能手里是 3.0、技能原样回显给模型也是 3.0（好感度 777 变 777.0）；改用 LONG_OR_DOUBLE 策略后 integer 稳定为 Long。技能与笔记去重：新增 /dedup [skills|notes|all] [apply] [阈值] —— 技能用 trigram 包含度、笔记用「标题」的 bigram Jaccard（默认阈值 0.85，只拦近乎复述的），刻意不共用指纹：笔记正文里同一件事的不同问法相似度极高，用正文指纹会把「原神 诺艾尔」并进「原神 桑多涅」；合并=标记 merged_into 指向代表条目、内容不删除，提取端用同一套抑制并把重复次数累加为     正确性与成本治理：中文检索召回、跨群污染、永久丢失、KV 前缀缓存、上下文扩容
    中文检索召回从≈0修到满召回：FTS5 的 unicode61 分词器把整段中文当成一个 token，MATCH 只能命中「整段完全相同」的文档，于是群聊历史/记忆/笔记的中文子串检索实际全部失效（实测 36 万条群聊记录里中文查询召回几乎为 0）；两个库的 FTS 索引全部迁移到 tokenize='trigram'（启动后台线程重建，5 万条/秒级），新增 FtsQuery 统一构造 MATCH 表达式（3 字滑窗 + 双引号转义 + 2 字查询自动回退 LIKE）并把所有 LIKE 兜底补上 ESCAPE；searchGroupChatHistory 原先每次 1.16-1.21 秒、且持有全局 DB 锁、在 82.98% 的消息上触发，现为 1-5 毫秒。技能索引不再被海量经验技能挤空：SELECT * FROM skills 按 id 降序取 4661 条，预算一满，id 很小的内置工具/API 清单（52 条 NapCat + 31 条系统工具）会被整体截断（execs/console 通道下内置技能一条都进不去），改为「内置优先 + 其余新建优先」并加版本校验快照缓存（原来每条消息一次 46ms 全表查询），索引预算 800→2000 token；同时索引不再用成功率门槛过滤（成功率低→永不出现在目录→永不被复用→成功率永远低的死循环）。跨群串味与并发：对话去重从「该发送者历史上说过同样的话就不再记录」（LIMIT 10 对存在性判断毫无作用，且无来源作用域）改为「同来源+同发送者+同角色+120 秒内」；去重命中时补写 message_id 不再按内容全局乱匹配、写到别的群/别人行上；群聊 prompt 不再注入「与该用户的私聊历史」（私聊内容当众泄露）；即时情绪、怒气联动按用户/按群隔离（原先群氛围每来一条消息 +2 怒、衰减只有 -2/分钟，会把全局怒气钉死在 100，AI 对所有群和私聊都变暴躁）；/stop 改为按请求闭锁（原先前一个请求的停止标记会被后一个请求重置）；线程池丢弃任务不再静默（被丢的消息既不回复也永久屏蔽该 messageId），重复消息登记改为带 10 分钟陈旧窗口的自愈结构；好感度/每日互动改为原子读改写；DeepSeekClient 的 tools 序列化缓存改为单一不可变持有对象（原两个 volatile 字段会被并发写交错成「key=渠道B、内容=渠道A」，把另一渠道的工具集发给模型）；群管理配置、敏感词库、技能版本、待处理请求池全部持久化/加 TTL。永久丢失修复：FileUtils.readFile 的 offset/limit 从「先截断到 5 万字符再切片」改为「在完整文本上切片」，修复第 5 万字符之后永远读不到（返回空串却被判为成功）；CQ 码不再无声删除，表情/骰子/位置/文件等降级为可读占位符（这段文本同时是记忆入库内容，丢了就是永久丢失）；回复与记忆的清洗从「通配剥离所有尖括号」改为只剥离约定的控制标记（List<String>、HTML 片段、x < 0 > y 曾被一并吞掉并写进记忆）；引用图片的 url
