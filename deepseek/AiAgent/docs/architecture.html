02 / 装配

装配流程

Boot.init() 顺序跑 19 个命名步骤；任何一步出错只让那一步对应的能力缺失，装配继续走完。

契约

行为实现
只真跑一次initOnce.compareAndSet(false,true) 失败即 return
全程持 initLock，结束前先落 initRunning=false 再放锁等待方看不到半拉状态
就绪钩子 onReady 在 started=true 之前跑「看到就绪」的读者必然「看到名额已空」
步骤异常收敛成台账一行steps.put(name,"failed: …")；只有第一个失败记进 failedStep
不向调用方抛异常它是控制台命令路径的第一环，抛出去就没人接手了
总步数常量STEP_TOTAL = 19

台账 steps 用 LinkedHashMap（顺序 = 执行顺序），读写共用一把只保护台账的短锁 ledgerLock；降级时 degraded() 为真、failureReport() 给人话。

空数据骨架：只创建、不覆盖、不写正文

ensureSkeleton 用 dir() 建目录、emptyFile() 建空壳文件：数据根、prompts、外挂层目录、files、tmp 五个目录，加上 identity.md、subagent.md 两个空文件。同名文件挡路就不覆盖，已存在的一个字不动；也不写任何兜底正文 —— 空文件与「文件不存在」在加载层语义一致（PromptFile.java）。

建表为什么排在装载之后：业务表由用到它的插件在装载期声明，装载之前注册表里还没有它们，所以 Boot.createLibTables() 在装载之后跑，另外留了热重载回调，重新装载时也能把新表补出来。

装配线程与进度

Boot.init() 在调用线程上同步跑完；生产入口 V4Activity 把它放到守护线程 v4-boot 上。进度由 BootProgress implements Boot.InitListener 逐行打印：step() 记最慢的一步、compile() 记编译进度、finished() 打汇总。

03 / 并发

线程与调度

回合按会话分道、道内 FIFO、道间并行；真正并发的是 N 个工作线程，模型调用另有一道许可闸门。

线程清单

线程名来源数量 / 队列满了怎么办
v4-bootV4Activity 的装配线程1，守护不适用
v4-turn-NBoot.turns，只服务本地控制台1 线程 + ArrayBlockingQueue(64)拒绝执行 + 一行 warn
v4-lane-NLanes.ensurePool()，懒启动turnWorkers（默认 2，钳 1..32）两道硬上限：turnLaneMax / turnQueueMax
v4-hook-NPool.hooks(conf,out)hookWorkers(4) + hookQueueMax(64)caller（调用线程兜底跑）或 skip
事件执行池Boot.newEventPool()，装到 LinkeventWorkers(8) + eventQueueMax(512)池没起来时每个事件单开一条线程
v4-*Th.pool()：唯一一个 4 线程 ScheduledExecutorService4，守护任务异常被吞掉，不杀调度
v4-tickTick.start() → Th.every(…)1 条周期任务，tickMs(20000)，下限 1000不适用
后台装载线程Boot.startSkillsAsync()（外挂层后台装载开关打开时才起）1，守护编译失败只让该插件停在 ERROR 态
v4-quoteQuoteCache.ensureWorker()，第一次真入队才懒启动1 专用线程 + 串行队列（64）超预算丢弃（qq\QuoteCache.java）
WS 连接线程Link 的 ServerSocket.accept() 循环每连接一条读线程握手超时 10000ms（qq\Link.java）
线程治理只有一处收口：后台线程都从 kit\Th.java 出，Boot.stop() 唯一调 Th.shutdown()，而它只收调度池。口径写在 kit\Th.java 的类注释里：常驻后台只允许两类 —— NapCat 链接服务与唯一的事件 tick；其余定时行为都挂在 tick 的钩子上。任务异常被吞掉，不会把调度本身带走。

分道调度器 Lanes

实现 Dispatcher（schedule\Dispatcher.java）。数据模型：Map<String,Lane> lanes + Deque<Lane> ready + List<Thread> pool，全受一把 lock 保护。每道带 queued／running／high／since 四个状态位。

textsrc\sair\v4\schedule\Lanes.java（提交路径）
submit(session, high, job):
  ① 先试着并进「该会话还在排队的那一条」    // 合并不占新名额，优先于一切上限判断
  ② lane.q.size() >= laneMax                        -> drop
  ③ pending.incrementAndGet() > queueMax            -> 回滚 + drop
  ④ 通过：入队；道不在 ready 且没在跑 -> enqueue（decision=start）
  锁外：打一行 [lane] session=… decision=… depth=… pending=…
        // 回话/告警一律在锁外：job.notice 会走网络 I/O，持锁发消息 = 一个慢连接卡住所有人

选道规则（master_first）

  1. 老化优先：等超过 turnPriorityAgingMs（5000ms）的普通道直接提到最前，与额度无关
  2. 额度内的高优道：highStreak < priorityBurst（8）时挑高优
  3. 额度用尽时让普通道走：这时不用 peekFirst()，否则排在前面的仍是高优道，额度等于没设
  4. 都不命中才先到先得

溢出策略

  • coalesce（默认）：并进同道还在排队的那一条
  • drop：按 turnDropNotice 回一句外挂文案
  • 不会静默消失：文案缺键时报错、不兜底
  • 合并只做整段拼接，装不下就 -1，不腰斩正文（ChatJob.java）

合并有一条排除项：带引文事实行（前缀 quote: ，见 qq\QuoteCache.java）的回合不参与合并 —— 合并会重建媒体事实串（ChatJob.java），任何非 media: 开头的行都会被静默丢掉。判据取的是保守方向：宁可多跑一个回合。

模型调用闸门

javasrc\sair\v4\Boot.java
ai.setGate(new java.util.concurrent.Semaphore(conf.modelConcurrency(), true));

主回合、定时任务、异步子 Agent 都要过它，所以「模型不并发」只有一处实现。许可数 modelConcurrency 默认 1（Conf.java）；fair=true 先到先得；等闸门上限 modelGateWaitMs 默认 180000ms，超时即放弃本次调用（ai\DeepSeek.java）；计数 gateWaiting／gateWaits／gateWaitMs／gateTimeouts／gateInFlight 汇总进 gateStat()。

心跳 tick：唯一周期源

Tick.start() 用 Th.every 起一条固定间隔任务；beat() 每拍四件事，三个 try 各自隔断，任一块出错都不影响另外两块与下一拍。定时算术集中在 nextFire(fireAt, repeat, now)：once → 0（不再触发）；daily = 24h；weekly = 7d；every:<分钟> 下限 1 分钟；其余一律 0。fireDue 先把下一次时间写好再跑，任务执行期间就不会重复触发。

04 / 工具

工具注册与调用

全进程只有一张工具表；入口判位、执行不判位；连续失败由一条「事实化」闸门收敛成一行 JSON。

唯一注册表

tool\Registry.java 持一个 ConcurrentHashMap<String,Tool>，注册口只有 add(Tool)：每个工具在表里只有一条记录，重名注册走同一把钥匙，不会出现两份同名工具。

schema 怎么生成

Tool 不可变，用 Builder 造（tool\Tool.java）；params 为空就给空对象 schema。

jsonsrc\sair\v4\tool\Tool.java
{"type":"function",
 "function":{"name":"…","description":"<desc> 例：<示例…> 返回：<returns>",
             "parameters":{"type":"object","properties":{…}}}}
// 说明串只在 Tool.fullDesc() 一处拼

另有 withoutHandler() 给插件一份去掉实现的副本（Tool.java），让它绕不过入口判位；Registry.getView(name) 就是这个出口（Registry.java）。ai\ToolSpec.fn(name,desc,params) 是更轻的纯工厂（ai\ToolSpec.java）。

两道门：交不交到手 / 点不点得动

门判据
可见性（交不交到手）auth.bits(c, Res.tool(名)) 含 X；判定抛异常 → 不交（fail-closed）
入口闸门（点不点得动）auth.allowRes(c, Res.tool(名), 'X')；非 null 即拒，并把拒文原文返回
资源判定（碰得到吗）不在这里 —— 发生在工具碰资源那一刻（Host.need* → Acl.allow）

不筛的两种情况：c == null（没有调用者，诊断或控制台拿全量视图）与 auth == null（权限面没装配 —— 这时基板不假装自己有权限面，交全量而不是交空表）。不过 call() 里 c == null 且 auth != null 时仍走入口闸门，唯一显式放行口是 Gate.deny 里的 c.master()。

调用路径与结果规整

textsrc\sair\v4\tool\Registry.java（call 路径）
call(name, args, turn):
  查不到工具      -> miss(name, c)      // 候选 + 正确用法，跟着可见面一起筛
  入口闸门拒      -> noteDeny 后直接返回拒文（不执行 Handler）
  handler null    -> "[tool] " + name + " 没有实现"

参数检查与名字兜底

机制口径
参数检查 argWarn看 required 里的必填项给了没有、enum 值在不在表内（大小写不敏感）；命中就返回一句提示，由 call 追加在结果后面。不拦：实现可能接受 md 里没声明的别名
名字归一化小写 + 去掉分隔符与空白（[_\-.\s]+ → 空）
相似度编辑距离，两行滚动数组
候选筛选只看该调用者可见的工具；候选数(3) / 距离上限(2)
候选为空回一句「当前可用：…」全清单

能力索引：一行事实

ToolIndex.line(visible, withDesc) 把可见工具压成一行「类别 → 工具[一句话]」。三个开关来自 data\prompts\tools-index.md：总预算 默认 12000、条目描述上限 40、默认类别 "其它"。主 Agent 带一句话、子 Agent 只给名字，省的是 token。文件缺失或解析不出类别 → line() 返回 null，事实块里就没有这一行。

连续失败闸门

闸门本体在 agent\Loop.java，认的是结构信号而不是关键词表：

textsrc\sair\v4\agent\Loop.java（失败判定）
failed(tool, result):
  head = 结果首行，截断 60 字符
  以 "[tool]" 或 "[auth]" 开头            -> 失败
  deniedResult(head) 为真（权限拒绝三形态）-> 失败
  不以 "[" + tool + "]" 开头              -> 不算失败（不是它自报的结果）
  以 "[自己名字]" 开头 -> 看 okMark(head)：ok=1 成功；ok=0 失败；没写也失败
环节口径
权限拒绝三形态[auth] 权限阻断 开头（兼容识别）／正文包含 [权限阻断] （现代判据）／以 缺 R/W/X 位 —— 开头（Host.need* 的信息性前缀）
ok= 读取只认取值恰是 0 或 1 的形态（ok=10 不算命中），否则当「没写」
计数failStreak + failLast（最后一次失败截断 120 字）；成功即清零
提示阈值达到就往上下文加一条 system 事实行
终止阈值达到就 break 主循环，终止文案进 Outcome.error

存储与数据表

单连接 + 全方法 synchronized 的 SQLite；表名列名只有一份白名单；FTS5 外部内容表配 trigram 分词器。

连接与 PRAGMA

纯 JDBC，无 ORM、无连接池（store\Db.java）。单连接 + 全方法 synchronized：读写走同一把锁、写操作天然串行，因此不会出现 "database is locked"；WAL 让读不阻塞写，busy_timeout 兜住跨进程的短暂争用。

数据表怎么组织

数据分两类。一类是基板运行表：闹钟、任务、键值、插件索引、出站消息台账这些由基板自己用，DDL 留在 store\Lib.java，列清单在 RUN_COLS。另一类是业务数据表：dialog、grouplog 这两张环境库由基板声明（消息流就是环境，基板是它们唯一的写入者），其余表由用到它的插件在装载期声明（EnvLibs.java）。

其中 dialog、grouplog、memory、note 这几张检索型表各配一张 FTS5 外部内容虚表：虚表名是 fts_ + 表名，本身不存正文，只索引声明的检索列；每张虚表另配 4 张影子表（*_config、*_data、*_docsize、*_idx）与 3 个同步触发器（ai 插入、ad 删除、au 更新），主键自动索引则由 SQLite 自己建（sqlite_autoindex_*）。

运行表与业务表分开算：Lib.java 声明的运行表（含出站消息台账 sent）由基板自己建，业务表由用到它的插件在装载期声明。两边都走 CREATE … IF NOT EXISTS 加「先查后补列」，所以同一份数据目录反复装配也只会核对，不会重建、不会重复报错。

子 Agent 拿不到 agent显式名单那条路在 Agent.subTools 剔过；Loop 这里挡住「空名单 = 继承全部工具」那条路（Loop.java）
说话类工具哪些工具算「说话类」由外挂层声明（本页不列名单）；setNoSpeak(true) 的收尾回合只记账、不发言（Loop.java）
「已经说过话」要认三种拒绝形态deniedResult 同时认 [auth] 权限阻断 开头、正文含 [权限阻断] 、缺 R/W/X 位 —— 开头。少认一种，ACL 面的拒绝就会被当成「说过话了」，她便不再补一句正确的回复（Loop.java）
11 / 装载机制

外挂层加载机制

目录扫描 → front matter 解析 → 内存编译 → 每插件一个类加载器 → 注册工具 / 声明表 / 挂扩展点。

外挂层里具体有哪些单元不在本页；这里只讲装载机制本身。

装载管线

textsrc\sair\v4\Boot.java（扫描调用点）
扫描（装配第⑯步同步走，或按后台装载开关起后台线程）
  for 每个插件目录:
      loadOne(dir, name):
        ① 解析 md 的 front matter        // hot\SkMd.java
        ② 校验声明名与文件夹名一致        // 不一致 -> 该插件停在 ERROR 态
        ③ 编译目录下的 *.java 为**内存里编译好的类**   // hot\SkCompile.java
        ④ 名字规范化（不合规范就改名）    // hot\ToolNames.java
        ⑤ 声明自己的表                   // 声明接口在契约包
        ⑥ 注册工具 + 挂钩子 + 整体注册扩展点
  末尾: createLibTables()                  // 把新声明的表建出来
组件机制
内存编译ToolProvider.getSystemJavaCompiler() + DiagnosticCollector；classpath 由 substrateClasspath() 给出（宿主进程 + 本插件编译产物的位置 + 框架与其依赖库）。插件目录不是 classpath（hot\SkCompile.java）
内存输出ForwardingJavaFileManager + SimpleJavaFileObject 两个内部类，把 .class 收进内存而不落盘（SkCompile.java）
类加载每个插件一个自己的类加载器 —— 不同插件的顶层类可以同名，互不冲突（hot\SkClassLoader.java：findClass 从 Map<String,byte[]> 取编译结果后 defineClass）
classpath 缓存一次运行内不变；refreshClasspath() 可以重算（SkCompile.java）
名字规范化注册名与声明名分离，映射留着；不合规范时由 hot\ToolNames.java 给出合规名（Skills.java）
动态执行hot\DynCode.java：运行期把一段源码编译并执行，装配第⑦步就 new 好
钩子声明解析既支持 YAML 数组 hooks: [on_timer, on_message]，也支持逗号或空格分隔的字符串（Skills.java）
钩子执行池钩子仍然「同步」跑（要等 _handled 才知道结果），但并发线程数不再随消息数涨（Pool.java）
库声明装载期由实现了声明接口的顶层类登记自己的表；装载器对每个顶层类都问一次（Skills.java）
卸载插件没了，它挂的工具 + 钩子 + 扩展点一起摘（Skills.java、Registry.java）

扩展点注册表：四种形状 + 两道上限

ext\ExtRegistry.java 是「基板⑦」，装配第⑨步建好。四种契约形状各有一张按 order, 名字 排序的表：ContextProvider（ext\ContextProvider.java）、OutboundStage（ext\OutboundStage.java）、LifecycleHook（ext\LifecycleHook.java）、TriggerVoter（ext\TriggerVoter.java）；每个扩展点具体能做什么、不能做什么，见 扩展点与契约面。

两道上限：单次扩展点调用超时 extTimeoutMs 默认 200ms（≤0 = 不超时；超时即放弃该次调用）（ExtRegistry.java、Conf.java）；上下文块还有全局字符预算 ctxBudgetChars 默认 6000，超预算从尾部丢块并计数 budgetDrops（ExtRegistry.java、Conf.java）。

总开关 on() = enabled() && any()：没挂任何 provider 时，连 provider 都不会被调用，开销一点都不多（ExtRegistry.java、CtxBuild.java）。故障隔离两层：扩展点自己做了异常隔离，调用方再兜一层「连注册表都炸了」，同样只丢外挂块（CtxBuild.java、QqGateway.java）。

契约形状（只有这些，且都是只读面）

形状要点
入口接口 call(...)被识别为工具入口的类；返回值可以是 String / Map / JsonObject / List / null。也支持反射回退：有 airun(...) 方法的类同样能被调用，写小件时省掉一批 import
装载期声明 declare(Libs)默认空实现；时机在实例化入口类之后、注册工具之前（表要早于用它的工具存在）。这里给的是注册表，不是宿主观图 —— 装载期没有对话
宿主 Host一次调用期间的唯一能力面，提供工具调用、发言、派子 Agent、注入、向 SFW 发命令等，改不动基板的任何判定
Args / ConfView / FavorView参数、配置、好感度的只读视图（好感度不参与权限判定，见 #auth-impl）
工具视图 ToolViewgetView(name) 拿到的是去掉实现的副本（Registry.java）
钩子标记 Hooked声明实现了哪些钩子，被装载器按接口自动识别

库注册表：store\Libs.java 定形、store\LibRegistry.java 实现；装配第③步建好之后，同一份对象交给 Store、Db 与装载器（Boot.java、Db.java），所以声明出来的表立刻进白名单与清单。具体有哪些插件、用途、参数、工具名、钩子名单都不在本页范围内 —— 见 能力 与 文件。

12 / 控制台与界面

控制台与界面

命令面、流式捕获环形缓冲、四种输出端点、面板的 EDT 挂载规则。

命令面：一个入口

term\Cmd.java 的 route(func, args) 是唯一入口，由 V4Activity.main(funcName, args) 转发。V4Activity 只搭「壳」（Boot + Cmd）并起一次装配线程，立即返回；「壳已搭好」的判据是 cmd != null 而不是 boot != null —— 装配中途失败时 boot 可能已经存在，但命令表还没建好，那种状态下继续把命令表建出来，控制台才可用（V4Activity.java）。

内部方法职责
status() / pendingLine()装配状态与各面计数 / 加载中的排队提示（Cmd.java）
chat(text)本地对话：要一个 Future 才能等回合结束，所以走 Boot.turns 那条单线程队列（Cmd.java）
tools(a)工具清单（带「该调用者在这把工具上的有效位」）（Cmd.java、Registry.java）
startCmd / restartCmd起基板 / 重启（Life 接口交给壳实现）（Cmd.java）
config(a) / aclCmd()配置读写（敏感值掩码打印）与账本操作（Cmd.java）
caller()控制台命令的主语一律是 MASTER（Cmd.java）

控制台为什么单开一条队列：本地 chat 需要一个 Future 才能等回合结束，它走 Boot.turns（单线程 + 64 槽有界队列）；QQ 入站、闹钟、异步子 Agent 走 Lanes。两条路分开，一个慢群就不会堵住全部会话。

控制台捕获：环形缓冲 + 游标读取

term\ConsoleTap.java 通过 SairCons.addPrintRunnable(id, runnable) 注册打印代理，代理 ID 常量 AiAgentV4_ConsoleTap。参数默认：环形缓冲 500 条、单次读取上限 4000 字符。缓冲本体是 ArrayDeque<Line> + 全局自增 seq，read(from, n, filter) 只回游标之后的部分。转发策略三档 auto/always/never；安装与注销走 install(conf)／install(conf, hold)／uninstall()，run(...) 会顺手补装。

捕获器的生命周期归壳：Th.shutdown() 不碰它 —— 它是控制台的一部分，插件构造期就挂上；注销由壳负责：只有壳卸载（调试壳 detach() ← V4Activity.exit()）时才注销。

输出去向：四种端点 + 一条出站阶段管线

term\Sinks.java 收四个 ctx\Sink 实现：ConsoleSink、QqSink、TaskSink（后台任务与闹钟结果的落点）、SilentSink（只吞不出）。出站阶段管线只接一处：Sinks.setExt(ext)，发送前先过 e.runStages(m, parts, sp).parts —— 于是「分段 + 渲染 + 外挂改写」都在同一个位置发生，没有第二条出站路径。

本地交流面板：窗口动作投到 EDT

点口径
挂载投递到 EDTSwingUtilities.invokeLater；已经在 EDT 上就地做（再投递会等自己）（TalkMount.java）
等待上限DEF_WAIT_MS = 5000；超时给出可读错误而不是静默失败（TalkMount.java）
状态载体volatile TalkPanel attached；挂载点只有一个，「查一下再挂」之间没有空隙让人插进来（TalkMount.java）
挂载时机装配最后一步；Boot.panelLock 的持锁期间不做挂载 —— 挂载会等 EDT，而控制台命令就跑在 EDT 上，那样会假死（Boot.java）
面板输出ui\PanelSink.java 是面板侧端点；ui\SfwStyle.java 管风格

调试实现

dev\DebugPort.java

  • 纯 ServerSocket 行协议；连上后第一行是 AUTH <token>：成功回 +OK <name>，失败回 -ERR bad token 并断开，每次失败记一行 warn
  • 只绑 127.0.0.1，不监听 0.0.0.0
  • token 留空则拒绝启动并打一行 warn
  • 装配不会自动起它：只由控制台命令起停，端口与 token 走命令参数、不进 config.json

dev\DebugSimPort.java

模拟口：把构造出来的事件喂进网关那条路，用来在没有真链接的情况下看路由行为；与调试口同一套「只回环 + 带 token」口径。另有 dev\DebugShell.java（调试壳，负责挂载与卸载捕获器）与 dev\DebugLog.java（调试日志）。

网络护栏

出站 HTTP 统一过 kit\NetGuard.check(url)。它挡三类目标：协议不是 http 或 https、地址根本解析不出来、以及落在回环或内网一侧的地址（本地名、云元数据域名、私网与链路本地段）。

判定结果结构化为 Verdict：blocked + code（ok/empty/scheme/bad_url/internal）+ 细分（loopback/private/link_local…）+ host + ip（NetGuard.java）。启动参数 -Dv4.netguard.devAllow=… 可以放行指定的主机名或 IP（只认字面量，不认通配；这张表在进程内第一次判定时读一次并缓存下来）。

kit\Out 一族：Out 是接口；PlainOut 直接打，GatedOut 带一个 Gate 开关（装配时用它按配置开关门），term\SfwOut.java 接到 SFW 控制台。日志类别是一等公民：默认只留「Agent 调用事件」这一类行，例如工具日志要先过 conf.logOn("tool")，调度决策行要先过 conf.logOn("lane")。

13 / 扩展

扩展点与契约面

四个扩展点、一组只读契约、两道上限：外挂层能做什么，做到哪一步就到此为止。

基板对外挂层只开四个口。每个口都有明确的「能做什么 / 不能做什么」，它们共用同一套护栏：单次调用独立超时、出错只丢自己那一次、每次调用留一行 [ext] 诊断。

扩展点能做什么不能做什么
OutboundStage
出站改写		位置在分段之后、发送之前（QqSink / TaskSink）。逐条三个口：veto 一票否决（true = 这一条不发）、transform 改正文（返回 null = 不改，返回空串 = 基板丢弃这一条）、extra 追加独立消息；另有一个整批收尾口，拿得到最终整条消息列表，可以整表改写或原样不动（ext\OutboundStage.java）改不动基板判定：权限位、地址判定、闸门与台账都在这条管线之外。否决是整条丢，没有「改一点点再发」的中间态；extra 追加出来的消息不再回 stage，插件之间就不会互相追加成环
ContextProvider
上下文提供者		每轮往 messages 里加一段，自己声明顺序（order + 插件名）、段位（stable()）与单段字符上限（maxChars()）：稳定段排在系统提示词之后、内置事实块之前，易变段排在内置事实块之后（ext\ContextProvider.java、BuildContext.java）内置事实块的位置与内容、历史条数与字符预算、本轮 user 消息的位置，都由基板定，它碰不到。它拿到的是只读口 BuildContext.host()，要写就写自己的库或自己的 kv
LifecycleHook
生命周期钩子		主回合的三个时点：回合开始（装配完、还没跑）、真要对外说话时、回合结束（正文已发出或已失败）。用途是记账与清理：写对话历史、记调用量、清临时态、发「typing」这类副作用（ext\LifecycleHook.java）不改消息内容 —— 那是 OutboundStage 的事，所以这里拿到的是只读 BuildContext，没有可改的正文。子 Agent 回合与后台收尾回合不触发，它们本来也不进对话历史
TriggerVoter
触发投票		三态票：ANSWER 回、DECLINE 不回（省掉一整轮模型调用）、ABSTAIN 不管。按 order, 插件名 依次问，第一个非弃权票生效（不是多数决）（ext\TriggerVoter.java、QqGateway.java）改不动地址判定本身：没人表态时网关仍走「私聊一律回、群里要求被 @」那条路。投票抛异常或超时都按 ABSTAIN 处理 —— 宁可不答，一条消息也不会因为投票而凭空消失
契约面是什么
入口接口 call(...)被识别为工具入口的类；返回值可以是 String / Map / JsonObject / List / null。也支持反射回退：有 airun(...) 方法的类同样能被调用，写小件时省掉一批 import
装载期声明 declare(Libs)默认空实现；时机在实例化入口类之后、注册工具之前（表要早于用它的工具存在）。这里给的是注册表，不是宿主观图 —— 装载期没有对话
宿主 Host一次调用期间的唯一能力面：调工具、发言、派子 Agent、注入、向 SFW 发命令都在这里，改不动基板的任何判定
只读视图 Args / ConfView / FavorView / ToolView参数、配置、好感度、工具的只读视图；ToolView 由 getView(name) 给出，拿到的是去掉实现的副本，绕不过入口判位（Registry.java）
钩子标记 Hooked声明实现了哪些钩子，被装载器按接口自动识别（src\sair\v4\skill\Hooked.java）

两道上限：单次扩展点调用超时 extTimeoutMs 默认 200ms（≤0 = 不超时；超时即放弃该次调用）；上下文块还有全局字符预算 ctxBudgetChars 默认 6000，超预算从尾部丢块并计数 budgetDrops（ext\ExtRegistry.java、Conf.java）。

总开关 on() = enabled() && any()：没挂任何 provider 时，连 provider 都不会被调用，开销一点都不多。故障隔离也分两层：扩展点自己做了异常隔离，调用方再兜一层「连注册表都炸了」，两层都只丢外挂块，不影响这一轮（ExtRegistry.java、CtxBuild.java）。

四个口都不通向判定层：权限位、地址判定、轮数上限与失败闸门、出站台账，全部由基板定。扩展点能读到结果、改写自己要发出去的东西、往上下文里加自己那一段，但改不了基板怎么判 —— 所以装了再多外挂，判定的口径仍然是同一份。
