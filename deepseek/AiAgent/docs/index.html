上手前值得知道的七件事

这些都是会直接影响你怎么用、怎么排障的硬约束或行为约定，每条都给了出处。

① 启动目录建议固定

敏感键的加密密钥派生包含 user.dir（当前工作目录），派生因子是「JVM 名 / 架构 / 用户名 / 主机名 / 工作目录 / 固定尾串」的 SHA-256，取前 16 字节做 AES-128 密钥。

出处 kit\Crypto.java。换机器 / 换用户名 / 换工作目录启动，密文就解不开，要改成明文让它重新加密。

② 配置改完要重载才生效

除 ai/start 与 ai/restart 外，其余命令只改配置文件：ai/config set 写完文件并不生效，要看 ai/status 里的「待生效」清单变空才算生效。

出处 Cmd.java、Conf.java。

③ 跨机部署才需要中转

NapCat 与插件不在同一台机器时，"发本地文件"这条路需要中转：URL 形如 http://host:port/<token>/<绝对路径>，token 不对一律 404。

出处 qq\Relay.java。它只读但能读本机任意文件（Relay.java）：默认关闭，只在跨机时开。

④ 聊天记录按保留期清理

三把独立的尺子：记忆 keepDays 默认 30、对话 dialogKeepDays 默认 180、群聊 grouplogKeepDays 默认 30；<=0 = 不过期。

出处 Conf.java。

⑤ NapCat 没连上也能用

监听失败（端口被占）或 napcatEnabled=false 时，本地交互照常可用，只是 QQ 侧能力不可用；而且"非本机监听 + 空 token"会直接拒绝启动监听。

出处 Boot.java、qq\Link.java。

⑥ 控制台永远有反应

命令分发整体包在兜底里：任何一条命令炸掉都不影响下一条；连装配全失败时也有一张最小命令表（help / status / tools / config）。

出处 Cmd.java。

⑦ 真正关停：用 /exit，或按精确 pid 杀进程：ai/exit 只停基板。基板停下之后调试口会随之关闭，而 JVM 进程仍然活着；在没有控制台的场景下，这时无法再 start。这是当前实现的行为，未计划修改。

正确做法：要真正结束进程，用框架控制台的 /exit（框架自带文档写的是「退出 SFW」，见 SairFrameWork\readme\pages\plugin-dev.html；进程由 SairFrameWork\run.bat 里的 javaw -jar SFW.jar 拉起），或者按精确 pid 结束进程。注意：命令表里对 /exit 的说明是"之后可再 start"（Cmd.java），而在无控制台场景下做不到 —— 以实际行为为准。

两条最容易踩的坑

群里只 @ 才触发

群消息的触发判定只认"被 @ 到自己"：判定点在 QqGateway.java 的 return ev.atSelf();（同一文件 是同一判定的使用处 决定是否剥掉开头的 @）。atSelf() 的判定本体在 qq\Ev.java。

jar 放到对的目录

插件 jar 的落位是 SairFrameWork\plugins\exection\ai.jar；数据根是 SairFrameWork\data\AiAgent-V4\。落位与目录结构见部署页 · 文件落位与文件页 · 数据根。
