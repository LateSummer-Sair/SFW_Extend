从 V3 到 V4
数据不迁移，配置能照抄

这一页只讲一件事：怎么把线上的 V3 换成 V4。包括会失去什么、怎么先留档、哪些配置能照抄、 升级后要重做哪几件事，以及哪几处行为换了做法。全部按 V4 侧的实际行为写。

会失去什么 → 升级步骤 换了做法的行为
前提

V4 不读 V3 的数据

这一条是升级前先要接受的：V4 的数据只有它自己那一个文件，没有“把 V3 数据带过来”这一步。好消息是配置可以照抄，而且加密口径一致。

V4 只开一个数据库文件

V4 的数据文件由配置对象给出，名字固定是 v4.db（Conf.dbFile() → path("v4.db")）。装配时打开的也是它：打不开就报一行 v4.db 打不开（<绝对路径>） 并降级继续，命令面照旧可用。

V4 的源码里没有读取 V3 数据文件的路径 —— 所以“数据不迁移”不是省了一步，而是设计如此。

配置能照抄，而且是同一个加密口径

敏感键的密文与 V3 完全兼容：密钥派生的尾串保持 V3 原样、六因子的顺序与 V3 一致、AES-128 的密钥取摘要的前 128 位（kit\Crypto.java）。

所以：在同一个启动目录下，V3 留下的存量密文可以直接被 V4 解开。换了机器、用户名或工作目录就不行 —— 密文与运行环境是绑定的。

V3 里那些 V4 不认识的键会被忽略：配置读取只认自己的已知键表，写错或过期的键会被当成未知键忽略，既不参与判定、也不会让基板出错。所以照抄旧配置是安全的 —— 多出来的键不会生效，但也不会添乱。

数据

会失去什么，怎么留档

下面这些都属于数据：升级后从零开始累积，V4 不会去读 V3 的库。想留档，只能在升级前自己备份一份。

V3 里的东西升级后说明
群聊消息记录不带入V4 从启用那一刻起重新记录；群聊保留期由 grouplogKeepDays 控制，默认 30 天
长期记忆与印象不带入V4 的记忆库从空开始，靠日常对话重新累积；保留期 keepDays 默认 30 天
对话历史不带入私聊 / 控制台会话各自重新开始；对话保留期 dialogKeepDays 默认 180 天
知识笔记与纠错记录不带入需要的话，在 V3 还在跑的时候自己导出文字另存
表情包记录与磁盘图片不带入V4 要重新收集；图片落点在数据根的 files\
好感度数值不带入所有人从 0 开始。另外留意：V4 里好感度不再决定权限，权限只看按归属分散的权限文件（基板侧那份在数据根下，每个技能那份在它自己的目录里，见权限管理）
定时任务与运行台账不带入需要在控制台重新设置；ai/tick 与 ai/alarm 可以查看心跳与定时清单
群成员 / 昵称缓存不带入这类缓存不再需要：V4 改为按需实时查询

留档怎么做

powershell升级前的留档（示例）
# 1) 整个 V3 数据目录复制一份出来（库 + 附件图片一起）
Copy-Item '<V3 数据目录>' '<备份目录>' -Recurse

# 2) 备份只用于留档与查证：V4 不会去读它
#    需要的文字内容，在 V3 还在跑的时候自己导出

这份备份什么时候做都不亏：V4 落地之后如果想回查旧记录，能查的就只有它了。

配置

配置怎么照抄

规则就两条：同名键直接照抄；V4 新增的键按需补。不认识的键会被忽略，不会报错，所以照抄本身很安全。

步骤

升级步骤（按这个顺序做）

六步：前两步是“留退路”，后四步是“换过来并核对”。

STEP 1 · 留档
按上一节把 V3 的数据目录整份复制出来（库与附件图片一起）。
STEP 2 · 停 V3
停掉 V3 的组件，别让两边同时连 NapCat —— 同一个 QQ 号只能有一个实例在收消息。
STEP 3 · 落位
把 AiAgentV4.jar 放进 SairFrameWork\plugins\exection\（线上这个名字是 ai.jar）；数据根用 SairFrameWork\data\AiAgent-V4\。细节见部署页 · 文件落位。
STEP 4 · 抄配置
按配置对照把同名键照抄过去（apiKey 建议先写明文让它重新加密），并确认 selfId / masterQQ / napcatEnabled / napcatPort / napcatToken 都对得上。
STEP 5 · 启动
用与 V3 相同的启动目录启动宿主（否则存量密文解不开），然后在控制台敲 ai/start —— 在它之前基板不工作。
STEP 6 · 重新配
把身份提示词放进 prompts\identity.md（冷启动只会给它建一个空壳文件）；重新设定时任务；要给谁放开某项能力，就按权限页的写法敲 ai/perm run <op> <身份> —— 那一条会写进该 op 归属的那份权限文件（默认对非主人是全关的）。

顺手核对两件事：ai/status 看装配是否齐备，以及有没有“待生效”的键；ai/napcat status 看 QQ 侧连上没有。完整清单见部署页 · 核对清单。

重做

升级后要重做的几件事

这些在 V4 里都属于“数据”或“外部配置”，不会被带过来，重新做一遍就好。

① 身份提示词

冷启动建的 prompts\identity.md 是空的：基板不带任何提示词文案。不放内容，她的身份就是空的 —— 这是最容易被落下的一步。

② 权限例外

V4 的权限判据是按归属分散的那几份权限文件：基板侧那份写在数据根下的 perms-core.jsonc（路径也写在这一份里），每个技能写自己的 perms.jsonc，装载时合并成一张表。表分技能、数据、路径三个域，每个域里没列到的按该域的默认值走 —— 技能没列到就不能用、数据没列到能读不能改、文件没列到不能碰；技能目录里没有那份文件时，它的全部 op 都不授权，而主人与她本人恒全权。写法与例子见权限页 · 怎么授权。

③ 定时任务

V3 的定时任务与运行台账不带入。V4 里用 ai/tick（手动催一次心跳）与 ai/alarm（定时唤醒清单）查看与确认。

④ NapCat 侧仍是同一个端口

插件侧默认监听 127.0.0.1:8082。NapCat 的反向 WS 指向这个地址与端口，并把 token 带上，两侧对得上就通。

差异

几处换了做法的行为

这些不是配置项的差异，而是“用起来会感觉不一样”的地方。先看一遍，升级后就不会觉得哪里怪。

主题V4 的做法
入口 没有“通道”这个概念了：旧命令名会明确回一句“属于已删除的通道概念”，并提示直接用 ai/chat；工具能不能用完全由权限决定，不再有按通道裁剪的工具表
身份 本地控制台交互就是 QQ 里的主人（MASTER）；主体分三类 MASTER / SYSTEM / ALLUSER，判定顺序是“显式 SYSTEM 标志 > 主人 > 其它”
权限 判据换成按归属分散的权限文件：三个域各判各的 —— 技能（谁能用哪个 op）、数据（谁能改、谁能读哪类数据）、路径（谁能碰哪些路径）；同一把键上 Ban 压过允许，更具体的键优先。没列到时技能不能用、数据能读不能改、文件不能碰；user:<QQ号>、group:<群号>、ALLUSER 各算各的
好感度 不再参与权限判定：控制台 ai/perm 管“能不能做”，ai/favor 管好感度数值，两件事各走各的
模型选择 model 的出厂值是 auto，auto 对应的默认模型是 deepseek-flash；写了具体模型名就严格按那个名字调用
群聊触发 只有被 @ 才触发：判据是 ev.atSelf()，主人在这里也没有豁免 —— 群里的主人同样要被 @ 才会被回答
配置生效 改配置的命令只写文件；要 ai/start（还没在跑）或 ai/restart（已经在跑）才生效；ai/status 会把“待生效”的键列出来
关停 ai/exit 只停基板：命令表口径如此，之后还能再 start。基板停下时本机调试口随之关闭，而 JVM 仍在运行；真正要关停 JVM，请用框架自己的 /exit，或按精确 pid 结束进程
数据文件 合并成一个 v4.db：业务库、运行表与全文索引都在这一个文件里，备份与迁移都只需要认准它

升级完先做一次“接线测试”：控制台 ai/start 之后敲 ai/status（看装配与待生效的键）、ai/tools（看当前可见的工具），再到群里 @ 它发一条消息看能不能回。三步都过，就算接上了。
