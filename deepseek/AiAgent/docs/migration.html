升级 · 用户指引

从 V3 到 V4
数据不迁移，配置能照抄

这一页只讲用户怎么升级：会失去什么、怎么先留档、哪些配置能照抄、升级后要重做哪几件事， 以及哪几处行为换了做法。全部按 V4 侧可复核的源码事实写。

会失去什么 → 升级步骤 换了做法的行为
前提

V4 不读 V3 的数据

这条是升级前必须先接受的：V4 的数据只有它自己那一个文件，没有"把 V3 数据带过来"这一步。

V4 只开一个数据库文件

V4 的数据文件由配置对象给出，名字固定是 v4.db（Conf.java:1103 的 dbFile() → path("v4.db")）。

装配时打开的也是它：打不开就报 v4.db 打不开（<绝对路径>） 并降级继续（Boot.java:444、:451）。源码里没有读取 V3 数据文件的路径。

配置能照抄，而且是同一个加密口径

敏感键的密文与 V3 逐字节兼容：密钥派生尾串"V3 原样"（kit\Crypto.java:41），六因子的顺序"与 V3 一致"（Crypto.java:130），AES-128 取 SHA-256 前 16 字节（Crypto.java:130、:140-148）。

所以：在同一个启动目录下，V3 的存量密文可以直接被 V4 解开。换了机器 / 用户名 / 工作目录就不行（Crypto.java:29-31）。

V3 里那些 V4 不认识的键会被忽略：配置读取只认自己的已知键表；写错或过期的键会被当成未知键忽略、不参与任何判定（Conf.java:349 就是这么处理已退休的 permissionMatrix 的）。所以照抄旧配置是安全的 —— 多出来的键不会让基板出错，但也不会生效。

数据

会失去什么，怎么留档

下面这些属于数据：升级后一律从零开始累积，V4 不会去读 V3 的库。要留档只能在升级前自己备份。

V3 里的东西升级后说明
群聊消息记录不带入V4 从启用那一刻起重新记录；群聊保留期由 grouplogKeepDays 控制，默认 30 天（Conf.java:146）
长期记忆与印象不带入V4 的记忆库从空开始，靠日常对话重新累积；保留期 keepDays 默认 30 天（Conf.java:142）
对话历史不带入私聊 / 控制台会话各自重新开始；对话保留期 dialogKeepDays 默认 180 天（Conf.java:144）
知识笔记与纠错记录不带入需要的话在升级前自己从 V3 侧导出文字另存
表情包记录与磁盘图片不带入V4 要重新收集；图片落点在数据根的 files\
好感度数值不带入所有人从 0 开始。注意：V4 里好感度不再决定权限，权限只看 ACL 账本（Auth.java:32-33、:57）
定时任务与运行台账不带入V4 需要在控制台重新设置（ai/tick / ai/alarm 可查看心跳与定时清单）
群成员 / 昵称缓存不带入这类缓存不再需要：改为按需实时查询

留档怎么做

powershell升级前的留档（示例）
# 1) 整个 V3 数据目录复制一份出来（库 + 附件图片一起）
Copy-Item '<V3 数据目录>' '<备份目录>' -Recurse

# 2) 备份只用于留档与查证：V4 不会去读它
#    需要的文字内容，请在 V3 还在跑的时候自己导出

备份这一份什么时候都不亏：V4 落地后如果发现还想回查旧记录，能查的只有这份备份。

步骤

升级步骤（按这个顺序做）

六步，前两步是"留退路"，后四步是"换过来并核对"。

STEP 1 · 留档
按上一节把 V3 的数据目录整份复制出来（库与附件图片一起）。
STEP 2 · 停 V3
停掉 V3 的组件，避免两边同时连 NapCat —— 同一个 QQ 号只能有一个实例在收消息。
STEP 3 · 落位
把 AiAgentV4.jar 放进 SairFrameWork\plugins\exection\（线上这个名字是 ai.jar）；数据根用 SairFrameWork\data\AiAgent-V4\。细节见部署页 · 文件落位。
STEP 4 · 抄配置
按配置对照把同名键照抄过去（apiKey 建议先写明文让它重新加密），并确认 selfId / masterQQ / napcatEnabled / napcatPort / napcatToken 都对。
STEP 5 · 启动
用与 V3 相同的启动目录启动宿主（否则密文解不开，见 Crypto.java:18），然后在控制台敲 ai/start —— 在它之前基板不工作。
STEP 6 · 重新配
把身份提示词放进 prompts\identity.md（冷启动只建 0 字节空壳，Boot.java:869-870）；重新设定时任务；要给谁放开某项能力，就按权限面的 ACL 写法在数据根的 perms.json 里写例外（默认对非主人是全关的）。

核对：ai/status 看装配是否齐备、以及有没有"待生效"的键（Cmd.java:1373、Conf.java:578-589）；ai/napcat status 看 QQ 侧连上没有（Cmd.java:1265）。完整清单见部署页 · 核对清单。

重做

升级后要重做的几件事

这些在 V4 里都属于"数据"或"外部配置"，不会被带过来。

① 身份提示词

冷启动建的 prompts\identity.md 是 0 字节：基板不带任何提示词文案（Boot.java:840-843）。不放内容，身份就是空的。

② 权限例外

V4 的权限判据只有一本账：数据根的 perms.json（Acl.java:121 的 FILE_NAME、Auth.java:24）。一条例外都没命中时按资源类型给位，其中 A 类（SFW 数据根之外的本机路径）对普通用户一位都不给（Acl.java:55、:145-150）。

③ 定时任务

V3 的定时任务与运行台账不带入。V4 里用 ai/tick（手动心跳）与 ai/alarm（定时唤醒清单）查看与确认（Cmd.java:1377-1378）。

④ NapCat 侧仍是同一个端口

插件侧默认监听 127.0.0.1:8082（Conf.java:128、:130）。NapCat 的反向 WS 指向这个地址与端口，并把 token 带上（qq\Link.java:431-435）。

差异

几处换了做法的行为

这些不是配置项差异，而是"用起来会感觉不一样"的地方。

主题V4 的做法出处
入口 没有"通道"概念：旧命令名会明确回一句"属于已删除的通道概念"，并提示直接用 ai/chat；工具能不能用完全由权限决定，不再有按通道裁剪的工具表 Cmd.java:211-216
身份 本地控制台交互 ≡ QQ 里的主人（MASTER）；主体分三类 MASTER / SYSTEM / ALLUSER，判定顺序"显式 SYSTEM 标志 > master > 其它" Cmd.java:1358、auth\Caller.java:15-26、:129-130
权限 判据换成资源 ACL 账本：按类默认分配 + 例外突破默认；主体层级 User<QQ>(3) > Group<群号>(2) > ALLUSER(1)，同级后者覆盖前者 Auth.java:9、:24-27、Acl.java:22-23、:92-99
好感度 不再参与权限判定；控制台 ai/perm 只管好感度，ai/acl 只看权限账本 Cmd.java:1383-1384、:1393-1394、Auth.java:32-33
模型选择 model 出厂值是 auto，auto 对应的默认模型是 deepseek-flash Conf.java:79-80
群聊触发 只有被 @ 才触发：判定点是一句 return ev.atSelf(); QqGateway.java:874、:752、qq\Ev.java:182
配置生效 改配置的命令只写文件；要 ai/start（没在跑）或 ai/restart（已经在跑）才生效；ai/status 会列出"待生效"的键 Cmd.java:1369-1371、Conf.java:578-589
关停 ai/exit 只停基板（命令表口径）；实测基板停下后调试口随之关闭而 JVM 仍活，无控制台场景下无法再 start —— 要真正关停请用 /exit 或按精确 pid Cmd.java:1366；SairFrameWork\readme\pages\plugin-dev.html:71、:139
数据文件 合并成一个 v4.db：业务库、运行表与全文索引都在这一个文件里 Conf.java:1103、Boot.java:444

升级完先做一次"接线测试"：控制台 ai/start 之后 ai/status（看装配与待生效）、ai/tools（看当前可见工具）、再在群里 @ 它发一条消息看能否回复。三步都过，就算接上了。
