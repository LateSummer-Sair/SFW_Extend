02 / LIFECYCLE

生命周期：装配 → 运行 → 关停

装配跑在自己的守护线程上分 19 步；运行期按会话分道调度、由心跳驱动定时；关停有两条路，走错一条会把自己关在门外。

启动装配：19 步，都在自己的线程上

装配绝不在调用线程上跑。框架的控制台回车是"界面线程上直接执行"，而装配要开库、建索引、装载外挂单元、起连接与心跳，要好几秒 —— 所以入口 main/help/ensureReady 一律立即返回，装配交给名为 v4-boot 的守护线程。但装配只由 ai/start（已在跑则是 ai/restart）触发：在那之前基板就是不工作的，其余命令只改配置文件（src\sair\v4\V4Activity.java:26-38、:317-334）。

运行期：分道调度 + 回合 + 心跳

每会话一条道

同会话严格先进先出、同一条道同时只有一个在跑；不同会话互不相干 —— 一个慢群不再堵住别人。真正并行的是工作线程（turnWorkers，出厂 2）schedule\Lanes.java:27-43。

溢出不静默

默认把后到的消息并进该会话还在排队的那一条（合并不新增待办）；装不下或选了丢弃策略时回一句可读文案，绝不静默消失。另有两道硬上限保证内存有界 Lanes.java:32-38。

优先级与老化

出厂口径是主人/私聊优先于群；道首任务带入队时刻，优先级老化保证普通道不会被高优流量饿死 Lanes.java:35、:57-59。

唯一的心跳

全基板只有一条周期 tick，做两件事：派发周期回调；检查到点的定时唤醒任务，到点就唤起主 Agent 跑一轮并把结果送回目标会话 Tick.java:20-26。周期出厂 20000 ms，下限夹到 1000 ms Tick.java:55、Conf.java:131。维护与出站台账裁剪也在心跳里 store\Store.java:441-443。

模型调用闸门

主回合、定时任务、异步子 Agent 都要过同一个闸门：许可数出厂 1（不并发），等待上限 180 s，等不到就放弃本次调用并收敛成一条失败结果 Boot.java:486-489、DeepSeek.java:103、Conf.java:162。

回合与收尾

一次回合跑到"模型不再要求调工具"为止；后台完成的任务回灌后触发一轮收尾回合，那一轮只记账不对外说话 agent\Loop.java:63-71。

关停：ai/exit 只停基板

必须知道的实现行为：ai/exit 会停基板 + 收掉两个调试口 + 关落盘句柄 + 注销控制台捕获器，但不结束进程（V4Activity.java:394-414、dev\DebugShell.java:110-136、dev\DebugPort.java:59-60）。后果：基板停下后调试口就关了，而进程仍然活着；此时若没有可用的控制台，就没有任何入口再敲一次 ai/start，基板起不回来。这是当前实现行为，未计划修改：把壳卸载当成调试面的终点是有意为之（在同一个壳里 ai/start 与 ai/restart 收的只是基板，观测面照旧）。

正确关停一：/exit

要走框架自己的关停路径，用控制台的 /exit（调试口那条"关框架"的命令走的就是它）。组件 ai/exit 的语义是"停基板、不改配置、不卸载插件、之后可再 start" term\Cmd.java:1366 —— 只有在确实还有控制台可用时它才是可逆的。

正确关停二：按精确 pid 结束进程

没有控制台、也不打算再让它工作时，直接结束那个确切的 pid（部署口径见 02 · 部署）。别用"按名字批量结束"这类粗口径 —— 一台机器上可能同时跑着别的实例。

重装 vs 重启：ai/start 幂等，已就绪时只回"已在运行"，绝不重启；要按新配置重装只有 ai/restart。装配/重启同时只允许一条，重复命令会被明确拒绝 V4Activity.java:316-348、:352。
