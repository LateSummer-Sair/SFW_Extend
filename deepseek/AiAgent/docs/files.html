命名与分层的两条约定

包名就是职责边界

没有 impl / util 这种无信息量的包名：kit 是可复用的基础件，store 是存储，qq 是接入，schedule 是调度。src\sair\v4\ 下只有一层子包，不嵌套第三层。

跨包只走小接口

装配期把实例注入给消费方：库注册表注入存储层（Db.setLibs，Db.java:81）、事件池按配置建成后交给接入层（Boot.java:1369-1370、Link.java:611-620）。所以线程数与表名这些"可配置的事实"都只有一个来源。

空数据首次启动会生成什么

整个数据根不存在（或为空）时，第一次启动就把骨架全部落盘，不需要手建任何文件；只创建、不覆盖、不写正文（src\sair\v4\Boot.java:851-876、Boot.java:837-847）：

目录先建出来

数据根本身、提示词目录、库目录、文件目录 —— 一律 mkdirs，已存在就跳过；同名文件挡路时不覆盖，交给上层报错（Boot.java:927-933）。

两个提示词空壳

prompts\identity.md 与 prompts\subagent.md 建成 0 字节空文件：空文件与文件不存在在提示词层语义完全一致（Boot.java:840-843）。

库文件与配置

config.json 由配置层落盘（Conf.java:1329-1406）、v4.db 由存储层连出来；表在库文件里由建表动作落盘（Boot.java:845-847）。

二次启动幂等：已存在的文件一律不动，已建的表不会重复建，骨架不会重复创建；日志里只会打一行"空数据骨架已建立 N 项"（Boot.java:872-874）。控制台可用性不依赖数据内容 —— 骨架齐备后命令面立刻可用。

数据根路径怎么被拼出来

数据根只有一处入口，其余路径都是从它派生的相对路径（Conf.java:370-375、Conf.java:1093-1103）：

javasrc\sair\v4\Conf.java
public File path(String rel) { return new File(root, rel); }   // :375 唯一的拼接口
public File promptsDir() { return path("prompts"); }           // :1093
public File filesDir()   { return path("files");   }           // :1097
public File dbFile()     { return path("v4.db");   }           // :1103

所以数据根搬到哪儿，整棵布局跟着走；config.json 的位置就是 new File(root, "config.json")（Conf.java:367）。

运行表数怎么核：(Select-String -Path src\sair\v4\store\Lib.java -Pattern '^\s*\{"').Count → 6（Lib.java:33-40 的声明表）。业务库表数：基板声明 2 张（store\EnvLibs.java:35-66）+ 外挂层声明 4 张 = 6。

连接与建表时机

  • 驱动：org.sqlite.JDBC（src\sair\v4\store\Db.java:48），连接串是 jdbc:sqlite:<绝对路径>（Db.java:126）。
  • 打开连接时设四项 PRAGMA（Db.java:134-137）：journal_mode=WAL、busy_timeout=5000、foreign_keys=ON、synchronous=NORMAL。open() 只连库、不建表（Db.java:107）。
  • 连上不等于能用：还要做一次真实读，好让装配能把"这一步"标失败（Db.java:141-148）。
  • 建表在插件装载完成之后跑一次，缺表即建、缺列即补、幂等（Db.java:610-623）；某个表失败只影响那一个（Db.java:637）。
  • 补列走"先查表结构、缺了才加"，避免在补过的库上刷假报错（store\Lib.java:113-131、Db.java:648-673）。

全文索引与分词

  • 有正文可检索的表各建一张 FTS5 外部内容表，命名规则是 fts_<表名>（LibSpec.java:164）：fts_dialog、fts_grouplog、fts_memory、fts_note。声明里没有索引列的表（sticker、pref）不建虚表，检索走回退列匹配。
  • 建表语句要点：content='<表名>'、content_rowid='id'，并优先用 tokenize='trigram'（Db.java:691-700）。为什么优先它：中文子串检索只有它是对的 —— 默认分词器会把整串汉字当成一个 token，命中不了中间片段（Db.java:676-681）。
  • 分词器是逐个降档的：先用 trigram 跑一遍全部表，失败就退回默认分词器再来一遍；两遍都失败就置"不可用"（Db.java:683-712）。
  • 可用性在打开连接时探测一次并缓存：临时建一张虚表再删掉（Db.java:218、Db.java:766-767）。
  • 每张虚表配三个同步触发器，命名 <表名>_fts_ai（插入）、_ad（删除）、_au（更新）（Db.java:714-736）；建好后立即做一次重建填充（Db.java:702）。
  • 不想给某张表建索引就用配置键 ftsOff 把它关掉：连索引带触发器都不建，检索只剩回退匹配（Db.java:206-216、Db.java:688）。这是体积上最有效的杠杆（见 配置 · 保留期）。

行的统一约定

id 与 ts

所有库表由基板统一补 id INTEGER PRIMARY KEY AUTOINCREMENT 与 ts INTEGER NOT NULL DEFAULT 0（毫秒）；声明里重复写也只算一次（LibSpec.java:203-217）。

JSON 文本列

extra 与 tags 是 TEXT 存 JSON 文本，读出来自动解析回对象／数组（Lib.java:23-26、Lib.java:161-164）。

表名可写中文

库表声明带中文别名，模型可以用中文指库（例如"记忆"落到 memory）；规范表名的翻译在存储层一处完成（Db.java:97-103、LibSpec.java:83-84）。

维护动作删什么

  • 超龄低重要度记忆行（importance <= 4）与停用闹钟、已成任务这些台账行（store\Store.java:53、Store.java:423-437）。
  • 聊天记录按各自的天数独立过期（群聊与私聊两把尺子，见 配置 · 保留期）。
  • note 从不被维护删除 —— 笔记是刻意写下来的东西，不属于流水。
  • 删行不会立刻还盘：SQLite 只是把页标成空闲，文件大小不变，要真正缩文件得另外做 VACUUM。

三份文件各自的角色

identity.md：她的根

路径由配置键决定（默认 prompts/identity.md，Conf.java:1063）。字符预算只是报警线，不是闸门：超预算只 warn 一行，正文一个字都不截、一个字都不丢（prompt\PromptFile.java:108-120）。

subagent.md：公共层

只描述"所有子 Agent 共同的那一层"；它不是某个子任务的说明书。渲染时按作用域走同一套注入位（Prompts.java:141-142）。

tools-index.md：文案外挂

它的内容会被多处读走：工具索引行（tool\ToolIndex.java:44-50）、能力索引（tool\Registry.java:43）、生命周期回话（term\Cmd.java:321-338）、入站那几路提示（QqGateway.java:744-792）、执行循环的终止文案（agent\Loop.java:33）、装配校验（Boot.java:656-671）。

读法与生效

  • 缺键不兜底：这个文件里少写一个键，用到那条文案的地方就报缺键、不发那一句，而不是编一句兜底话（Cmd.java:332、QqGateway.java:759、Loop.java:483）。
  • 按修改时间自动重读：解析结果带修改时间判断，文件一动就重读（ToolIndex.java:120-130）。
  • 正文有独立的热重载：命令面那条提示词重载只重读正文，不受"改配置要重启"的口径影响（Cmd.java:800-805、Cmd.java:1170-1171）。
  • 路径被限制在目录内：读取其它提示词时按相对路径解析并限制在提示词目录内的 .md（Prompts.java:64-74）。
  • 空壳语义：空文件与文件不存在完全等价 —— 空数据冷启动只建 0 字节空壳，基板不带任何提示词正文（Boot.java:840-843）。

jar 里面是什么

  • 条目结构：META-INF\MANIFEST.MF（89 字节，非 .class 的只有它一个）+ sair\v4\ 下的 313 个类文件条目，解压后合计 1,246,946 字节。
  • 包目录与源码包一一对应：sair\v4\ 下 16 个子包目录 + 根包类文件（与 源码包结构 同构）。
  • 清单内容只有两行：Manifest-Version: 1.0 与 ACT: sair.v4.V4Activity —— 后者是组件入口类，框架按它装载（见 技术实现 · 装配）。
  • 不含第三方依赖：SQLite 驱动与 JSON 库都由宿主运行环境提供，jar 里没有对应的包目录。这就是为什么产物只有 675 KB（源码 1.97 MB，编译后类文件约 1.25 MB）。

数据与产物的边界

可丢弃的

out\ 与 build\ 都是中间态：删掉不影响运行，重新编译／重新打包即可再生。产物本体只有一个 AiAgentV4.jar。

不可再生的

数据根下的 v4.db、config.json、perms.json、prompts\ 是运行资产：删了就没了。特别是 v4.db —— 保留期那组键是唯一会删数据的旋钮（见 配置 · 保留期）。

升级前先备份数据根：换新 jar 不动数据根，两侧文件互不覆盖；但 v4.db 里的表结构变更会由新版自动补列（Db.java:648-673），这一步不可逆。做法见 升级。
