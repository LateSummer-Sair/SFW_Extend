命名与分层的两条约定

包名就是职责边界

没有 impl / util 这种看不出内容的包名：kit 是可复用的基础件，store 是存储，qq 是接入，schedule 是调度。src\sair\v4\ 下只有一层子包，不再套第三层。

跨包只走小接口

装配期把实例注入给消费方：库注册表注入存储层（Db.setLibs）、事件池按配置建成后交给接入层（Boot 里的事件池步骤 → Link）。所以线程数、表名这类“可配置的事实”都只有一个来源。

03 / DATAROOT

数据根布局

运行期只碰一个数据根目录：SairFrameWork\data\AiAgent-V4\。这一节先分清“哪些是数据、哪些是配置”，再看每个文件是什么。

两个位置的关系：插件落位后，数据根是 <框架目录>\data\AiAgent-V4\（<框架目录> 指 SFW 的安装目录）；本仓的 data\ 是同一个结构的本地对照副本（文件名与子目录名一致），两边可以互相对照着看。

先分清：数据、配置、权限文件、提示词

类别文件是什么删了会怎样
数据 v4.db（以及 v4.db-wal / v4.db-shm）、files\ 全部业务数据与运行台账，加上下载 / 导出 / 表情包图片的落点 删了就没了，只能靠备份；想腾空间可以用保留期那组键，而不是删库
配置 config.json 扁平 JSON，全部配置键都在这里；敏感键（模型密钥、QQ 接入 token、中转 token）是密文，与运行环境绑定 删了会按出厂值重建；里面的个性化设置要重新配一遍
权限文件 perms-core.jsonc 与各技能目录里的 perms.jsonc 权限判据，独立于配置：谁能用哪个 op、谁能改 / 读哪类数据、谁能碰哪些路径，都写在这里；按归属分散，读的时候合并成一张表 删了就回到“一切未授权”的状态（主人与她本人恒全权，不受影响）
提示词 prompts\*.md 身份提示词、子 Agent 公共部分、文案与能力索引；正文由你自己写 删了等于空：基板不兜底任何文案
外挂 data\skills\ 外挂单元目录：一个目录就是一项能力 删掉那一项能力就消失，基板照常运转

一句话记住这条边界：config.json 管“怎么跑”，perms-core.jsonc 与各技能目录里的 perms.jsonc 管“谁能做什么”，v4.db 管“发生过什么”。这三样各管一段，互不代替。

空数据首次启动会生成什么

整个数据根不存在（或者为空）时，第一次启动就会把骨架全部落盘，不需要手动建任何文件：只创建、不覆盖、不写正文。

目录先建出来

数据根本身、提示词目录、外挂目录、文件目录、临时目录 —— 都用 mkdirs 建，已经存在就跳过；如果有同名文件挡路，它不会覆盖，而是把这件事报给上层（Boot.ensureSkeleton / dir()）。

两个提示词空壳

prompts\identity.md 与 prompts\subagent.md 建成空文件：在提示词层，“空文件”与“文件不存在”的语义完全一致，所以空壳就够，基板不塞任何默认文案。

库文件与配置

config.json 由配置层落盘，v4.db 由存储层连出来；表在库文件里由建表动作落盘（emptyFile() 建空壳，建表在装配后段跑一次）。

二次启动是幂等的：已经存在的文件一个字都不动，已经建好的表不会重复建，骨架也不会重复创建；日志里只多一行“空数据骨架已建立 N 项”。控制台的可用性不依赖数据内容 —— 骨架齐备后命令面立刻可用。

数据根路径怎么被拼出来

数据根只有一处入口，其余路径都是从它派生的相对路径（Conf.path(rel) 是唯一的拼接口）：

javasrc\sair\v4\Conf.java
public File path(String rel) { return new File(root, rel); }   // 唯一的拼接口
public File promptsDir() { return path("prompts"); }
public File filesDir()   { return path("files");   }
public File dbFile()     { return path("v4.db");   }

所以数据根搬到哪儿，整棵布局就跟着走；config.json 的位置同样是 new File(root, "config.json")。

04 / DB

数据表落在哪

全部表都在一个 SQLite 文件 v4.db 里：6 张业务库表 + 7 张基板运行表，另外还有全文索引虚表与同步触发器。

这两组的关系：运行表的 DDL 与列清单留在基板里（store\Lib.java）；业务库表 6 张 = 基板自己声明 2 张（store\EnvLibs.java，即消息流那两张）+ 外挂层在装载期声明 4 张。

连接与建表时机

  • 驱动是 org.sqlite.JDBC（src\sair\v4\store\Db.java），连接串是 jdbc:sqlite:<绝对路径>。
  • 打开连接时设四项 PRAGMA：journal_mode=WAL、busy_timeout=5000、foreign_keys=ON、synchronous=NORMAL。open() 只负责连库，不建表。
  • 连上不等于能用：还会做一次真实读，好让装配能准确指出“是六库这一步失败”。
  • 建表在插件装载完成之后跑一次：缺表就建、缺列就补，重复执行也安静。
  • 补列走“先查表结构、缺了才加”，所以补过的库再跑一次不会有副作用。

全文索引与分词

  • 有正文可检索的表各建一张 FTS5 外部内容表，命名规则是 fts_<表名>：fts_dialog、fts_grouplog、fts_memory、fts_note。声明里没有索引列的表（sticker、pref）不建虚表，检索走回退列匹配。
  • 建表语句要点：content='<表名>'、content_rowid='id'，并优先用 tokenize='trigram'。中文子串检索靠的就是它 —— 默认分词器会把整串汉字当成一个 token，命中不了中间片段。
  • 分词器是逐个降档的：先用 trigram 跑一遍全部表，失败就退回默认分词器再来一遍；两遍都失败就置“不可用”。
  • 可用性在打开连接时探测一次并缓存起来。
  • 每张虚表配三个同步触发器，命名是 <表名>_fts_ai（插入）、_ad（删除）、_au（更新）；建好之后立刻做一次重建填充。
  • 不想给某张表建索引，就用配置键 ftsOff 把它关掉：连索引带触发器都不建，检索只剩回退匹配。这是体积上最有效的一个杠杆（见 配置 · 保留期）。

行的统一约定

id 与 ts

所有库表由基板统一补 id INTEGER PRIMARY KEY AUTOINCREMENT 与 ts INTEGER NOT NULL DEFAULT 0（毫秒）；声明里重复写也只算一次。默认排序有 ts 就是 ts DESC, id DESC，否则按 id DESC。

JSON 文本列

extra 与 tags 是 TEXT 存 JSON 文本，读出来会自动解析回对象 / 数组，用起来跟普通字段一样。

表名可写中文

库表声明带中文别名，所以模型可以用中文指库（例如“记忆”落到 memory）；规范表名的翻译在存储层一处完成，别名大小写不敏感。

维护动作会删什么、不删什么

  • 会删：超龄的低重要度记忆行（importance <= 4）、停用的闹钟、已经完成的任务这些台账行。
  • 会删：聊天记录按各自的天数独立过期（群聊与私聊是两把尺子，见 配置 · 保留期）。
  • 不会删：note 从不被维护删除 —— 笔记是刻意写下来的东西，不属于流水。
  • 删行不会立刻还盘：SQLite 只是把页标成空闲，文件大小不变，想真正缩小文件要另外做 VACUUM。
05 / PROMPTS

提示词文件

数据根下的 prompts\ 存三类外挂文本：身份、子 Agent 公共部分，以及“文案与能力索引”。它们都是纯文本，改完按修改时间自动重读。

文件是什么
prompts\identity.md身份提示词。基板只带这一份初始提示词
prompts\subagent.md子 Agent 的公共部分提示词；缺文件就等于空，基板不兜底
prompts\tools-index.md文案与能力索引：索引行的预算、工具的一句话示例、队列溢出 / 排队 / 初始化中等提示语、面板标题、偏好块三行文案

三份文件各自的角色

identity.md：她的根

路径由配置键决定（默认 prompts/identity.md）。字符预算只是报警线，不是闸门：超预算只 warn 一行，正文一个字都不截、一个字都不丢。

subagent.md：公共层

写的是“所有子 Agent 共同的那一层”，不是某个子任务的说明书。渲染时按作用域走同一套注入位。

tools-index.md：文案外挂

它的内容会被好几处读走：工具索引行（tool\ToolIndex.java）、能力索引（tool\Registry.java）、生命周期回话（term\Cmd.java）、入站那几路提示（QqGateway.java）、执行循环的终止文案（agent\Loop.java）、装配校验（Boot.java）。

读法与生效

  • 缺键不兜底：这个文件里少写一个键，用到那条文案的地方就会报缺键、不发那一句，而不是编一句兜底话。想改文案，就把键补上。
  • 按修改时间自动重读：解析结果带修改时间判断，文件一动就重读。
  • 正文有独立的热重载：命令面那条提示词重载只重读正文，不受“改配置要重启”的口径影响。
  • 路径被限制在目录内：读取其它提示词时按相对路径解析，并限制在提示词目录内的 .md。
  • 空壳语义：空文件与文件不存在完全等价 —— 空数据冷启动只建一个空壳文件，基板不带任何提示词正文。

构建产物与仓根产物

仓库根下哪些是产物、哪些是源码，以及产物落在线上哪个位置。这一段也顺便说清哪些东西可以放心删。

插件 jar

位置说明
仓根 AiAgentV4.jar构建产物本体，发布时用的就是这一份
线上落位 SairFrameWork\plugins\exection\ai.jar同一份产物放进插件目录并改名；控制台前缀跟着文件名走，所以叫 ai.jar 就是 ai/

两个位置是同一份产物；落位与命名见 部署 · 目录。

jar 里面是什么

  • 条目结构：META-INF\MANIFEST.MF（非 .class 的只有它一个）+ sair\v4\ 下的类文件条目，解压后就是完整的实现。
  • 包目录与源码包一一对应：sair\v4\ 下 16 个子包目录 + 根包类文件（与 源码包结构 同构）。
  • 清单内容只有两行：Manifest-Version: 1.0 与 ACT: sair.v4.V4Activity —— 后者是组件入口类，框架按它装载（见 技术实现 · 装配）。
  • 不含第三方依赖：SQLite 驱动与 JSON 库都由宿主运行环境提供，jar 里没有对应的包目录 —— 这也是产物能做得这么小的原因。

仓根一览

名字类别是什么
AiAgentV4.jar产物插件本体，落位后按文件名决定控制台前缀（改名为 ai.jar 就是 ai/）
src\源码全部 114 个 .java，见 源码树
data\数据数据根的本地对照副本，见 数据根布局
docs\源码本静态站：导航上的若干 .html 页面 + css\site.css + js\site.js；无外链、无第三方库、无网络请求
build\暂存构建暂存区：外挂层源码与文案的中间副本，不参与插件打包，删掉也能重新生成
out\产物编译输出目录：sair\v4\ 下 16 个子包目录 + 根包类 —— 与 jar 内条目同构
META-INF\源码只有 MANIFEST.MF，打包时进 jar 根
README.md文档仓库说明书：九项能力、权限模型、工具面、命令面、部署要点

数据与产物的边界

可丢弃的

out\ 与 build\ 都是中间态：删掉不影响运行，重新编译 / 重新打包就能再生。产物本体只有一个 AiAgentV4.jar。

不可再生的

数据根下的 v4.db、config.json、perms-core.jsonc（以及各技能目录里的 perms.jsonc）、prompts\ 是运行资产：删了就没了。尤其是 v4.db —— 保留期那组键是唯一会删数据的旋钮（见 配置 · 保留期）。

升级前先备份数据根：换新 jar 不会动数据根，两侧文件互不覆盖；不过 v4.db 里的表结构变更会由新版自动补列，这一步是不可逆的。做法见 升级。
