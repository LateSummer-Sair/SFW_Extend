前置

前置条件与硬约束

四条都是"不满足就一定出问题"的硬条件，不是建议。

① 跑在 SFW 宿主里，由宿主起进程

插件不是独立程序，它由 SFW 框架加载。宿主自带的启动脚本是 SairFrameWork\run.bat，内容就一行有效命令：

batSairFrameWork\run.bat
@echo off
cd /d %~dp0
start 8x64\bin\javaw -jar SFW.jar %*

同目录下还有框架自己的 SFW.jar，不用改它。

② 启动目录建议固定

敏感键（apiKey / napcatToken / relayToken，Conf.java）是密文落盘的，密钥派生包含当前工作目录。

派生因子 = JVM 名 / 架构 / 用户名 / 主机名 / user.dir / 固定尾串 的 SHA-256，取前 16 字节做 AES-128 密钥（kit\Crypto.java）。换机器、换用户名、换工作目录都解不开（Crypto.java）—— 这时把对应键改成明文，让它重新加密。

③ 只要一份 jar，落位固定

线上这份是 plugins\exection\ai.jar（<框架目录> 指 SFW 的安装目录）；仓库根的 AiAgentV4.jar 与它逐位相同。

Get-Item '<框架目录>\plugins\exection\ai.jar' | Select-Object Length

④ 提示词要自己准备

冷启动只会建 0 字节空壳 prompts\identity.md 与 prompts\subagent.md —— 基板不带任何提示词文案（Boot.java）。空文件与"文件不存在"在加载器里语义完全一致。

部署后把提示词文件放进数据根的 prompts\ 就可以用了。当前线上这三个文件是：identity.md 14,034 字节、subagent.md 1,329 字节、tools-index.md 9,998 字节。

落位

文件放哪里

只有两个位置要记：插件 jar 放宿主 plugins\exection\，运行数据在宿主 data\AiAgent-V4\。

放什么位置说明
插件 jarSairFrameWork\plugins\exection\ai.jar宿主的插件目录；文件名就是 ai.jar
运行数据根SairFrameWork\data\AiAgent-V4\配置、数据库、提示词、附件与临时文件都在这里
命令脚本（可选）任意路径的 *.ir 文件启动时按行当控制台命令执行：run.bat "<路径>.ir"
宿主体SairFrameWork\SFW.jar + 8x64\bin\javaw由 run.bat 调用，不由插件管理

数据根里有什么

名字是什么谁建的
config.json配置文件（已知键 94 个，见配置页）Conf.ensureDefaults()（Boot.java）
v4.db唯一的数据文件（Conf.java）；表在装配第⑯步末尾落盘（Boot.createLibTables）Store.open()（Boot.java）
prompts\提示词文件目录（identity.md / subagent.md 等）骨架 + 你自己放文件

tmp\临时文件目录骨架（Boot.java）
外挂扩展层目录后加进来的能力存放处；怎么写见 11 · 技能开发骨架（Boot.java）
权限文件perms-core.jsonc 与各技能目录里的 perms.jsonc：谁能用哪个 op、谁能改 / 读哪类数据、谁能碰哪些路径（见 07 · 权限管理）主人用控制台写，或手改文件
logs\ / debug-port.json 等运行期落盘物（日志、调试面状态）运行期

更细的文件地图（源码 17 个包 + 数据表落点）见文件与数据根页。

权限文件只活在实例旁：部署脚本把 data\ 往宿主的运行数据根拷时，按文件名跳过这几份 —— perms-core.jsonc 与每个技能目录里的 perms.jsonc，以及旧版那两份统一账本；另外 config.json、v4.db、files\、tmp\、cache\、启动脚本与调试面凭据文件也都不参与拷贝。所以项目仓库里不放权限表，部署也不会用项目里的副本覆盖线上已经授权的那几份 —— 升级时它们的字节原样留着。要重置它们，只能在控制台改表或直接编辑那份线上文件。

命令前缀从哪来：控制台命令的前缀是组件名（V4Activity.java 三处都在用 getName() / 安全化后的组件名去构造命令对象），线上这个组件名是 ai，所以命令都写成 ai/start 这种形式；取不到名字时代码里的兜底是 ai4（Cmd.java）。

首次配置

第一次要配哪几样

配完记得：写文件不等于生效，要 ai/start（没在跑）或 ai/restart（已经在跑）。

apiKey默认 ""密文落盘与启动目录绑死
含义
模型服务的访问密钥。与 napcatToken / relayToken 同属"值不许外露"的敏感键（Conf.java）。
怎么配
ai/config set apiKey <你的 key>，然后 ai/start（已在跑就 ai/restart）。也可以直接编辑文件写明文，下次保存会重新加密。
没配会怎样
ai/chat 只会回一句可读的说明并给出解决命令，不会崩基板。
selfId / masterQQ默认 0身份
含义
机器人自己的 QQ 号与主人的 QQ 号。本地控制台 ≡ QQ 里的主人（Cmd.java）。
怎么配
ai/config set selfId <QQ>、ai/config set masterQQ <QQ>；主人可以有多个（masterQQs，Conf.java）。
注意
群消息的触发判定依赖事件里带的 self_id：缺 self_id 就恒判为"没有被 @"（qq\Ev.java）。
napcatEnabled / napcatHost / napcatPort / napcatToken默认 false / 127.0.0.1 / 8082 / ""
含义
是否开 NapCat 反向 WS 监听、绑哪个地址与端口、准入 token（默认值见 Conf.java）。
怎么配
见下面「把 NapCat 接进来」一节。改完要 ai/start / ai/restart 一下才生效（Cmd.java）。
调错的后果
端口被占 → 监听失败，但本地交互照常可用（Boot.java）。

首次启动会自己建骨架：数据根不存在或为空时，装配会先落盘目录与空壳文件，只创建、不覆盖、不写正文：已存在的一律不动，config.json 与用户数据永不被清（Boot.java）。执行了什么会在控制台打一行"空数据骨架已建立 N 项"（Boot.java）。

NapCat

把 NapCat 接进来

方向是反的：插件是服务端，NapCat 作为客户端连过来。

谁连谁

插件实现的是反向 WebSocket 服务端：它绑定 napcatHost:napcatPort 并等 NapCat 连进来（qq\Link.java）。所以 NapCat 那边要配的是"反向 WS 指向这台机器"。

实现只用 JDK + gson：java.net.ServerSocket + 手写 WebSocket 握手（RFC 6455），不引第三方网络框架（qq\Link.java）。

token 怎么带

握手时会校验 token（配了才校验）：接受 Authorization: Bearer <token>，也接受 URL 上的 ?access_token=<token>（qq\Link.java）。

安全默认：绑非本机地址 + token 为空 = 拒绝启动监听；绑回环但 token 为空只给一行告警（qq\Link.java）。日志只打动作名与响应摘要，绝不打印 token（qq\Link.java）。

配置步骤

text控制台命令序列（示例）
ai/config set napcatEnabled true
ai/config set napcatHost 127.0.0.1
ai/config set napcatPort 8082
ai/config set napcatToken <自己设一个强 token>
ai/restart
ai/napcat status

这些命令只写配置文件，生效靠 ai/restart（Cmd.java）。NapCat 侧把反向 WS 指向同一地址与端口，并在请求里带上 token。ai/napcat status 用于确认连接状态（Cmd.java）。

连接失败不等于基板坏了：监听失败或 NapCat 没连上时，本地控制台与已有数据照常可用，只是 QQ 侧能力不可用（Boot.java）。排障可以先看 ai/status，它会点名失败步骤。

跨机

跨机部署才开的中转

NapCat 在另一台机器时，它读不到这台机器的盘符路径，需要一个 HTTP 只读中转把本地文件变成它能取的 URL。

它是什么

一个内建的 HTTP 服务：URL 形如 http://host:port/<token>/<绝对路径>；token 不对一律 404（不区分 401/403，避免被探测）（qq\Relay.java）。

token 没配会自动生成并写回 config.json 的 relayToken（可复现、可手改）（Relay.java）。端口默认 2671（Conf.java）。

它的权限有多大

源码里的原话：只读、只认 token 路径前缀；服务能读本机任意文件 —— 不需要时就关掉（Relay.java）。

因此默认是关的：relayEnabled=false，只在跨机部署时打开，并配 relayPublicHost 让它生成对端能访问的地址（Relay.java）。

relayEnabled默认 false默认关
含义
是否开启文件外链中转。
怎么开
ai/config set relayEnabled true + 设 relayPublicHost，然后 ai/restart（Cmd.java）。
调错的后果
同机部署时开着它，等于把本机文件的只读下载口暴露出去；不需要就关。
relayPort / relayPublicHost / relayToken / relayTtlMinutes默认 2671 / "" / "" / 见配置页
含义
监听端口、对外主机名、准入 token、链接有效期（Conf.java）。
注意
日志与状态输出里的 token 一律脱敏，只留前 4 位（Relay.java）。
冷启动

第一次启动会生成什么

数据根为空时自动补齐；这一步是幂等的，第二次启动什么都不做。

生成项内容
数据根目录数据根本身
prompts\目录 + identity.md、subagent.md 两个 空壳
files\附件与下载落点
tmp\临时目录
外挂扩展层目录能力存放处（怎么写见 11 · 技能开发）

幂等承诺（有出处，不是口号）：ensureSkeleton() 的契约是"只创建、不覆盖、不写正文：已存在的一律不动（二次启动幂等，config.json 与用户数据永不被清）"（Boot.java）；方法只把"本次真正新建的项"计入返回列表（Boot.java）。

起停

启动与关停的正确做法

这一节的两个口径可以分开看：启动基板用 ai/start；结束进程用 /exit 或精确 pid。

启动：ai/start 是唯一的"加载并运行"

它读 config.json 并跑 19 步装配；已经在跑时只回话、绝不重启，并告诉你"要生效得用 ai/restart"；已经有一条装配/重启在跑时明确拒绝，不并发（Cmd.java）。

装配跑在自己的线程上，进度直接打在控制台（Cmd.java）。

开机自动跑命令：.ir 脚本

启动脚本可以带一个 .ir 文件，里面的每一行就是一条控制台命令，随启动依次执行：

text.ir 脚本示例
web/start
ai/config set napcatEnabled true
ai/debug on
ai/restart
ai/status

用法：run.bat "<路径>.ir"（run.bat 末尾的 %* 把参数透传给宿主）。仓库根就有一个这样的脚本：SFW-BOT.ir —— 它的第 2 行写的用法与这一节一致，第 5-10 行就是逐行命令。

关停：分清"停基板"和"结束进程"

ai/exit 只停基板

命令表对它的说明是"框架转发到组件 exit()：停基板（不改配置、不卸载插件；之后可再 start）"（Cmd.java）。

但实际行为是：基板停下之后调试口会随之关闭，而 JVM 进程仍然活着；在没有控制台的场景下，这时无法再 start。这是当前实现的行为，未计划修改。

要真正关停

用框架控制台的 /exit（框架自带文档：SairFrameWork\readme\pages\plugin-dev.html 与 「/exit 退出 SFW」），或者按精确 pid 结束进程。

进程是由 run.bat 里的 javaw -jar SFW.jar 拉起的；按 pid 关停前先用系统工具确认那个 pid 就是宿主进程，按名字批量结束容易误伤。

把 ai/exit 和"退出程序"分开看：它不结束 JVM。想重启基板而不是结束进程，用 ai/restart（先停旧基板，再读文件重新装配 19 步，不并发）（Cmd.java）。

清单

部署核对清单

每一条都能自己验；先验过再往下走会更稳。

装之前

  • jar 是这一份吗：
  • 宿主能起：run.bat 与 8x64\bin\javaw 在位
  • 启动目录确定不再改（密文与工作目录绑死，Crypto.java）
  • 数据来自 V3 的话先看升级页：V4 不读 V3 的数据

装完

  • ai/status 能看到装配到哪一步、有没有失败步骤（Cmd.java）
  • ai/status 的「待生效」清单为空（否则配置还没生效，Conf.java）
  • ai/napcat status 连接状态符合预期（Cmd.java）
  • 数据根里 config.json 与 v4.db 已生成、prompts\ 里放好了提示词
  • 群里发一条 @ 它的消息，能收到回复（只 @ 才触发，QqGateway.java）

出问题时先看哪里

现象先看常见原因
聊天不回、命令说"未装配"ai/status还没 ai/start，或某一步装配失败（会给失败步骤）
改了配置没反应ai/status 的「待生效」段ai/config 只写文件，要 ai/restart（Cmd.java）
QQ 侧没反应ai/napcat status监听失败（端口占用）或 token 不匹配；本地交互不受影响（Boot.java）
密钥解不开密文派生提示（只含因子描述、不含密钥）换了机器 / 用户名 / 工作目录（Crypto.java）
群里不触发消息里有没有 @ 到它只 @ 才触发（QqGateway.java）；事件缺 self_id 则恒判为未 @（qq\Ev.java）
